# 八周开发路线

## 总原则

每周产出一个可运行、可测试的增量。第三周结束时普通协作功能可用，第五周结束时知识问答可演示，第六周结束时 AI 任务规划可确认写入。

## Week 1：工程与认证

- 建立仓库、Maven、Vue、Docker Compose
- Flyway 初始迁移
- 统一响应、异常和 requestId
- 用户、JWT、Refresh Token
- 邀请接受流程
- CI 运行后端测试和前端构建

验收：邀请用户可以登录并查看空项目列表。

## Week 2：项目、成员、里程碑

- 项目 CRUD
- OWNER/ADMIN/MEMBER 权限
- 成员邀请、角色修改和移除
- 里程碑 CRUD
- 项目布局和成员页面

验收：两个测试账号在同一项目中看到不同权限。

## Week 3：任务协作

- 任务 CRUD 和状态流转
- 依赖关系与环检测
- 评论
- 看板
- 审计日志
- 项目概览统计

验收：普通协作平台可独立使用。

## Week 4：文档与 MinIO

- 文件上传、下载、删除
- PDF/DOCX/MD/TXT 解析
- 异步状态与重试
- 文本清洗和分块
- 文档页面轮询

验收：四种文档都能进入 READY，失败能显示原因。

## Week 5：Embedding 与 RAG

- AiModelGateway
- 多 Provider 配置
- Embedding 写入 pgvector
- 项目范围精确检索
- 知识会话、回答和引用
- Fake AI 测试

验收：从竞赛规则中回答 10 个问题并显示正确来源。

## Week 6：AI 任务规划

- 结构化 Schema
- 项目上下文与只读工具
- 异步生成和一次修复
- 草案编辑接口
- 日期、成员、依赖校验
- 幂等确认与事务写入

验收：生成一份 10～20 个任务的计划，编辑后一次确认创建。

## Week 7：质量与安全

- Testcontainers 集成测试
- RAG 60 条评测集
- 规划 20 个评测场景
- 限流、日志脱敏、Prompt Injection 用例
- 性能测试
- 修复 N+1、慢 SQL 和异常流程

验收：默认测试不消耗真实模型额度，评测报告可复现。

## Week 8：展示与求职材料

- Docker Compose 一键启动
- 完善 README、架构图、ER 图、OpenAPI
- 录制 3～5 分钟演示视频
- 准备项目介绍和面试问题
- 整理真实指标和用户反馈
- 发布 `v0.1.0` Tag

验收：在干净环境按 README 启动，完成一次完整演示。

## 每日建议

- 3 小时项目开发
- 1 小时 Java/数据库/网络基础
- 1 小时算法
- 30 分钟测试、文档和 Git 提交

## 风险控制

若进度落后，按顺序砍掉：

1. SSE 流式问答
2. Redis 缓存，只保留基础限流降级
3. 复杂项目统计
4. AI 只读 Tool Calling，改为后端预组装上下文

不得砍掉：权限隔离、引用来源、任务规划确认和测试替身。
