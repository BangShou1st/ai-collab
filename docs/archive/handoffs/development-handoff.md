## 一、模型接入、规划与 OpenCode Zen

- 分离业务输出契约与提供商传输模式：提示词 JSON 为规划兼容基线，原生 JSON/Schema 模式按能力启用；不把“支持原生结构化输出”当成提示词 JSON 的必要条件。
- 修复网关过早拒绝候选正文的问题，使完整 JSON 围栏整理、Schema 校验和有界修复能正确执行；不删除其他场景的必要校验。
- 骨架、详情和局部修复均有准确错误分类。可修复错误最多一次修复；成员、来源、骨架身份、锁定字段及权限仍严格验证。
- 修复输入包含必要的原目标、最新约束、成员/来源范围、基准版本和具体问题，不只发送缺乏上下文的草稿片段。
- 明确最终有效模型、配置快照、输出预算和模式。实际使用值与日志/界面一致；区分认证、限流、超时、截断、格式和业务错误。
- 普通连通性、规划结构输出、流式和原生工具能力分别验证，不能一次普通聊天成功就声明全部支持。

只读参考 `E:/project/spec-agent` 的实际模型适配和传输实现，尤其：

- `backend/src/main/java/com/specagent/model/provider/OpenCodeModelInferenceGateway.java`
- `backend/src/main/java/com/specagent/model/provider/HttpOpenCodeZenTransport.java`
- `agent-brain/src/spec_agent_brain/decision/engine.py`
- `agent-brain/src/spec_agent_brain/global_assistant/agent.py` 与 `model_adapter.py`

借鉴可验证的请求、响应处理和契约边界，不修改该项目，不复制它的业务状态机或 Python 架构。不同路径可能使用不同 response_format，不要假设 spec-agent 全部提示词 JSON。当前 ai-collab Zen 已有提示词 JSON 与 stream=true 路径，先核实再改。

OpenCode Zen 可能限流，用户预计当地时间 2026-10-03 08:00（Asia/Shanghai）恢复，这只是预期，不是可用性保证。新会话实际时间可能已经超过该时刻：不等待到点、不定时轮询、不把真实服务恢复作为其余开发的前置条件。

前一轮用本项目已启用的 mimo-v2.5-free 进行过一次真实尝试，结果为 AI_MODEL_CREDENTIAL_INVALID，本地密钥解密成功，未获得正文。用户确认最近成功的是 spec-agent 配置。因此不要把所有失败预判为 429，也不要据此认定 OpenCode 协议实现不兼容。

优先用本地 HTTP 模拟服务/传输桩和生产适配器验证：请求路径与头、model/messages、模式对应字段、stream=true、SSE 增量与终止、正文/工具调用分片组装、usage 缺失、空内容、截断、非 SSE 错误、401/403/429/5xx、超时和取消。不要为了测试放宽生产环境全局访问策略。

当前项目已有凭据可用于有界真实测试，使用合成数据；不打印密钥、不将密钥写入源码/报告，不擅自复制或覆盖 spec-agent 凭据。碰到认证或限流失败停止重复请求，继续其他开发。若完成真实验证需要用户处理配置，提出一次简短问题但继续独立工作。

最终区分“静态协议核对通过”“生产适配器的本地模拟测试通过”“真实服务调用通过”。前两者只证明协议实现符合预期，不能报告真实可用。保留一条恢复后可手动运行的最小 smoke test 及准确操作说明。

## 二、Agent 工具与运行时

按 `docs/agent-runtime-design.md` 实施，至少完整覆盖：

- 工具成功、失败、拒绝、取消、未执行、结果未知分别表达；MCP isError 不丢失；失败不进入已验证事实。
- 本轮未暴露工具必拒绝；参数错误返回字段及约束；完整接收并校验工具参数后才执行。
- callId 协议配对与服务端持久化调用身份分开；缺失、重复、同身份不同参数及重复提交有明确处理。
- 独立只读调用有界并发，使用应用管理的执行器；工具截止时间从发起计算并落实内部/MCP 不同配置。
- 提案串行，批次所有调用都有处置，不能第一个提案后吞掉后续调用。部分成功保留结果并准确呈现完成范围。
- 工具重试、模型重试、参数纠正和格式修复分别计数，整体受总预算约束；429/超时不静默降级工具语义。
- 补充当前目标、约束、已核验引用、有效观察与待澄清项；用户补充继续原目标，取消/替换有明确语义。
- 类型化澄清动作逐步替代仅依赖 [QUESTIONS] 的识别方式，兼容旧历史。
- 审批绑定所见版本，提交事务内重新校验；写入结果未知先查持久化结果，不盲目重做。
- 取消停止新动作并尽可能中止在途请求；拒绝迟到提交。恢复复用已知结果；租约接管、SSE 重连不造成重复副作用。
- 前端同步展示真实步骤、部分失败、等待输入、待审批、正式写入与取消；不模拟模型内部思考。

## 三、Ollama Embedding 与 RAG

- 加入系统管理员管理的 Ollama 本地预设，首批复用 OpenAI 兼容 `/v1/embeddings` 协议；不把 `/api/embed` 直接塞给现有解析器。
- 支持本地免密钥、正确默认地址/路径、容器部署地址提示、当前表单候选配置测试与实际维度探测。不要沿用默认 1536 作为所有模型维度。
- 本地 HTTP 访问采用限定的 Embedding 目标策略；不删除全局公网 HTTPS 校验、不开放所有私网目标。保存、测试与实际请求使用同一规则。
- 切换提供商/目标地址不继承旧云密钥；普通同配置编辑可保留密钥。兼容新增 provider 的数据库迁移。
- 查询向量与指纹来自同一配置快照，文档写入也遵守该快照。准确区分排队、处理、完成与失败。
- 实现候选索引构建、校验、激活及旧代际管理，构建失败不挤掉原可用索引；撤销文档访问立即生效。
- 加入有界知识追问上下文，修复无效引用/无证据处理；模型推断与资料结论区分。修复已识别的文档提交结果与通知不一致、问答长度限制不一致。
- 不自动安装 Ollama 或下载模型。已有服务可用时做合成文本实测；否则完成模拟验证并记录真实验证未完成。
