## 2. 本轮范围：三个开发包

### A. 证据压缩与消费一致性（D1/D3/D6）

- **D1**：partial 首条记录不能被 Composer 按整条完全覆盖排除。主请求要保留未送入摘要的尾部，后续摘要仍按偏移续读；兼容当前已经保存的 partial 元数据。允许先保留整条原始记录的有界重复，不为消除重复另建压缩协议。工具调用/result 成对、引用身份完整；只有完全覆盖的前缀才退出原文视图。
- **D3**：明确 `LENGTH` 等截断/不合格结束的辅助摘要不能直接发布并推进覆盖。沿用既有有界校验/降级策略，保留旧有效摘要与原始来源，已发生用量幂等结算。同步核对 RUN_CONTEXT、会话摘要及重压缩同类路径；不通过句末标点猜测完整性，不无限重压缩，不给正常最终回答加累计输出限制。
- **D6**：工具层耗满后，未遍历到的相关、未覆盖来源仍进入裁前估算；去重/失效/无关排除不误计。不能先裁掉来源再说没达到触发线，不恢复年龄固定裁切。

### B. 摘要发布并发安全（D2）

- 对真实 claim epoch、有效租约、取消、目标修订做并发安全检查与发布。普通 SELECT 加 @Transactional 不够，第二次无锁 SELECT 也不够。
- 采用符合现有锁序的短事务行锁或等价原子条件方案；复用既有 lease/goalRevision 事实，不能用 run.version 冒充目标修订。检查暂停/续跑/取消/接管与 session 更新的锁序，避免补修引入死锁。
- 不跨模型 HTTP 持锁。已经受理的暂停按现有契约允许在途结果保存，不自动解除暂停；未获准入不能发新请求。
- 同 attempt 发布/结算只一次；fenced 返回不成为有效摘要、不推进覆盖，但发生用量如实结算。调用方应能区分有效提交与 FENCED/CAS 冲突，不能在日志或返回值上把所有完成都说成成功提交。
- 用真实事务证明租约过期未换 epoch、检查与发布之间取消/目标修订/接管的提交顺序；保留重复完成与暂停镜像。

### C. 每次请求的准备与转换一致性（D4/D5/D7/D8）

- **D4**：v2 和 composer-v2=false 一致排除子运行的项目记忆；子仍保留自己的委派目标、工具观察、RUN_CONTEXT 与必要身份，主运行继续正常使用项目记忆。回归使用非空实际记忆选择，不能靠空 mock 或“忽略上文”提示词掩盖。

## 3. 不得改变的设计

- v2 累计输入/输出仅统计，数据库 NULL 表示无累计上限；不新增 8M、累计输出、假无限量或第二个容量平台。
- 单次输入守当前模型 H=W-R-S；T=min(256k,0.85H) 为软压缩线，L=0.5T 为软目标，不是拒绝上限；未知窗口如实标 estimated 并保留既有回退。不要凭模型名称猜 1M。
- 父子执行额度独立，子用量回收只统计；根 24 模型轮/64 步/64 工具，子 12/16/24，depth=1、最多 3 个子运行。旧 v1 与 COMBINED/SEPARATED 恢复不重解释。
- 根活跃 45 分钟、子 30 分钟、模型单请求 10 分钟、连接 15 秒；续租保持短 claim、有界、不跨 HTTP 持事务锁。
- 失败自动重试、崩溃接管、已保存结果消费与工具幂等全部保留。
- 暂停后明确输入续跑，不加继续按钮；已受理后台规划继续完成。
- 只做电脑端验收，不重做对话 UI，不重开已收口 SSE，不把 Last-Event-ID 可选证据升级为门槛。
- 高内聚、低耦合与明确依赖优先；不以减少代码行数为目标。参考本地 LangChain 课程思路，不迁框架。
