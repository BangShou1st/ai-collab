## 2. 用户已经确定的体验

1. 点击“暂停”，停止 Agent 后续动作；已经发出的模型请求和已经受理的动作允许完成当前阶段，并保存真实结果。
2. **已经受理的后台规划继续完成**，暂停 Agent 不能取消规划 attempt、重建 operation 或停止后台规划任务。继续时读取原 operation/attempt 的状态与结果。
3. **不增加“继续执行”按钮。用户通过原有输入框表达继续意图，恢复同一个 runId**，复用目标、有效约束、模型响应、工具结果和已受理业务动作。不会新建派生运行，不重复审批/写入，不清零已耗额度、时长或恢复次数。
4. 当前会话的当前运行明确为 PAUSED 时，识别明确的续跑表达，例如“继续”“继续吧”“接着做”“恢复执行”“继续刚才的任务”“把剩下的做完”。它是控制操作，**在普通消息追加之前分流到 resume 用例，不经 appendUser 更新 latestRequest、goalRevision 或有效约束**。不能只支持某两个精确字符串，也不能看到“继续”子串就恢复。含否定、仅询问能力或同时提出新目标的输入不能直接续跑。
5. 等待澄清时的回复仍走现有 `/continue`；不能把用户对澄清问题的回答当暂停恢复，也不能用 resume 代替审批。
6. 恢复后下一次确需模型请求时，按当前 AGENT 配置解析；已发出的请求按原配置完成，已保存结果及待处理工具继续使用原身份与 source_mode。
7. 暂停采用动作边界语义。界面必须区分“正在暂停”和“已暂停”，不能在服务端尚有在途工作时宣称已经停止。

## 3. 最小状态与控制设计

优先只新增 `PAUSED`（非终态）和 `pause_requested_at`，不增设独立 PAUSING 状态、checkpoint 表、七种 phase、约束哈希、心跳平台或多套调度规则。数据库当前最高迁移为 V60，新增迁移按现场下一版本编号，预计 V61；不改写旧迁移。

状态行为明确如下：

| 当前状态 | 暂停 | 继续 |
| --- | --- | --- |
| QUEUED | 原子转 PAUSED，不启动新动作 | 无暂停意图时重复 resume 返回当前状态 |
| RUNNING | 落库暂停意图，暂时仍 RUNNING；安全边界确认 PAUSED | 暂停尚未完成时不允许抢先恢复，返回明确业务状态提示 |
| FAILED_RETRYABLE | 等待自动重试期间直接 PAUSED，自动调度不得继续领取 | 手动继续转 QUEUED，可立即调度；保留已耗重试次数与额度 |
| PAUSED | 幂等返回当前状态，无重复事件 | 原子转 QUEUED，清除暂停意图，保留原 runId 与进度 |
| WAITING_FOR_APPROVAL / WAITING_FOR_USER_INPUT | 当前已在等待外部输入，不提供暂停按钮 | 保持原审批/澄清入口，不冒充 resume |
| SUCCEEDED / FAILED / CANCELED / BUDGET_EXCEEDED | 不改终态；竞争中返回最新结果或明确业务状态错误 | 不复活终态；既有派生 retry 语义保持 |

重复 resume 在已恢复到 QUEUED/RUNNING 且没有新的暂停意图时返回当前运行，不二次推进或重复记事件。PAUSED 允许按原取消语义“结束本次运行”，随后不能恢复原运行。

暂停不冻结业务世界或资源版本。恢复继续进行原有角色、权限、Skill 白名单、source_mode、资源版本和幂等校验；撤权/资源失效/配置不可用时按现有明确错误处理，不擅自换模型或修改业务对象。

## 4. 原子边界与在途工作的处理

### 4.1 暂停意图不等于已经暂停

RUNNING 的暂停请求只记录控制意图，**不要立即撤销在途请求的 claim 或调用取消服务的 interrupt**。不要因写暂停意图而让在途响应携带的运行版本失配、造成响应落库回滚；结合现有 CAS 与锁决定最小写法。控制意图、普通执行进度和审计更新时间职责要区分。

真正进入 PAUSED 时才结清本 claim 的已确认执行段、释放租约并使旧 claim 失效；以后旧 worker 即使刷新业务版本，也不能继续推进。暂停等待不计入 active_elapsed_ms；继续不清零已确认时长。沿用 R1 的 last_progress_at 语义、现有 deadline 和请求超时，不新增暂停专属超时体系。

暂停请求与“新动作准入”用同一运行持久化控制边界确定顺序：动作先获得准入，则允许完成该阶段；暂停意图先落库，则不再启动该动作。短事务完成准入，不持有运行行锁等待整个模型请求或远程工具响应，否则暂停按钮会被长调用阻塞。

### 4.2 每类新动作都要遵守暂停控制

检查模型请求（含摘要请求）、工具实际执行、自动重试、规划受理和提案创建这些入口。不是只在 advance 开头读一次暂停标记。复用小而明确的控制协作者/既有入口，避免多处复制状态判断。

- 模型已发出：允许返回并保存完整响应与现有结算，保留 finalizing 元数据；暂停后不启动响应提出的新工具。
- 普通最终文本完成当前阶段且不启动新的外部动作时，允许正常收口；最终完成与暂停竞争必须按同一持久化边界处理，不能把已经完成的运行改成 PAUSED。
- 有待处理工具、尚需新请求或新业务受理时：保存进度后进入 PAUSED，保留未执行 invocation 的 PENDING 状态。
- 并行工具：已经准入/发出的调用允许完成并落结果；仍在专用线程池或信号量队列中、尚未获得执行准入的调用不能继续启动。在线程池/限流等待之后、实际调用之前复核控制与 claim。
- 暂停不应被当作模型格式错误、工具失败、超时、取消或自动重试原因。不要因此耗掉恢复次数，或把未启动调用标成 FAILED/SKIPPED。
- 真实错误、已确认超时和实际超限仍按原规则处理；暂停不能变成规避原限额的手段。

确认 PAUSED 前，必须完成该 claim 内已准入工作的结果收集/持久化或现有超时处理，再释放租约。避免先显示已暂停、随后同一 worker 仍启动工具或提交新业务动作。

### 4.3 业务受理与恢复

`AgentPlanningOperationService`、提案用例等有业务效果的原子受理边界也需遵守暂停意图，不能仅依赖执行器之前的无锁检查。核对现有 invocation/run 锁顺序，避免新死锁。

已经受理的 operation/提案在原身份下继续完成；“业务已提交、Agent 工具结果尚未落库”的窗口恢复时查询/复用原记录，不能再调用新身份做一遍业务。保留现有业务事务与幂等身份，不许为暂停拆散事务。

暂停的结果写路径与 `requeueRun` / 终态取消不同：**不能调用会 markBatchHandled 或把所有 PENDING 标成 SKIPPED 的路径**。暂停保留未消费 MODEL_TURN 和待处理调用。

## 5. 真实调度与恢复顺序

复核并实现整条 `AgentRuntimeJob → AgentRecoveryJob/claimNext → AgentWorker.process → AgentRuntimeCoordinator`，不能只在测试里直接调用协调器。

- PAUSED 不进入自动 claim；也不因重试定时或审批外部回写自动回到 RUNNING。
- 已有暂停意图的 RUNNING 若 worker 退出、租约过期：仍需有控制收口路径先按 R1 结算已确认进度，再转 PAUSED；新 worker 不开始新动作。**不要简单把带暂停意图的过期 RUNNING 从全部接管查询里过滤掉，让它永远卡在“正在暂停”。**
- 继续后的新 claim 先复用已保存响应、已完成 invocation、已受理 operation，然后才考虑新模型请求；正常与恢复保持同一份 afterResponseSaved 规则。
- Worker 的既有预算前置检查也必须区分“准入下一次请求”和“消费已保存结果”：不能因为重新预留下一轮而丢掉有效最终文本；真实输入超限、时长与工具限额保护仍有效。
- 部分完成批次继续使用 R2 已修好的剩余调用计数，单轮上限按原批次校验，已完成项不再占新增额度。
- 并发 pause/resume/cancel/claim 与完成通过行锁、CAS、epoch 实现可解释的提交顺序；取消或终态先落库后，暂停/继续不能将它复活。重复继续只有一个有效 claim。

## 6. API、事件与目录职责

在现有 Controller/AgentRunService 增加明确的 pause/resume 用例，例如 `/runs/{runId}/pause`、`/runs/{runId}/resume`，返回权威运行状态及暂停意图。resume 是内部控制能力，不意味着页面要有继续按钮。沿用项目访问与运行控制授权，不降低权限，不创建新权限平台。

原有输入框发送入口在权威运行状态为 PAUSED 时先识别续跑意图，调用同一 resume 用例；识别与状态检查放在后端统一入口，前端消费返回的同一运行状态，不能只靠前端字符串判断绕过普通消息的目标更新。采用一个小而可测试的状态相关识别函数，覆盖常见等价说法、礼貌语气、空白和标点；不引入额外模型请求、通用意图分类框架或长关键词库。必须区分“继续刚才的任务”与“不继续了”“如何继续”“继续检查另一个项目”等表达。有歧义时保留暂停及输入，给出明确澄清提示。WAITING_FOR_USER_INPUT、普通新任务和终态下的文本仍按原用途处理。

从暂停界面发出的文本请求显式绑定当前 runId 与“处理该暂停运行输入”的作用域，可以由 resume 接口接收文本，或在现有输入接口增加最小的运行作用域字段；选择符合当前返回契约的简单方式。后端识别明确续跑意图后调用幂等 resume，即使第一个请求已经恢复，重复请求也不能退回普通 submit 新建任务。若发送途中原运行已经取消/完成，返回其最新状态或业务提示，不擅自把控制输入变成新目标。此处不需要新的通用去重平台。

状态转换、标记和相应控制事件同事务；可按现有命名增加 `RUN_PAUSE_REQUESTED`、`RUN_PAUSED`、`RUN_RESUMED`，完整贯穿 enum、数据库 CHECK、view/DTO、前端类型/归约器及事件重放。不能只改 Java enum 忘记 SQL 约束。

控制事件不是新的 USER 目标消息；不要污染 latestRequest/goalRevision/摘要中的当前任务，也不重复写最终回答。幂等命令不产生重复控制事件。

前端展示依据运行详情和同一事件流，刷新从数据库恢复；暂停等待可停止 Agent 执行流的无意义重连，恢复需重新订阅原 run。**非终态不等于一直活跃**，不要把 PAUSED 标成终态以省事。已受理规划的独立状态更新与卡片读取继续有效。

维持 M1–M4 的职责：API 转换、应用用例、运行时动作边界、domain 状态规则、仓储/Recorder 原子事实、前端纯归约与组件。新控制协作者只在确有职责需要时添加，不为了拆小文件制造回调链、通用中间件或重复 Bean。

## 7. 前端交互完整交付

沿用当前 Agent 页的视觉风格、对话主线、自然过渡说明、紧凑工具行与规划卡片，不重做布局或增加大量诊断配置。可使用已安装 impeccable 做局部交互完善，范围为既有界面；无需开启新品牌设计或产品访谈。

- QUEUED/RUNNING/自动重试等待时提供“暂停”；“结束本次运行”沿用取消，作为次要操作，别再用模糊“停止运行”混淆两种行为。
- 暂停请求发出：按钮 loading、防重复点击；收到意图但尚未确认时显示“正在暂停，当前步骤完成后保留进度”。此时输入继续意图不能提前撤销暂停或启动另一推进者，保留输入并提示等待暂停完成。
- PAUSED：稳定的暂停状态和“进度已保留”；输入框保持可用，提示“输入继续，接着完成当前任务”，沿用发送按钮和 Ctrl+Enter；不添加继续按钮。“结束本次运行”作为次要操作。停止“正在分析”的运行提示/脉冲，不假报失败；保留正文、工具展开态、焦点、滚动位置和规划卡片。
- 继续：同一个 run 恢复事件订阅与后续活动，最终回答仍只出现一次；已有工具条目不重复，不因恢复重挂载整个活动块。
- 所有 pause/resume 请求记录 projectId、sessionId、runId 和恢复代次；响应到达时核对作用域。切项目/会话、当前 run 已换或组件销毁后，迟到响应不能覆盖页面或订阅错误运行。pending 门闩和异常释放也要正确。
- 暂停期间通过现有发送入口识别常见明确续跑表达，后台分流到同一 resume 命令，不追加为新目标。处理期间防重复发送，成功后清空已受理的控制输入，失败或需要澄清时保留草稿。状态变化可在活动流显示“已继续”，不伪造新的用户任务或最终回答。WAITING_FOR_USER_INPUT 的文本仍按澄清回复处理。
- 本轮不支持“继续并修改目标”的智能续接：暂停期间其他新要求不要静默清空、替换目标或直接重放旧参数。保留输入草稿，明确提示继续原任务，或先结束本次运行再发送新要求；也可使用现有“新建会话”。服务端普通消息入口必须防止暂停/暂停请求期间的新消息悄悄改写当前任务的工作状态。无需新增约束版本平台。
- 刷新、切回会话和其他标签页恢复必须显示真实状态；竞态中任务已完成则显示完成，不把刚发送的续跑意图变成另一条新任务。控制错误用明确业务文案，不显示原始 IllegalStateException/500。
- 键盘可操作、焦点可见、状态不只靠颜色；桌面与窄屏按钮可用，无横向溢出。暂停后 SSE 不活跃是正常状态，别显示成连接故障警报。

## 8. 必须做的确定性验收

测试需要覆盖真实行为与提交边界，优先 Spring 原子写路径 + 隔离 PostgreSQL + 安全替身模型/工具。用同步点、事务锁或受控时刻，不等待完整租约、不靠 sleep 碰竞态。不要仅靠 Mockito 确认方法调用，或复制实现写镜像断言。

| 场景 | 必须证明的行为 |
| --- | --- |
| QUEUED / 自动重试等待暂停 | 无新动作，自动调度不领取 PAUSED；继续不重置已耗重试次数/预算 |
| 模型在途暂停 | 请求可以完成并保存；不因暂停意图版本变化丢响应；返回工具时后续调用保持 PENDING |
| 完整文本已保存后暂停或 worker 退出 | 经真实 Worker 入口继续完成原答案，新增模型请求为零，答案/事件/步骤一次 |
| 部分工具已完成 | 继续只执行剩余项；已有动作与结果不重复；16 额度边界仍正确 |
| 工具线程池/信号量排队 | 暂停后未获准入的排队调用不新启动；已准入结果落库；不误标 SKIPPED/失败 |
| 规划已受理、Agent 结果未落库时退出 | 同一 operation/attempt 继续；后台在暂停期间可完成；继续读取原结果，零重复受理/审批 |
| 暂停意图写入后 worker 退出 | 接管只确认 PAUSED，不推进动作；租约等待不算执行；继续有新 claim，旧 worker 被拦截 |
| 并发重复 pause/resume 与 claim | 一次有效状态变化/事件、一个推进者、原 runId，不新建派生运行 |
| pause 与新业务受理/完成/cancel 竞争 | 提交顺序可解释；暂停先准入则无新业务，业务先准入则保留其结果；终态不被覆写 |
| 恢复中改配置、来源模式与撤权 | 新请求用当前配置，旧调用用原 source_mode；权限/审批/实际超限继续有效 |
| 控制事务中途失败 | 状态/标记/事件整体回滚，不出现数据库已暂停但无事件的拆分提交 |
