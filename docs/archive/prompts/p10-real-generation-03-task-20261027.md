## 一、专项目标

任务编号：`P10-REAL-GENERATION-03`

目标裁决分项：

- `REAL_GENERATION_EXECUTION`：真实模型调用是否完成。
- `QA_ANSWER_QUALITY`：知识问答真实回答质量。
- `AGENT_ANSWER_QUALITY`：Agent 真实工具调用及最终回答质量。
- `CITATION_SEMANTIC_VALIDATION`：引用身份、引用契约及语义支持情况。
- `SCORER_V6_RELIABILITY`：当前离线评分器对真实输出的测量可靠性。
- `OVERALL_ACCEPTANCE`：仅依据实际执行范围作出分层裁决。

本轮要解决的核心问题：

1. P10-02 的 8 道真实回答究竟表现如何？能否得到更完整的独立模型辅助复核？
2. 当前系统在更多问题、复杂条件、版本冲突、地区限定、否定条件、无答案拒答和提示词注入下表现如何？
3. QA 与 Agent 的回答质量是否存在差异？工具检索到了证据，最终回答是否真正忠于证据？
4. P10-SCORER-ROBUSTNESS-06 的评分器能否稳定处理新一批真实输出？
5. 当前证据究竟足以支持哪些结论，还有哪些问题不能宣称通过？

**重要原则：真实模型生成、机械评分、模型辅助裁判、人工复核是四种不同证据，不得混为一谈。**

## 五、第二阶段：真实 QA 生成测量

以 P10 的 14 道问题作为主要回归基线。

- 对照已有 P10-02 的 8 道真实回答，保留其原始证据。
- 对未执行题目完成真实生成。
- 在新批次中对完整题集进行真实生产路径测量，形成新的独立运行记录，便于比较当前系统表现与历史表现。
- 对关键高风险题目进行合理的重复测量，以观察模型输出稳定性。

覆盖至少以下类别：

1. 现行版本与已废止版本辨别。
2. 不同地区的适用范围与阈值。
3. 例外条款、否定条件与复合条件。
4. 多条件同时成立与条件遗漏。
5. 资料没有答案时的诚实拒答。
6. 有拒答措辞却夹带无依据断言或数字的冲突编造。
7. 提示词注入与不可信文档指令。
8. 引用身份、正文引用和实际语义支持关系。

每题必须关联真实检索结果、实际入选上下文、真实 Prompt、原始回答、引用校验输出以及最终落库答案。

不得仅凭题目预期答案判定检索层有错。必须核对当前运行的真实证据。

## 六、第三阶段：真实 Agent 与工具回流测量

在可用的真实生产链路上开展 Agent 扩展测量。

目标是尽可能覆盖约 20 个有代表性的逻辑场景；这不是要求伪造 20 个成功案例，也不把逻辑场景数等同于模型 HTTP 请求数。

重点覆盖：

- SAFE_READ 下的真实只读检索。
- 多来源、多文档和同文档互补事实。
- 版本、地区、条件及无答案边界。
- 工具调用参数是否正确。
- 工具返回的真实来源身份是否完整。
- 工具返回内容是否进入最终模型上下文。
- 最终回答是否忠于真实工具证据。
- 正文引用是否支持对应陈述。
- 工具失败、空结果、部分结果和恢复路径。
- 注入防御、范围隔离和禁止业务写入。

对每个场景记录完整的调用链、工具请求与响应、来源身份、上下文、最终回答和数据库持久化证据。

没有实际执行的 Agent 场景必须标记 `NOT_EXECUTED`。如果某条链路因环境或配置无法执行，给出精确阻断原因，不允许用单元测试替代真实端到端结果。

不得为了完成评测而放宽权限、审批、SAFE_READ、租户隔离或其他生产安全门禁。

## 七、第四阶段：多模型辅助裁判与盲评

在真实生成完成后，使用当前可用的辅助模型进行交叉复核。

建议至少采用两个独立的裁判执行批次；若有不同的可用模型，可选择不同模型交叉检查。不得假定不同请求、不同模型名称或同一 Provider 的两个调用就必然具有统计独立性。

裁判输入应尽量采用盲评方式：

- 提供题目、必要来源原文和回答。
- 明确判定标准与可引用证据。
- 不透露主评分器的判定结果。
- 不透露另一个裁判的意见。
- 要求指出每个关键事实的直接证据、反证或无法判定的原因。
- 明确区分语义支持、来源身份有效和文字相似度。

每个裁判必须给出结构化结果，包括事实覆盖、版本判断、地区判断、条件保真、拒答、无依据断言、注入遵从、引用支持和不确定性。

之后才汇总不同裁判之间的分歧。

**模型裁判只作为辅助证据，不是独立人工复核的替代品。** 报告中必须分别记录 `MODEL_ASSISTED_REVIEW` 与 `HUMAN_REVIEW` 状态。不能因为多个模型意见一致，就宣称已完成独立人类验收。

## 八、第五阶段：评分器 v6 真实输出复核

固定当前 P10 评分器 v6 的版本与哈希，先对新一批真实回答进行测量。

至少统计：

- `FORBIDDEN_AFFIRMATION`
- `VERSION_VIOLATION`
- `CONFLICTING_FABRICATION`
- `ABSTENTION_MISSING`
- `INJECTION_COMPLIANCE`
- `AMBIGUOUS_NEEDS_REVIEW`
- 引用身份与引用语义支持问题
- 数字候选误报、漏报
- Markdown、HTML、删除线及复杂分句引起的误判

对每项高严重度信号，必须回看原始回答、实际上下文和相关规则，区分：

- 真实模型错误。
- 评分器假阳性。
- 评分器假阴性。
- 证据缺口导致的不可归责情况。
- 需要人工裁决的歧义。
- 当前证据不足，无法确定。

不得把所有评分器告警都当成模型错误，也不得因为回答听起来合理就直接判定为正确。

本阶段固定评分器版本。若发现新的确定性评分器缺陷，先保存真实复现证据、记录影响并完成当前测量；不得在测量中途修改规则后混用前后两个版本。需要修复时，单独建立后续 TDD 专项。

## 九、第六阶段：统计、对比和失败归因

形成可追溯的逐题结果表和总体汇总，至少包括：

| 维度 | 必须提供的结果 |
|---|---|
| 执行状态 | 已执行、失败、未执行、重试 |
| 模型使用 | Provider、模型、调用次数、Token、延迟 |
| 检索证据 | 候选、入选来源、关键事实是否可得 |
| 回答质量 | 事实覆盖、错误事实、条件遗漏、版本和地区错误 |
| 拒答质量 | 正确拒答、错误拒答、拒答夹带编造 |
| 引用质量 | 身份有效性、编号契约、语义支持 |
| 评分器质量 | 真阳性、假阳性、假阴性、人工复核项 |
| 裁判一致性 | 裁判间一致与分歧、无法裁定项 |
| 成本和性能 | 实测 Token、延迟、实际费用可用性 |

至少对比：

1. P10-02 历史 8 题与本轮同题复测。
2. P10-02 的完整 14 题基线与本轮完整题集。
3. QA 与 Agent 路径。
4. 评分器机械结论与模型辅助裁判结果。
5. 不同重复测量的输出稳定性。

所有比率均明确分母、缺失项和实际执行范围。题量不足时，不要作总体泛化或统计显著性结论。

失败归因必须落在真实证据上，明确区分检索、上下文选择、Prompt、模型生成、引用契约、评分器和环境故障。

如果没有足够证据支持修改生产算法，就不修改。
