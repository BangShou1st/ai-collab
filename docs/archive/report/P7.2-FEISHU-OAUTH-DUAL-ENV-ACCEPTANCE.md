## 二、20049 根因及直接证据

**根因：授权端点与令牌端点配对错误。** 代码用 `accounts.feishu.cn/open-apis/authen/v1/authorize`（带 PKCE）发起授权，但令牌交换打到了 `accounts.feishu.cn/oauth/v3/token`。`oauth/v3/token` 是飞书面向 app_access_token/tenant_access_token 的 RFC-6749 端点，**尚未接入 PKCE 校验**：凡由 PKCE 流程（`code_challenge`）签发的授权码到 v3 端点交换，服务端无法校验 challenge，直接返回 `20049 PKCE code challenge failed`。此前"本地 challenge 与解密 verifier 重算指纹一致"只能证明应用内部自洽，无法暴露端点侧协议不匹配。

**直接证据链**：
1. 飞书官方文档《获取 user_access_token》《刷新 user_access_token》（riba2534/feishu-open-docs 官方镜像，2026-05 更新）：HTTP URL 为 `https://open.feishu.cn/open-apis/authen/v2/oauth/token`；官方 Golang 示例的端点配对正是 `AuthURL: authen/v1/authorize` + `TokenURL: authen/v2/oauth/token`。
2. 官方 v2 错误码表将 `20049` 定义在 **v2 端点**下（"PKCE code challenge failed，请检查 code_verifier"），v3 端点文档（tenant/app token）无此码。
3. 官方 SDK（larksuite-oapi-sdk-rs）常量 `USER_OAUTH_TOKEN_URL_PATH = "/open-apis/authen/v2/oauth/token"`，注释明确用于 user authorization-code 与 refresh 流程。
4. 应用日志中飞书返回的 `feishuCode=20049`（6699083 加的 WARN 日志捕获）与上述协议结论完全一致；本地 start/complete 指纹一致排除了应用侧 challenge 篡改。

## 三、官方 OAuth 协议核实依据（修复依据）

| 协议点 | 官方结论 | 修复动作 |
| --- | --- | --- |
| 端点配对 | `authen/v1/authorize` ↔ `authen/v2/oauth/token` | 令牌端点换为 v2 |
| Content-Type | v2 固定 `application/json; charset=utf-8` | form-urlencoded 改 JSON 请求体 |
| 请求字段 | grant_type/client_id/client_secret/code/redirect_uri/code_verifier | 字段保持一致，编码方式修正 |
| PKCE | code_verifier 43-128 字符，S256 | 保留 S256 与现有 verifier 生成（43 字符） |
| 响应结构 | 顶层 `code`（0 成功）+ access_token/expires_in/refresh_token/refresh_token_expires_in/scope | 解析保持兼容（原本就按顶层字段） |
| Refresh 轮换 | refresh_token 仅能使用一次，轮换下发新值 | 保留现有互斥与轮换落库语义 |
| 错误码 | 20003/20004/20065（code 无效/过期/已用）、20026/20037/20064/20073（refresh 无效/过期/撤销/已用）、20071（redirect 不匹配）、20072（503 临时）、20074（应用未开刷新） | 按表补全映射（见下） |
| State 防 CSRF | 授权码 5 分钟有效且单次使用 | 保留 state 哈希存储与 300 秒过期 |

错误码映射：20003/20004/20065 → 重新授权（授权码一次性，不得重放）；20071/20074 → 配置错误；20026/20037/20073 → 重新授权；20064 → 已撤销；20072/429 → 临时故障；5xx → 结果未知。**未取消 PKCE、未绕过 State、未关闭权限校验；单次交换失败不会用同一 Code 跨协议重试（测试断言 requests==1）。**

## 八、环境变量模板与双环境差异

统一语义（Local/Staging/Production 相同含义，切换只改值不改代码）：

| 变量 | 用途 | 本地 | Staging | Production |
| --- | --- | --- | --- | --- |
| `APP_PUBLIC_URL` | 用户访问的前端 origin | 可空（前端回退） | 网关前端地址 | Cloudflare Pages 域名 |
| `FEISHU_OAUTH_REDIRECT_URI` | 飞书回调完整 URL | 可空（不启用飞书） | 网关回调 URL | 生产回调 URL |
| `AUTH_ALLOWED_ORIGINS` | 认证 CORS 白名单 | `http://localhost:5173` | 前端 origin | 生产前端 origin |
| `BACKEND_ORIGIN` | Pages Function 转发目标 | 不适用 | 预览分支可回退 | 必填，缺失明确 503 |
| `MINIO_PUBLIC_ENDPOINT` | 文件下载公开地址 | `http://localhost:9000`（默认） | 网关地址 | 独立下载 origin |
| `MODEL_CONFIG_MASTER_KEY` | 加密根密钥 | 必填 | 必填，**不得更换** | 必填，**不得更换** |

Java/Vue 源码零硬编码业务地址；`dev.ps1 Validate-Config`/`doctor` 拒绝通配符与占位符密钥；Pages 双 Function（api/storage）统一走 `resolveBackendOrigin` 校验，**Production 不可能静默使用 Staging 后端**（本轮修复了 storage Function 的残留回退）。
