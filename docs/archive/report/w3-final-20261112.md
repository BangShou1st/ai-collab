## 3. 测量 A（门禁，stub）

环境：本机 worker 进程 + 本地 stub Java 网关（`latencyMs=0`）；冻结集 15 条；每档
`--candidate-target {8,20,50}` × 34 runs（warmup 0）= **510 样本/档**。

| 候选数 | 样本 | P50 | P95 | P99 | overhead P95 | overhead P99 | confidence | 判定 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- | --- |
| 8 | 510 | 5.012 ms | 11.933 ms | 17.004 ms | 11.933 ms | 17.004 ms | HIGH | **PASS** |
| 20 | 510 | 5.850 ms | 24.413 ms | 40.968 ms | 24.413 ms | 40.968 ms | HIGH | **PASS** |
| 50 | 510 | 16.188 ms | 37.911 ms | 45.957 ms | 37.911 ms | 45.957 ms | HIGH | **PASS** |

- 门禁：overhead P95 ≤ **800 ms**、P99 ≤ **1500 ms**；三档均通过，余量 ≥20 倍；
- stub 下 `T_model` 已知且恒为 0 → `overhead == total`；
- 原始证据：[`docs/acceptance-evidence/2026-11-12/w3-1-rerank-latency/`](../../acceptance-evidence/2026-11-12/w3-1-rerank-latency/)；
- Java 侧独立证据（`RerankOverheadBudgetTest`）：`samples=510 p50=3.007ms p95=5.130ms p99=6.305ms`。

**限定**：候选 20/50 由 `--candidate-target` 以合成候选补齐（`labels=0`），补齐档的 NDCG/支持率
不具可比性；本测量只证明**服务开销**，不证明排序质量。

## 5. W3.2 Ed25519 短令牌

### 5.1 格式与模式

- JWS Compact `alg=EdDSA`、`typ=JWT`、`kid`；claims `iss=ai-collab-backend`、`sub=backend`、
  `aud=["ai-worker","backend"]`、`scope="rerank model-call decide plan"`、`jti`、`iat`、`exp`
  （TTL 300s）；允许 ±60s 时钟偏移；
- Java 模式：`static`（默认，行为不变）/ `ed25519`（只验短令牌）/ `dual`（轮换过渡：签发 Ed25519，
  验签先 JWT 后静态）；
- Python 模式：`static` / `ed25519` / `dual`；**只持公钥**，验签通过后把**入站 Bearer 原样**
  透传给 Java `/internal/ai/v1/model-calls`（不重签、不落盘、不进日志）；
- 私钥只在 Java（PKCS#8 DER base64），公钥在 Python（SPKI DER base64，多 `kid`）。

### 5.2 必测矩阵（全部通过）

| # | 用例 | 结果 |
| --- | --- | --- |
| 1 | 合法令牌 | 通过 |
| 2 | `exp` 过期 | 401 / expired |
| 3 | 签名篡改 | 401 / bad_signature |
| 4 | `aud` 不符 | 401 / audience |
| 5 | `sub` 不符 | 401 / subject |
| 6 | 未知 `kid` | 401 / unknown_kid |
| 7–8 | 时钟偏移 ±59s / ±61s | 通过 / 401 |
| 9–10 | 轮换：旧公钥保留 / 只配新公钥 | 通过 / unknown_kid |
| 11 | `alg=none` / 篡改 header | 401 |
| 12 | 日志与错误体不含令牌 | 断言通过 |
| 13 | `static` 模式回归 | 通过 |
| 14 | 跨语言：Java 固定密钥/claims 生成的 JWS == fixture.token，Python 验签通过 | 通过 |

另：`InternalTokenIssuerTest` 用 RFC 8032 §7.1 TEST 1 向量验证"私钥→公钥"派生（JDK 无公开 API，
按 RFC 8032 标量乘基点实现，仅启动时一次）。

### 5.3 客户端接线（集成期修正）

- 三个认知端点统一走 `api/auth.require_token`（scope 分别为 `rerank`/`plan`/`decide`）；
- `DecideGatewayClient` / `QueryPlanGatewayClient` 改为依赖 `InternalTokenProvider`（原复用
  `RerankProperties.serviceToken`），ed25519 模式下 shadow/契约调用才能带上可验签的短令牌；
- Java 服务令牌 scope 扩为 `rerank model-call decide plan`。

### 5.4 证据等级

离线单测 + 跨语言 fixture = **TESTED**；**真实 staging 双端联调/轮换演练 = NOT_VERIFIED**
（本会话无 staging），上线前必须补。

## 6. W3.3 shadow 采样

- `rerank.shadow-sample-rate`（`RERANK_SHADOW_SAMPLE_RATE`）默认 **1.0**（保现状），区间 [0,1]；
- 未采样 → `rerank.shadow.skipped{reason="sample"}`；并发饱和 → `{reason="saturated"}`；
- 抽样在 Java 结果算完之后、提交后台之前，不影响用户可见结果与延迟；
- runbook 建议 staging `0.1–0.2`；真实流量下效果 **NOT_VERIFIED**。
