## 二、缺陷清单

### P1-1 AI 任务规划：人工编辑无法保存，“确认落库”永远无法到达
- **现象**：规划生成后（v2）提示“规划已生成，但有 27 项需要确认”（负责人未分配/缺参考来源）。逐个“采纳建议负责人”、修改任务后点击页面底部**“保存新版本”**：按钮可点击（disabled=false），但**未发出任何网络请求**（网络日志只有 GET），无成功/失败提示；版本号不变、警告数不变。由于警告无法清零，页面上**始终不出现“确认落库/写入任务”按钮**，与页面自述“草案 → 审核 → 确认，只有确认后才会写入真实项目任务”矛盾。
- **影响**：AI 规划这一核心卖点止步于“生成”，人工审核成果无法落库，功能实际不可用。
- **复现步骤**：
  1. `uatowner1102` 登录 → UAT验收项目一 → 任务规划 → 创建规划（标题/目标/约束，开始 2026-11-02 截止 2026-11-16）
  2. 等待生成完成（约 5–10 分钟）→ 点击任一警告的“手动编辑” → 点“采纳建议负责人”或修改任务标题
  3. 滚动到底部点击“保存新版本”
  4. 打开 DevTools Network：无任何 POST/PUT 请求；警告仍 27 项，无“确认”按钮
- **证据**：`10-plan-save-noop.png`、`09-plan-review.png`；网络日志（仅 GET task-plans*）
- **建议**：修复保存动作的提交链路；保存失败必须有明确错误提示；考虑“批量采纳/一键分配全部负责人”；警告清零前在页头明示“还需处理 N 项后可确认”。

### P1-2 协作 Agent：只读分析运行无法产出最终答复，运行标记“失败”
- **现象**：发送“请逐一检查项目里所有任务的依赖关系、负责人和截止日期，并给出完整的健康度报告”（纯只读），Agent 完成全部工具步骤（查阅项目资料 3 项查询 ✓、分析项目风险 ✓）后**没有生成任何最终回答**，会话状态直接“失败”，并提供“重试”。重试后同样失败（2 次复现，模型 DeepSeek-V4.1-Flash-1017）。
- **影响**：Agent 的只读分析类场景完全不可用；写操作链路正常，反差明显。疑似工具循环结束后的最终模型响应生成/解析失败（如空回复或格式问题），且失败原因未在 UI 展示（“诊断与资源”面板未能打开，无法进一步定位）。
- **复现步骤**：
  1. 进入 协作 Agent → 输入上述只读指令 → 发送
  2. 等待工具步骤全部 ✓ → 观察无最终答复，会话列表标记“失败”
  3. 点“重试” → 复现
- **证据**：会话列表“项目协作 2026/11/2 失败”、“运行 · 失败”标题（截图未单独留存，过程记录于会话内）
- **建议**：修复最终响应生成；失败时在“运行 · 失败”旁展示服务端错误摘要；“诊断与资源”面板点击无响应需一并排查。

### P2-1 规划创建对话框的日期选择器禁用所有未来日期
- **现象**：创建规划的“开始/截止”日历中，今天（2026-11-02）之后的全部日期为灰色不可选，翻月亦然；规划“两周内上线”只能靠在输入框**键盘输入**日期绕过。
- **复现**：任务规划 → 创建规划 → 点开“开始”日历 → 观察 11/3 起全部置灰。
- **证据**：`08-planning-date-picker.png`
- **建议**：日期禁用逻辑疑似写反（应为“不早于今天”），需修正并补充未来日期用例。

### P2-2 移动端任务看板缺少“新建任务”入口
- **现象**：iPhone 14 视口（390×844）下，任务看板 DOM 中不存在“新建任务”按钮（`document.querySelectorAll` 计数为 0），移动端用户无法创建任务。
- **证据**：`12-mobile-board.png`
- **建议**：移动端为高频写操作提供浮动操作按钮或收纳进菜单。

### P2-3 偶发“空遮罩层”导致整页不可点
- **现象**：连续开关任务详情/编辑弹窗后，出现 `el-overlay display:block` 但内部无任何对话框的透明遮罩（z-index 2057），页面所有点击失效约 10 分钟，最终需刷新恢复。复现 1 次。
- **证据**：DOM 快照（`{"overlays":[{"display":"block","z":"2057"}...], "dialogs":[...parentVisible:false]}`）+ `06-empty-overlay-bug.png`
- **备注**：测试环境同时存在浏览器扩展干扰（扩展自身报 React #185 错误，见控制台），不排除叠加诱因，请开发在干净环境复核。
- **建议**：弹窗关闭动画结束时应确保 overlay 卸载；可加“点击遮罩关闭/ESC 兜底”。

### P3（体验问题，不阻塞）
1. **负责人显示为 UUID**：Agent 执行过程与提案正文显示“负责人：14d0f01f-4323-…”，而审批卡片内是显示名，前后不一致且不可读。
2. **弹窗预校验提示过早**：新建项目/新建任务弹窗一打开就显示“项目名称不能为空/任务标题不能为空”。
3. **工作台 AI 卡片状态不同步**：能力探针 4/4“已验证可用”后，工作台仍显示“可用性需在 AI 设置中测试确认”。
4. **规划编辑无自动保存/未保存提醒弱**：仅在 beforeunload 时拦截；测试过程中用户完成分配后误以为已保存（本次实测真实发生）。建议编辑卡提供显式“已保存”状态标记，或自动保存草稿。
5. **规划生成过程反馈单一**：约 5–10 分钟内仅显示“正在生成规划骨架”，无阶段进度/耗时提示（v0→v2 静默跳变）。
6. **规划编辑器“负责人”下拉曾出现“无数据”**（后续复测多数卡片有数据），疑与懒加载时序有关，建议复核。

## 三、改进建议（按优先级）
1. 修复 P1-1/P1-2 两个 AI 主链路阻断问题（上线前必须）。
2. 补齐移动端写操作入口（P2-2），修正日期选择器（P2-1）。
3. 为 Agent/规划的长耗时操作增加阶段化进度与失败原因透出。
4. UUID→显示名统一映射；表单校验改为提交时或输入后触发。
5. 建议对“AI 规划确认落库”与“Agent 只读分析”补充端到端自动化用例，避免回归。

## 四、最终结论

**AI Collab 目前尚未达到真实普通用户可长期使用的程度。**

- **达到可用水平的部分**：账号/项目/邀请/任务/依赖/文档/RAG 问答的完整协作链路顺畅且工程质量较高——RAG 引用可查、权限服务端强制到位、任务状态机与依赖约束前后端一致、Agent 写操作的“先审批后落库”设计真实有效（批准后任务确实写入看板）。这部分已具备日常使用条件。
- **阻断性短板**：两大 AI 卖点折损过半——AI 任务规划能生成却**无法人工确认落库**（P1-1），Agent 只读分析**无法产出最终结论**（P1-2）。以“AI 协作平台”的定位，这两个 P1 使核心价值闭环断裂。
- **修复建议**：优先修复上述两个 P1 并回归后复测；P2/P3 可随下一个迭代处理。修复后预期可达到可用水平，其中 RAG 与 Agent 审批链路已接近生产质量。
