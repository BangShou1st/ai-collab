## 2. Python 端点（实现版）

### 2.1 `/v1/rag/plan`

- 请求/响应字段与边界严格按冻结 §1；`deadlineMs` 默认 8000、上限 30000，取
  `min(请求, AI_WORKER_QUERY_PLAN_DEADLINE_MS)`；
- `filters` 独立模型 `extra=forbid`，只允许三类键；`filters.documentIds ⊆ 请求 documentIds`，
  编造 id 丢弃并记 `ai_worker_query_plan_unknown_document_ids_total`（按去重 id 数）；
- `dateRange` ISO 日期、`from<=to`；`confidence∈[0,1]`；
- 解析允许 Markdown 围栏单 JSON；缺字段/类型错/越界 → `SCHEMA_VIOLATION`(422)；
- 鉴权走 `api/auth.require_token(scope="plan")`，入站 Bearer 原样透传给 Java 网关；
- 指标：`ai_worker_query_plan_duration_seconds{outcome}`、`_confidence`、`_unknown_document_ids_total`。

### 2.2 `/v1/agent/decide`

- 四决策 `CALL_TOOL/FINAL/ASK_USER/NO_OP`；`CALL_TOOL` 必须带 `toolCall.name`（∈ 本次 tools）与
  object `arguments`；其它决策不得带 `toolCall`；
- 非法决策/越界工具名 → **内部重试一次**（固定纠错段，不回显模型原文）→ 仍非法
  `SCHEMA_VIOLATION`(422) + `ai_worker_decide_invalid_tool_call_total`；
- 幂等键四元组、缓存 10 分钟/1024 条/只缓存成功/同键不同 body 400/逐字节重放；
- `asyncio.timeout(budget.deadlineMs)` → 504，无半成品；
- prompt 组合字节 >64 KiB → 422 `INVALID_REQUEST`；
- `purpose=AGENT`（Java 侧按 Agent 档位选路/记账）；`promptVersion` 取 `decide.system` 版本；
  `latencyMs` 取网关值（缺失 null）；`usage` 缺失 UNKNOWN；
- 指标：`ai_worker_decide_duration_seconds{outcome,decision}`、`_invalid_tool_call_total`、
  `_retry_total`、`_contract_violation_total`；**不返回 token 流**。

### 2.3 PromptPack

新增 `query_plan.system/user`、`decide.system/user`（`2026-11-12.1`），只经 PromptStore 读取；
manifest 18 条、Java fallback 19 文件，`ai-prompts check`/`export-java --check` 绿。

## 3. Java decide shadow

- `decide.mode=java`（默认）：**零外呼、零快照、零指标**，与未实现时一致；
- `shadow`：仅在 `depth=0` + `PROJECT_RESEARCH` + 只读 + 工具轮边界触发；虚拟线程 +
  `Semaphore(8)`；**不重试**；失败只记指标；
- 快照有界（facts≤8×500、messages=[]、observations≤6×400、tools≤16、schema≤2000、
  总 ≤32000 字符；超限按 observations→facts→未调用 tools 裁剪，**被本轮调用的工具不会被裁掉**，
  裁不掉则跳过该轮并记 `skipped{turn}`）；
- `snapshotHash="sha256:"+sha256(canonicalJson(除 snapshotHash/schemaVersion))[0:32]`；
- Java 侧决策由真实响应推导（CALL_TOOL 取第一个工具名 / FINAL / NO_OP），记录一致率、无效
  工具调用、契约合法性、延迟、失败原因；
- **绝不**把 Python 的 toolCall 交给 `AgentToolCallExecutor`；服务没有执行器/仓储/事件协作者，
  测试用 `verifyNoInteractions` + 反射断言；
- 集成修正：客户端不再把"工具名不在本次 tools"当契约异常（否则 `invalid_tool_call` 永远为 0），
  成员资格判定留给 shadow 服务计量。

### 3.1 指标

`decide.shadow.calls{decision}`、`.agreement{result=match|mismatch}`、`.invalid_tool_call`、
`.contract{result=valid|invalid}`、`.failure{reason}`、`.skipped{reason}`、`.truncated`、`.latency{outcome}`。

### 3.2 QueryPlan Java 契约

`QueryPlanGatewayClient` + DTO + `query.plan.enabled=false`；`filters` 只接受三类键，
未知键按契约违规拒绝；7 项 HttpServer stub 测试；**没有任何检索调用方**。

## 4. `ai-eval decide`（冻结集结果）

冻结集 32 条：20 golden（合法输出，人工标注）+ 12 adversarial（越界工具名/非法 JSON/缺字段/
参数非 object/决策违规）。结果（`--scorer replay`，stub）：

| 子集 | cases | 指标 | 值 |
| --- | ---: | --- | --- |
| golden | 20 | decisionAgreement | **1.0（20/20）** |
| golden | 20 | jsonValidityRate | **1.0（20/20）** |
| golden | 20 | schemaViolations | 0 |
| adversarial | 12 | rejectedRate | **1.0（12/12）** |
| adversarial | 12 | invalidToolCalls | **2**（负样本，验证检测能力） |
| 全体 | 32 | decisionAgreement / jsonValidityRate | 0.625 / 0.625（含负样本分母） |
| — | — | confidence | `LOW_CONFIDENCE`（32<200） |
| — | — | evidence / qualityClaim | `TESTED (stub)` / `NOT_VERIFIED` |

**这不是**"达到 98%/99.5%"的证据：golden 全绿只证明**契约与管线正确**；真实模型的一致率/合法率
必须在 staging 由 `--scorer worker` 产生，本会话不可达 → **NOT_VERIFIED**。
