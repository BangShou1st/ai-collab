**核对备注（证据限定与差异更正）**

1. **S1.5 thinking 关闭的证据强度**：只有**配置级**（provider `capabilities=["CHAT","STREAMING"]` 不含 `THINKING` → `GeminiModelAdapter` 必然下发 `generationConfig.thinkingConfig.thinkingBudget=0`）与**请求级**（该模型接受 `thinkingBudget=0` 返回 200，未触发 fallback 去字段；全部 200 响应无 `thoughtsTokenCount`、无 `thought` part）两层证据；该模型在**所有模式**下都不返回 `thoughtsTokenCount`（含 `includeThoughts=true` 对照组，输出 token 数同为 220），**无法用 token 数对照证明 thinking 差异**。
2. **memory recall 分母**：S3 报告正文原写 `recall 0.00（0/19）`，但封印 `aggregate-memory.json` 的 14 个 case `judged` 之和为 **20**（3/2/2/1/1/1/1/1/1/1/2/1/1/2），仓库冻结集 `tests/fixtures/memory_set/memory_baseline.v1.jsonl` 亦为 **20**；`recall = matched / Σjudged` 由冻结代码计算（`eval/memory.py`）。本报告按证据记 **0/20**；S3 报告已同步更正为 **0/20**，比值 0.00 与判定不受影响（未重算、未改口径）。
3. 其余数字均逐项回读证据文件，与任务简报一致；模型在各阶段不同的情况见 §0.3。

## 5. 未完成项与风险

### 5.1 未完成项

| 项 | 状态 |
| --- | --- |
| W3.1 真实用户 canary | 未做（shadow ≥1 周未执行） |
| W3.3 真实流量抽样 | 未验证（`rerank.shadow-sample-rate` 仅单测） |
| W4 真实用户 shadow | 未做（decide 只在冻结集上测得 0.70 / 0.95） |
| W5 Job dispatcher / recovery | 未实现（无真实触发与租约恢复调度） |
| W5 候选审核 / 发布 | 未实现（候选无法离开 `PENDING_REVIEW`） |
| `/v1/jobs` 端点验证 | NOT_VERIFIED（static 无 claims，503 fail-closed） |
| memory job 端到端 | 未验证（依赖上两项） |

### 5.2 风险

1. **免费 provider 不可作生产依赖**：ModelScope 出现 429（tier 20 观测首轮 60 次尝试中 31 次 429，51.67%）与整体慢（model P50 3.3–9.2s）；Gemini 免费档 15 RPM 且存在 15–30s 尾延迟尖峰（30s 诊断仍见 15.2s / >30s）。
2. **样本量不足**：S3 为 32 / 21 / 14 例，S1 门禁 15/档、观测 60/档，S1.5 门禁 15 次——全部 <200，一律 `LOW_CONFIDENCE`；不得外推到生产或其他 provider / 模型。
3. **门禁语义风险**：overhead 门禁在真实链路虽达标，但 gate 层只有 2 个 known 样本；"overhead 达标"不能替代"3s 预算达标"。
4. **证据标签风险**：D10 未修前，引用 aggregate 必须同时引用 sidecar，否则会把真实模型结果读成 stub。

### 5.3 建议下一步

1. 付费 / 专用配额，或把 deadline 与降级策略解耦（异步 / 流式首字节 / 局部 rerank），先在 staging 复测同一三档门禁；
2. 修 D5（planning 默认 deadline）后再做 shadow 接线，避免默认 503 污染观测；
3. 重做 D6 / D7 的评测设计（在模型输出上做定向变异；判定集保证 facts 支撑 + 语义匹配口径），冻结后重跑；
4. 补 W5 Job 触发 / recovery / 候选发布闭环，并用 Ed25519 job claims 验证 `/v1/jobs` 端到端；
5. 再评估 W4 decide 的 prompt 与策略（"追问 / 不动作"被系统性替换为调工具）。
