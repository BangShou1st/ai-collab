## 2. D1 候选召回实验（R0/R1a/R1b）：词法补充无最终证据净收益

在同一真实 pgvector 索引上对每道题额外执行**每变体至多 1 条有界 SQL、≤4 条补充候选、0 次额外向量调用**：

- **R1a**（query 中明确 ASCII 编号/《》标题 → SQL LIKE）：冻结题集中只有 Q06 含 `REQ-7741`，
  而该 chunk 本就向量排名第 1，补充无增量。其余问题无可抽取词元，零成本零变化。
- **R1b**（query 中文二元组在项目分块上的不同命中数排序，阈值 ≥2）：**成功把 Q02 目标 chunk
  补进候选池**（Q02 从 `RETRIEVAL_MISS` 变为池内成员，携带真实向量相似度 0.3643/全量排名 23），
  但在 QA（5 名额）与 Agent（8 名额）两条路径的最终上下文中**仍被 `SELECTION_MISS:SOURCE_CAP` 丢弃**——
  其相似度排在池内末段，任何保序装配都无法让它赢得名额。

**结论：候选池层面的召回改善不能转化为最终证据保留，与 P4-RAG-QUALITY-02 的 B=800/120 结论同构。
R1 分支按设计 §3 停止，不入生产。** Q02 属于分块/语义排序问题，在"不改分块、不换模型、不上重排"的
约束下无可证实净收益的解法；改分块已被 P4 真实对照否决（尾部条件改善但最终上下文仍丢失）。

## 3. D2 上下文选择实验：S1 否决、S2 准入、Agent 路径保持现状

四变体同候选、同名额、同 8000 预算；冻结回放 = network-recovery-03 的 14 行真实历史候选（23 项事实）：

| 变体 | 定义 | 冻结回放 | 真实当前 SHA | 裁决 |
| --- | --- | --- | --- | --- |
| A（原生产） | 候选顺序装配 5 名额 | 21/23 | 25/27 | 基线 |
| S1 | 两阶段跨文档代表优先（`buildDiverse`，Agent 同款选择器） | 20/23，**丢失 Q05 v1.9 关键事实** | 24/27，同丢 v1.9 | **否决**：代表优先挤掉同文档第二关键事实，违反零关键事实回归门槛 |
| **S2（准入）** | 候选顺序 + 每文档名额 cap=2（两遍填充、全量重排保回填；只用 documentId 身份信号，非 D/E 字面家族） | **22/23，零回归，救回 Q03 上线门禁** | **26/27，零回归，Q03 三阶段证据齐全** | **入生产**：`KnowledgeContextBuilder.buildBalanced*`，QA 同步/流式两入口切换 |
| S3（对照） | 同 S2 但 cap=3 | 22/23 零回归 | — | 记录对照；cap=2 对实测"单文档名额洪泛"失效模式约束更强，且冻结题集无需同文档第 3 条事实 |

S2 的已知结构性权衡（确定性反例 CE3 记录在案）：单一文档有 ≥3 条必需互补事实且其他文档占据
候选名额时，第 3 条让位给其他文档代表。冻结 16 题中同文档必需事实最多 2 条（Q05 两版本条款、
Q16 两条规则、Q04 两条导出事实），该权衡不触发；作为边界记录写入测试。
非竞争场景（候选数 ≤ 名额）S2 与 A 逐字节恒等（CE8）。

**Agent 路径本轮不改**：真实数据测得 limit=8 时 Q03 上线门禁/回滚触发条件、Q04 导出审计、
Q05 v1.9 共 4 项事实被 stage-1 代表名额挤掉；limit=12 可救回其中 3 项（上线门禁因代表拥挤仍无法保留）。
提高 Agent 默认 limit 会放大每次工具调用的 token 成本，且端到端回答质量需真实 Chat 模型验证
（本轮无授权），故维持现状并记录数据，留待未来授权轮次决策。

## 4. D3 引用契约：分组引用解析的最小机械修复

历史真实回答中 Q03/Q09 使用 `[S1, S2]` 分组引用，而校验器只识别单项 `[S\d+]`，
导致分组内合法引用**不被持久化**。本轮生产改造（`KnowledgeCitationValidator`）：

- 受限分组格式 `\[(S\d+(,\s*S\d+)+)]` 逐成员校验：合法成员计入持久化引用；
  部分非法时仅移除非法成员；全部非法移除整组；单项引用维持历史归一化（`[S01]`→`[S1]`）。
- 新增 9 个确定性用例（全合法/无空格/混合/全非法/重复成员/S0 与越界/畸形括号不误伤/补零归一/身份映射），
  连同既有 8 例共 17 例全绿。
- 边界口径写入 Javadoc：`citation_number_valid`（机械可判）≠ `citation_claim_supported`（人工审查）；
  `insufficientEvidence` 保持狭义结构标记语义，本轮未扩展、未做关键词式语义判断。

## 5. 成本与越界核查（D4 口径）

- S2/R1 均为**检索后纯函数**：0 次额外向量调用、0 条额外 SQL（R1 实验除外且未入生产）、
  候选池/名额/预算（8000 code point）不变；QA 与 Agent 路径查询 embedding 调用数保持各 1 次。
- 指标口径：真实测量值来自本地 Ollama（fingerprint `EmbeddingFingerprints.fingerprint("OLLAMA","qwen3-embedding:0.6b",1024)`），
  一次性 Testcontainers pgvector，语料 sha256 与冻结 manifest 逐字节一致；
  全量排名仅作诊断、从不回填生产候选；QA 与 Agent 分母不混算。
- 权限/隔离：全部测量经生产 `DocumentSearchService`（project/READY/fingerprint/generation 过滤），
  指定文档范围题（Q10/Q11/Q13/Q15/Q16 及 Q12）候选与来源零越界（测试断言）。

## 6. 遗留未解决问题（如实声明）

1. **Q02 续发前提召回**：候选层缺失（全量排名 23），本轮所有受控方案（R1a/R1b、S2、limit 扩大）
   均无法在约束内把该事实送进最终上下文；需要分块或语义排序层的变化，均超出本轮授权与证据边界。
2. **Agent limit=8 的同文档第二事实挤掉**（Q03/Q04/Q05 各 1–2 项）：结构源于 stage-1 代表优先，
   提高 limit 有实测收益（+3 项）但需成本与端到端验证授权，本轮维持现状。
3. **端到端回答质量**：未调用任何外部 Chat 模型（Gemini 24/24 预算已用完，无新授权），
   本轮一切结论限于检索/证据/引用契约层，不声称生成层收益。
