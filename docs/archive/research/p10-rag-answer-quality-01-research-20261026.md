# P10-RAG-ANSWER-QUALITY-01 研究报告：从证据保留到回答可信

> 日期：2026-10-26　基线：`dev@efafbc2`　方法：源码审查 + 冻结题集 + 确定性评分器实验
> 证据：`docs/acceptance-evidence/2026-10-26/p10-rag-answer-quality-01/`

## 1. 研究问题

P9 证明证据保留率 94–96%，但"证据可见"到"回答正确"之间隔着版本辨别、冲突解决、
条件保真、诚实拒答与引用支持五个未被测量的环节。本轮建立可验证的评测工程基础并回答：
哪些错误可机械判定？现有 Prompt 与引用契约把哪些责任推给了模型？

## 2. 源码审查发现

1. **QA 引用契约是强校验+强替换**：`KnowledgeCitationValidator` 对 `[S#]`/分组编号做身份校验，
   无有效引用的实质回答被整体替换为统一拒答文案（invalidOutput）——正确但无引用的回答用户看不到，
   这是被确定性测试固化的既有行为（CONTRACT_FORCED_ABSTENTION）。
2. **Agent 引用与正文零耦合**：来源卡=工具实际读取身份（11 项 PostgreSQL 契约保护），
   正文无编号协议，逐句支持关系无机械绑定——"available-but-uncited"是契约行为而非缺陷。
3. **QA system prompt 缺版本/归属辨别指令**：有引用规则、拒答规则、注入防御；
   没有"识别现行版本/废止条款/组织归属（华东≠华南）"的任何引导。P9 实测冲突条款
   QA 6/7、Agent 7/7 与正确条款同屏，辨别责任 100% 在生成层。
4. **无独立答案存在性判定**：拒答决策=模型判断 + Prompt 指令；系统只在其发生后
   机械验证拒答措辞与证据缺失的一致性。

## 3. 机械边界实验（14 题冻结子集 × 模范/坏回答）

- 枚举范围内**零漏检零误报**：8 个坏变体的 10 项高严重度（版本现行错误、废止当现行、
  地区套用、否定翻转、编造+未拒答、编造引用、无引用强制替换、注入遵从）全部命中；
  14 题模范基线 0 高严重度。
- **实测漏检案例**：未枚举的否定翻转措辞（"允许先组织培训再补签"）不触发机械告警
  ——语义级翻转检测必须人工，这条边界被固化为 limitations 与 rubric 的分工。
- **归因分层的必要性**：AQ09 的"退回发起节点"P9 未进 QA 上下文；评分器将其缺失归因为
  系统证据缺口（MISS_EVIDENCE_GAP），并把"回答包含未进上下文的事实"标为泄漏观察
  （HIT_WITHOUT_CONTEXT_EVIDENCE）——避免把检索缺口记成模型错、也避免把幻觉记成能力。

## 4. 对下一轮（真实生成授权后）的预期风险排序

1. 版本/地区冲突辨别（Prompt 无引导 + 冲突条款同屏率高）——最可能的高严重度来源。
2. 拒答判断（有相关文字≠有答案；H-G07-NONE/INDIRECT 型问题）。
3. 条件保真（"不得/除非/仍需人工确认"的限定词丢失）。
4. 引用语义支持（编号合法易，逐句支持难；Agent 更缺工具）。

## 5. 结论

离线契约层完成并可回归：评分器、Rubric、归因分层、QA/Agent 协议差异全部确定性固化。
真实生成层所有指标保持 `REAL_GENERATION_NOT_EXECUTED`；最小预算（≤34 次请求）已列于设计文档，
未执行任何调用。本轮没有修改任何生产回答算法。
