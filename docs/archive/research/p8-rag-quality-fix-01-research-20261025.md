## F1 有界补读与摘录

策略输入只有原始问题、合法命中的候选与索引配置；事实标签仅用于之后评分。R1 取最先命中的两份文档，在原候选之外按距各文档首命中块的 chunk_no 距离补读，最多四块。R2 在同样两份文档内按章节标题与问题的不同中文二元组交集排序，最多四块。每条路径每变体增加一条参数化 SQL，不使用金标准、固定文档名、题号或诊断全量排名。保留项目、成员、READY、provider/model/dimension/fingerprint/generation，并排除原候选；仅测试侧实现。

R1 在 QA 的四块补读中未触及 Q02；Agent Top20 已有较多相邻块，反而能补到目标。R2 在两条路径都补到目标。但按原选择策略仍因 SOURCE_CAP 丢失。研究臂再给补读首块保留一个来源名额：QA 得到 Q02，Agent 现有 600 字前缀仍丢条件；查询二元组评分的单个连续 600 字局部片段则保留原文 [208,808) 的尾部条件。没有改动 chunk/hash，没有拼接断句；摘录位置及原文在结果中可核验。

准入失败：R2 的 QA 保留名额臂救回 Q02，却丢失 Q03 的上线门禁。普通补读零最终收益。局部摘录只在测试侧装配，未接入真实 Runtime 模型轮；全文否定/数字/版本关系的一般安全性没有得到证明。因此本轮不能宣称 Q02_FIXED，也不增加生产 SQL 或摘录逻辑。

## F3 引用契约

Agent 未定义 QA 的 S 编号语法，把 P8 Q13 的字面 `[S999]` 当作 Agent 已验证引用不成立。真正复现的缺陷在来源投影：子来源移交参数直接进入最终卡片，没有重新核验持久化依据与当前身份，也可能替换持久化摘录。独立 PostgreSQL 初测8项中5项断言失败，其中4项证实未知身份、无读取依据、失效身份、替换摘录缺陷；另1项把失败子运行中的成功读取资料也要求排除，属于过度限制的新测试预期，复核后已改为保留其可用来源身份。之前两次夹具装配错误分别为用户名长度与缺失 fingerprint，单独记录，不当作生产缺陷证据。

最小修复只修改 recorder 的子来源合并：一条有界 SQL 重读本父运行持久化移交的合法来源，匹配 documentId/chunkId 并使用原持久化摘录。移交生产者只收集成功工具读取，但不要求子运行最终成功；这样保留失败研究的合法部分证据，且不冒充结论支持。来源字段、正文、前端、QA 编号规则保持兼容。真实 Chat 生成、语义支持与浏览器界面验收均未执行。长期契约见 [来源契约](../../design/agent-source-citation-contract.md)。

## 工程复核中的修正

收口复核为新增查询补上源表 UUID 主键 ANY 过滤（最多50项），避免仅以 UUID 转文本比较妨碍索引。独立引用测试记录实际 SQL 的 EXPLAIN ANALYZE，并限制每次最终投影新增查询数不超过1、返回行数不超过50。

首轮全量 verify 记录1808项、0断言失败、1执行错误、35跳过：新实验子类未显式声明 Ollama opt-in，普通套件意外执行该研究方法，并复用了已关闭容器对应的数据源。该次记录不是最终源码通过证据；已为子类显式声明与既有真实检索测试相同的门控，重新执行显式启用的真实实验和最终默认 verify。没有放宽事实、权限或普通容器测试阈值；引用契约 PostgreSQL 用例仍是必须实际运行的 CI 硬门槛。

第二次 verify 在执行中主动中止：复核确认候选的“子运行必须最终成功”过滤会误删其先前成功工具读取的资料，故先去掉该额外限制，再对最终源码重新验证。既有冻结事实、E1–E11及生产阈值没有修改；新测试预期的修正与初测原始记录同时保留。
