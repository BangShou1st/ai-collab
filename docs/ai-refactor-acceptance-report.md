## 验收发现的问题与修复

1. Spring Boot 4 的 Jackson 3 HTTP 转换器把领域层 Jackson 2 `JsonNode` 输出成节点属性对象，破坏正文、工具结果和上下文。新增明确的双向 JSON 树桥接模块，加入真实 HTTP 序列化回归。
2. 修订提案未随修订来源运行列出；审批响应又缺少 revision 等字段，使批准缺少所见版本参数。补齐关联查询和响应字段，验证修订后按 revision 2 批准、一次正式写入。
3. 规划失败摘要和提示失真。保留阶段与具体错误码，新增原草稿完整保留的集成回归。后续进一步纠正 HTTP 403 的认证归因，未确认原因的拒绝不再显示为密钥错误。
4. 恢复规划任务局部修复入口，提交当前版本与任务身份锁定条件；有未保存编辑时提示先保存。修复入口不绑定已过期的问题 ID。
5. Agent 新运行清除旧详情并隔离过期异步响应；终态加载当前详情，取消后停止展示分析状态。

## 后续收尾：Agent 展示与 Zen 请求封装

用户复核指出，审批成功截图中模板 Plan 的所有步骤仍显示“待执行”。确实没有模板步骤与实际 invocation 的持久化关联，不能通过运行成功推断模板完成。本轮改为：

- 右侧展示由真实工具事件生成的执行记录，按 invocation 区分成功、失败和中止；同批次部分失败不会全部标成成功。
- 原 Skill 模板明确显示为“参考步骤”，包括无工具关联的报告生成等内容；不再显示“待执行”。没有删除原 Skill 或改变其执行语义。
- 会话侧栏采用当前运行状态，避免仍展示上一次取消；历史回放不再覆盖数据库已知终态或修改原始运行快照。
- 浏览器复验运行 `8e7048a5-07f7-47e9-adb9-2c9350777bda`：整体完成，2 次工具调用中 1 次成功、1 次 `TOOL_EXECUTION_FAILED`，参考步骤保持参考而非成功。新截图与回归用例保留。

重新只读对照 spec-agent 当前实现，发现此前 Zen 模拟测试漏验客户端封装，代码也确实存在差异：缺少 `bash` / `read` 保留工具、`x-opencode-client/request/project` 身份头；会话头直接使用业务 UUID；User-Agent 不完整；连接探测未使用同一流式封装。这些差异已修复，并补充生产适配器本地 HTTP 回归。会话转换为稳定的 `ses_` 客户端 ID，每次请求使用新 `msg_` ID，关联缓存有界。传输保留工具没有业务执行入口，返回其调用或业务名称冲突均拒绝；Custom 模型不附加这些内容。
