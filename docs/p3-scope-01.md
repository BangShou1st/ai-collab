## 1. 决策与授权边界

P3 的目标是缩短高校竞赛团队、软件课程项目用户从“看到待办/资料/AI 结果”到“完成下一步协作”的路径。保留现有模块化单体、Vue SPA、权限和人工确认边界。

本次正式交付的是范围基线、候选需求、优先级建议、验收合同和开发交接。**初始规划时 U 系列均为候选；2026-10-20 用户先批准 U-01（P3-TASK-01），随后明确批准 U-02（P3-TASK-02），两项均已实现。U-03～U-05 仍待批准。** SCOPE-01 原轮次实施两项诊断技术债 T-01/T-02；后续 TASK-01 已实施 U-01，详见 [TASK-01 验收记录](acceptance-evidence/2026-10-20/p3-task-01/README.md)；U-02 详见 [TASK-02 验收记录](acceptance-evidence/2026-10-20/p3-task-02/README.md)。未做用户访谈，频率、转化率和节省时间均未知，不虚构用户研究结论。

本文件是新 P3 的规划入口。旧蓝图中的 P0–P4 是历史交付编号，与本文件的需求优先级 P0/P1/P2 无关。历史验收的后续勘误和最新专项结果优先，不能把旧建议直接搬成新需求。

## 3. 候选需求与推荐排序

评估口径：价值 1–5（越大越高），成本为单开发者含测试/文档的粗估工作日，不是承诺日期；风险低/中/高，验收可行性高/中。优先级 P0 为当前交付或经证实的阻断项，P1 为建议首批用户收益，P2 为后续可选优化。没有证据支持新增业务 P0。

| 推荐顺序 / ID | 用户场景与最小需求 | 类型 / 优先级 / 状态 | 价值 / 成本 / 风险 / 可验收性 |
| --- | --- | --- | --- |
| 0 / T-01、T-02 | 诊断取消必须有证据；传输再次断开时展示正确状态 | 技术债 / P0（本轮有限修复）/ 已实现、自动化通过 | 3 / <1日 / 低 / 高 |
| 1 / U-01 | 成员从工作台看到自己的未完成任务，点击直接到该任务详情，刷新可恢复 | 用户流程 / P1 / **已批准、已实现（P3-TASK-01）** | 5 / 1–2日 / 低 / 高；仅复用任务读 API |
| 2 / U-02 | 收到任务类通知后直接处理对应任务，保留已读行为，失效目标有中性反馈 | 用户流程 / P1 / **已批准、已实现（P3-TASK-02）** | 4 / 1–2日 / 中 / 高；复用 U-01 深链接，自动化与真实 Edge 验收见专项记录 |
| 3 / U-03 | 用户分清“已保存模型配置”“该用途可解析”“能力曾测试通过”，找到正确设置入口 | AI 可用性 / P1 / 待批准 | 4 / 2–4日 / 中 / 中；复用用途路由/探测，禁止默认发真实探测 |
| 4 / U-04 | 管理者看到失败资料后知道错误类别、谁能处理、如何单项重试；成员知道联系管理者 | 易用性 / P2 / 待批准 | 3 / 1–2日 / 低 / 高；现有 retry/reindex 足够，不受 R-1 历史会话阻塞 |
| 5 / U-05 | Owner 确认规划后能识别本计划中未分配项，进入已有看板分配 | 协作效率 / P2 / 待批准 | 3 / 2–3日 / 中 / 高；先核对已有 sourcePlanId 跳转是否已满足 |
| 6 / E-01 | 将仓库外 SSE 故障夹具变为可选、仅本机的可复用脚本，减少后续相关验收准备 | 工程技术债 / P2 / 待批准 | 2 / 1–2日 / 低 / 高；仅在相关改动需复验时做 |
| 7 / E-02 | 修正文档过时迁移范围、测试告警和构建体积；性能问题须先测量再拆包 | 工程技术债 / P2 / 待批准 | 2 / 0.5–2日 / 低至中 / 高；不能为清 warning 扩大重构 |

排序理由：先修已证实的小型诊断错误；U-01 无模型/数据库依赖且堵点可由源码确认；U-02 复用同一路由；U-03 涉及多用途信息契约，需要先明确状态定义，不能顺手宣称“AI 健康监控”；U-04/U-05 是改善既有能力的使用路径，实际需求强度有待用户反馈。成本不相加为强制总工期，任一任务独立可交付、可停止。

产品确认前需要保留的假设：用户经常从工作台进入任务、任务通知比全类型通知跳转更有价值、AI 状态误读会造成实际困扰。实施后可先用合成验收确认路径，再由目标用户反馈决定是否继续；不为验证假设新建埋点平台。

## 7. 两项诊断技术债与验证

- **T-01：已证实并最小修复。** 原 `classifySseDisconnect` 在 localAbort=false 时凭 error.name=AbortError 判 CLIENT_ABORT，与 OBS-02 规则矛盾。测试先改为 UNKNOWN 并复现失败；实现仅修该分支。显式 localAbort=true 仍 CLIENT_ABORT，DOMException 同样无证据则 UNKNOWN。
- **T-02：已证实并最小修复。** 原 beginEpisode 在活跃区间提前返回，导致 TRANSPORT_RECONNECTED 后再次错误/提前结束仍显示传输重连。新增参数化测试两分支先失败；实现仅在活跃区间退回 RECONNECTING，保留首次类别、累计次数、区间内不重复 disconnect；重新 opened 后 aligned 才 recovered。

两项仅修改 `agent-sse-diagnostics.ts` 和对应测试；不变更 Runtime、SSE 游标/退避、后端/数据库/工具/模型策略。新增边界为自动化验证，未冒充本轮真实浏览器故障注入。详细执行记录见 [本轮验收记录](acceptance-evidence/2026-10-20/p3-scope-01/README.md)。
