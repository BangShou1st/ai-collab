## 3. 五项必须完成的修复

### F1：显式绑定暂停运行的输入不能退化为普通新任务

入口：`AgentRunService.submit`，当前 `pausedRunId` 检查及 `!latest.status().terminal()` 分流。

原运行暂停→恢复→快速完成后，迟到/重复的“继续”带着原 pausedRunId 到达，目前会跳过控制分流并 createRun，生成第二个目标为“继续”的任务。这已经在真实 PG 复现。

修法原则：只要请求显式绑定了暂停运行，就始终在该运行的控制作用域中处理，不能掉入普通 createRun。原运行已完成/取消时返回其真实状态或明确业务提示；不存在/不属于当前会话/当前 run 已切换时按已有授权与业务错误拒绝。运行中重复明确续跑仍幂等，暂停意图未确认时仍不提前恢复。

不要全局禁止终态后发送消息：**未绑定控制作用域的真正新请求仍按现有业务提交**。如果选择返回终态运行，前端应展示真实状态，不把它当成恢复成功后继续调度。采用符合现有返回契约的最小方式。

正式回归至少覆盖：首次续跑、重复续跑、绑定原 run 的迟到终态输入、取消后输入、绑定失效，以及普通终态后真正新任务可以发送。断言 run 数量、runId、USER 消息及原目标/工作状态，不能仅检查异常类型。

### F2：输入续跑的异步响应必须保护页面作用域

入口：`use-agent-workspace.ts` 的 `send` 及其后续消息加载。不要只修已有 `pauseActiveRun`。

A 会话发送“继续”→请求挂起→切到 B→输入 B 的新问题→A 响应到达，目前会清空 B 草稿并重启当前订阅。

发送时捕获 projectId、sessionId、当前 runId、恢复代次，依现有方式判断响应是否仍属于当前页面。过期成功/失败不能改新页面状态、清草稿、换订阅或显示旧请求错误；继续调用的 loadMessages 等异步结果也要绑定作用域。包含切换后又切回、组件卸载及当前运行已换的情况。

保护所有响应副作用，不只保护一次 timeline.run.id 比较。保持 pending 门闩和异常释放正确，避免旧请求释放不属于它的操作状态；同一页面发送后新增的草稿也不要被旧输入的成功响应误清空。用局部作用域检查解决，不创建通用请求管理框架。

正式回归使用延迟 Promise：切会话保留 B 草稿与订阅、切项目/恢复代次变化不串状态、延迟消息加载不覆盖新会话。关键断言是最终页面和实际订阅/消息行为。

改为正确调用或一个明确键盘处理函数。普通发送、PAUSED 输入续跑调用 send；WAITING_FOR_USER_INPUT 调用现有澄清入口。点击按钮行为和防重复发送保持一致。

### F4：同一运行的旧控制回包不能覆盖较新事件

入口：`pauseActiveRun` 中无条件覆盖 timeline.run 的路径；同时复核输入续跑应用响应的同类边界。

项目、会话、run 都没变化时，暂停请求的旧 RUNNING 快照仍可能晚于 RUN_SUCCEEDED 事件到达。目前会把已完成页退回正在暂停，事件流结束后可能不再纠正。

复用现有 lastEventSequence/运行详情或必要的权威刷新，区分“作用域正确”和“快照仍然最新”。较旧响应不能覆盖已应用的较新状态、暂停标记或订阅决定；同样不能仅用“终态永不回退”掩盖 PAUSED/QUEUED/RUNNING 之间的顺序问题。若某返回结构没有序号，选一个局部、可解释的核对方式，不新增全局状态同步平台，不无限轮询。

正式回归用受控事件与延迟 API 响应：RUN_PAUSE_REQUESTED→RUN_SUCCEEDED 后旧暂停回包到达仍显示完成；暂停/恢复之间的旧快照不能恢复错误标记；正常最新控制响应仍生效。保留已有工具展开、时间线和回答去重语义。

### F5：摘要首次请求和重压缩补齐暂停准入

入口：`AgentContextSummarizer`、Recorder 的 `beginSummaryAttempt` / `beginSummaryRecompressAttempt`，以及必要的协调器收口。

主请求 beginModelCall 的运行行锁准入正确，但摘要走独立身份路径。首次摘要在途时 requestPause 提交，返回超长结果后当前代码仍会新发重压缩请求；PG 探针实际计数为 2，期望为 1。

摘要的每次新出站请求在现有身份创建事务内，复用同一运行的暂停/状态/租约准入检查，与暂停意图写入确定提交顺序。不要只在流程开头补一次无锁检查，也不要复用一个 callId 合并两次实际请求的身份。短事务准入，锁不跨网络等待。

暂停意图先提交则不创建该请求身份、不发模型请求；请求先准入则允许这一阶段完成并处理真实结果。首次摘要已发生的结果按原规则保存/处理，若不合格且不能重压缩则沿用原有效摘要，不虚报新覆盖。暂停拒绝是控制结果，不能被辅助摘要的通用 catch 误当失败消耗重试或导致主请求继续出站；后续由现有安全边界确认 PAUSED。

保持现有摘要算法、覆盖与 CAS 规则、独立记账和 R1/R2 行为。只保证已发生请求沿原路径处理一次，不扩展精确计费。

正式回归使用真实 PG + 安全替身模型：暂停先于首次摘要准入时零请求；首次在途暂停且返回不合格输出时只有首次请求、无重压缩身份；首次正常在途结果仍按原语义保存；无暂停时合法重压缩仍可执行；过期 claim 不能准入。另验证最终经 Worker/协调器收口为 PAUSED，主请求未被辅助 catch 意外继续执行。
