## 已确定的修复点

修订模型返回了合法的 JSON 数值 `"estimateHours": 3`。工具 Schema 声明：

```json
{"type":["number","null"],"minimum":0.5,"maximum":80}
```

实际校验错误为：`.estimateHours类型期望 ["number","null"]，实际为 integer`。一次参数纠正后模型仍返回合法整数 3，于是错误消耗纠正预算并终止运行。

JSON Schema 的 number 包括整数和小数；integer 依据是否具有小数部分判断，不能只看序列化时有没有小数点。[官方数值类型说明](https://json-schema.org/understanding-json-schema/reference/numeric)。

检查 `ai-collab-backend/src/main/java/com/shitulelv/aicollab/agent/domain/tool/ToolArgumentValidator.java`，修正通用数值类型匹配，确保单类型和类型数组采用一致规则。不要要求模型输出 3.0，不要对太空兔加模型名特判，不要删除工时范围或其他参数校验。

先用真实失败载荷建立可失败的回归，再修正：

- `number` 与 `[number,null]` 接受整数 3 和小数 3.5；nullable 接受 null。
- 字符串 "3"、布尔值、对象不能冒充数值。
- 0 与 81 仍不满足该工时范围；边界值按 Schema 正确处理。
- integer 与 nullable integer 的数值语义保持一致，不能为了修复 number 而接受有小数部分的数值。
- 使用实际任务提案 Schema 验证模型失败样本，覆盖嵌套字段/类型数组。
- 通过真实工具执行器补一项行为回归，确认合法整数不会消耗参数纠正预算；无效参数仍不能执行。

不在本轮无必要地替换整个 Schema 框架。保留所有权限、审批和业务校验边界。

## 真实复验顺序与通过标准

1. 启动受限副本和现有真实验收宿主，使用副本已有加密配置，把验收模型显式设为 space-bunny-free。不得输出密钥、借用其他项目凭据或改正式配置。
2. 查看原 PENDING 提案与正式任务，确认失败未更改原提案、未产生写入。原提案仍有效时优先复验同一提案；过期则新建有唯一验收标题的合成场景，保留旧失败证据。
3. 用正常业务语言要求修订同一待审批提案：标题改为指定新标题、工时改为 3，HIGH 和负责人保持。不给用户增加字段路径、JSON 格式或浮点写法要求。
4. 核对提案 ID 保持不变、revision 增加，标题/工时符合要求，其余不应改变的字段保持；审批前正式任务数为 0。若模型未落实约束，记录真实失败，不用直接改库补成成功。
5. 用旧 revision 审批应返回版本冲突并保持无正式任务；用当前 revision 正常审批后恰有一项正式任务，字段与已确认提案一致。
6. 使用同一幂等键重复批准，返回同一业务结果，不新增任务；验证读取与刷新后结果仍一致。
7. 验收请求“只查询当前任务标题、状态和负责人”，核对自然语言及事实表与业务记录一致，不产生额外提案或写入。
8. 补真实浏览器证据或明确本轮仅为 API 级验收，不用 API 结果冒充浏览器通过。遇到缺陷优先本地复现并修复，再进行有界真实复验。

如再次遇到 429/403，记录实际 HTTP 分类和安全错误元数据，停止本轮生成请求；不要预判限流，也不要反复切模型试额度。协议错误需保留足够的安全诊断（错误类别、字段路径、结束原因、阶段/调用 ID），不能只剩 AI_PROVIDER_INVALID_RESPONSE。
