## 四、实施范围

### M1：统一组件装配与必需依赖

核对协调器内部 new 组装器/工具执行器/摘要器、摘要器同时 @Component、工具执行器 commonPool 默认值与 scheduler/limiter 后置赋值，以及 RoutingAgentModelExecutor 配置存储后置注入。

通过现有 AgentRuntimeConfiguration 或同等明确的生产装配入口，让协调器接收这三个已有协作者，使用容器中的同一摘要器；工具调度及配置存储在构造时明确。先检查真实依赖图和潜在循环，再选择最小装配调整，避免引入 @Lazy 或可变 setter 掩盖新循环。

单测显式提供受控依赖或执行器。不要用生产必需依赖为 null 的兼容分支迁就测试，也不要机械删除真正有产品用途的可选逻辑或历史恢复路径。普通纯函数辅助类不要求全部成为 Spring Bean，不新增装配插件系统。

### M2：抽取工具结果投影

从 AgentModelMessageComposer 抽出具体的 AgentToolOutputProjector，承接列表、规划、正文与通用 JSON 结果投影。输入为工具输出和容量，输出为模型可见结果；不访问数据库、不读取配置、不决定下一步动作。

资料过期判定留在原查询边界。组装器继续负责内容挑选、状态/提示词组合和原生工具消息配对。优先移动现有算法和常量，保持输出语义；不要顺带调整投影阈值、消息顺序、分页算法或摘要触发。

复用 ListPageContract 和既有分页串联回归。移转纯投影测试到职责所属组件；不要保留两套算法，也不要增加通用投影策略体系。只在真实消费者需要时保留简短兼容委托。

### M3：清理无消费者的旧入口

重新核对全仓、Bean 名称/动态查找与调用，确认 AgentPromptFactory 没有生产消费者后，删除其实现、注册及仅验证这套旧实现的测试。核对 RoutingAgentModelExecutor.isNativeToolError 等直接相关的无调用私有方法，可一并清理。

保留真实 Legacy/CHAT-only 能力与旧 source_mode 缺失记录的必要兼容。不要根据“旧代码”名称批量删除执行路径；不通过删除有效行为测试、放宽断言或扩大 skip 让重构变绿。

### M4：修正目录边界并写维护约定

AgentLoopGuard、AgentConvergencePolicy 属于运行控制，当前 domain 代码依赖 application 的 RunView/StepView。将这两个策略归入 application/runtime，并更新引用与对应测试归属。不要为了形式分层复制相同字段的 DTO、增加映射器或全面搬目录。

在一个维护文档中明确：api 负责 HTTP/SSE 转换；application 负责用例；application/runtime 负责本轮准备、上下文与推进；domain 保持业务契约且不反向导入 application/api/infrastructure；infrastructure 负责 SQL/外部协议与业务工具适配。保持当前应用层使用具体仓库的务实结构，本轮不强行补一整套 repository port。

文档用简短调用图说明“请求准备 → 消息组装/投影 → 模型调用 → 工具或最终结果 → 原子持久化”，注明摘要、配置和调度各自入口及事务边界。可以在 `docs/agent-runtime-maintenance.md` 同时记录本轮结果，避免拆成多份重复说明。

不要为了行数拆散 AgentRunEventRecorder 的事务，不改 AgentWorkingState 的约束规则，也不创建前端全局状态副本。
