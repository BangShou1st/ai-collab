## 第二组：修资料可读完整性，并验真实回答质量

### 已确认的问题

1. `list_tasks` 默认一页 20 条、最多 50 条；composer 超限时数组只留前三条，却保留原 `returned=20` 和第 20 条的 `nextCursor`。现有函数探针确实得到“可见 3 条，续页从第 21 条开始”。按这个游标续读会遗漏第 4–20 条。
2. `list_milestones` 只有 limit，最多 50 条，没有续页入口，无法通过该工具读完更多里程碑。
3. 结果还经过持久化前 sanitizer 的体积缩减、持久化后 composer 的投影；只改一层可能继续漏读。`items` 与 `taskFacts` 有重复事实，也会浪费输入。

### 实现要求

- 为任务、里程碑保留简单、有稳定排序的分页契约，模型可见记录、条数、覆盖范围和下一段位置必须一致。不能提供跨过未展示记录的游标。
- 优先减少重复字段、控制单页体积，必要时采用针对列表的明确投影/续读契约。选最小的可验证方案，不造泛化检索框架或查询 DSL。
- 保留脱敏、权限、结果体积上限、原调用身份和必要输入保护。模型视图投影与服务端原始结果区分清楚，不改历史原始结果来伪造“已读全”。sanitizer 若已裁掉内容，必须仍有可用的原范围续读方式。
- 检查工具 schema、实现、提示说明是否同步。避免指令互相要求“第一轮全部调用”和“最少必要调用”。收敛直接影响这三类问题的矛盾，不重写全部 Skill。
- 回答按问题组织：结论、必要事实、原因、可执行建议、未核查范围。没有日期/依赖/文档证据时明确不知道，不能仅凭 TODO 判断延期。不得用最低字数、额外裁判模型或长模板假装质量提升。
- 因额度停止而资料未读全时如实反馈部分结论及剩余范围，不能输出“全部核对完成”。不在本轮实现跨运行断点续接。

### 必要回归与质量验收

- 以可追溯的多页数据验证完整 ID 集合无遗漏、无重复，覆盖超过 50 条里程碑、长任务描述、最新/历史投影阈值（当前 6000/1500 字符），以及 sanitizer 的缩减边界。不是只断言存在 `projection` 标记。
- 有限测试应真实串联“工具分页 → 清洗 → 模型可见视图 → 续页”，防止测试只镜像实现。
- 隔离数据中安排已逾期任务、正常在途任务、关联里程碑、缺失依据等，覆盖三类问题：项目概览；按指定范围列全部；检查本周任务是否影响交付。
- 假模型用于确定性工具协议、事件和界面验收；用户截图里的 acceptance-b 短回答是 `ScriptedAcceptanceModel` 固定文本，不能当成真实质量证据。
- 若现有已授权真实配置可用，用当前配置对上述三类问题做小规模真实质量验收，每题一次，失败只做与本轮修复直接相关的定位。使用隔离项目，不导出凭据，不扩大为 24 轮。如果没有可用真实配置，明确保留该项未验收，不能以假模型结果代替。
