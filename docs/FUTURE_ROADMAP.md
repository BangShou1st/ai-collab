# AI Collab 后续路线图

当前实现基线见 `feature-matrix.md`。本路线图只描述未来优先级，不代表已完成，也不应被模型当成单次任务全部实现。

## P0：稳定基线（已完成）

- Phase 09 Dashboard 与 Audit 前后端闭环；
- 现有测试、迁移预期和审计中文摘要修复；
- 项目 OWNER 编辑、归档、删除入口；
- 中文界面与内部枚举显示收口；
- 真实只读冒烟脚本；
- 功能矩阵、OpenAPI 和开发文档重构。

后续每个阶段都必须保持 P0 的全量测试、构建和冒烟通过。

## P1：补齐第一版基础业务

按小任务依次完成：

1. 项目类型：竞赛项目、课程设计、软件实训、其他；
2. 项目四态：准备中、进行中、已完成、已归档，并设计合法转换；
3. 成员主动退出项目；
4. 所有权转移；
5. 管理员创建和停用测试账号；
6. 里程碑开始日期与截止日期语义；
7. OpenAPI 自动契约校验。

所有权转移必须先设计数据库并发语义，不能通过直接降级 OWNER 实现。项目状态/类型需要新迁移、后端 DTO、前端中文入口和历史数据回填。

## P2：知识库体验

1. 问答流式输出和可取消请求；
2. 回答有用/无用反馈；
3. 引用定位到 PDF 页码或 DOCX/Markdown 章节；
4. 文档版本与重新索引；
5. Embedding 模型切换后的批量重建索引；
6. 检索质量评测集和离线指标。

流式输出优先使用 SSE，仍需保存最终完整消息和实际引用；断流不能留下“已成功”假记录。

## P3：项目协作增强

1. 站内通知、任务分配和截止提醒；
2. 依赖完成、文档处理和规划完成提醒；
3. 甘特图、依赖图、日历和成员负载；
4. 任务批量操作和看板拖拽排序；
5. AI 周报和延期风险解释；
6. 规划与正式任务变更对比。

先实现可验证的数据库统计，再让模型解释；不能把模型估计当成项目完成率事实。

## P4：项目协作 Agent

按 `development/agent-design.md` 分阶段：

1. 持久化运行状态机、预算和只读工具；
2. 带来源的项目问答、进度检查和周报草案；
3. 前端审批式任务/里程碑写工具；
4. 定时运行与通知；
5. 评估模板、多 Agent 和更复杂工具。

第一阶段禁止业务写入。第二阶段也只注册窄工具，不允许任意 SQL、HTTP、项目删除、成员/角色、文档删除、密钥配置或自动确认 AI 规划。

## P5：模型与运维

- 管理员模型配置界面与加密密钥托管；
- 供应商健康、额度和成本观测；
- 明确策略下的手动/自动故障切换；
- Prompt/Schema 版本管理和评测；
- 对象存储与数据库备份恢复；
- CI 契约、依赖和安全扫描；
- 前端代码分包和性能预算。

模型自动切换必须确认 Embedding 兼容性；不得因为免费额度变化混用不同向量空间。

## 任务选择规则

每次从同一优先级中选择一个可闭环任务，使用 `development/claude-mimo-task-template.md` 写明范围、权限、数据迁移、接口、中文界面和验证。完成后更新功能矩阵；路线图条目只有在真实入口、权限和验证全部存在时才可移到 P0。
