# 05｜RRF 与融合策略——依据不足，不修改（决策记录）

> 日期：2026-11-08 ｜ 阶段裁决：**NOT_EXECUTED（有据不改动）**

## 1. 决策依据

任务规则明确："如果阶段 3 和阶段 4 已证明路由策略能够有效避免无收益的 Lexical 调用，
就先保持原有融合算法。"

本轮证据链：
1. 阶段 3 已落地——FAST 查询不再执行词法 SQL（Dense-only + 有界回退），HYBRID/STRUCTURED
   （含精确标识符）保留词法通道并输出依据；COMPLEX 走多查询分解。无收益的词法调用已被路由层消除。
2. 阶段 4 已落地——保留词法通道的场景其成本从 3.0s 降至 0.6s 且语义等价（diff=0），
   "词法太慢"不再构成融合层改动的动机。
3. 融合质量的既有证据：公开 Benchmark 显示 Hybrid RRF 在陌生短 passage 语料上劣于 Dense-only
   （0.729 vs 0.809）——但该劣化的主因是词法召回质量（Lexical Recall@10 仅 0.121、独立贡献 0 题），
   而非 RRF 算法本身；在企业长文档语料（P9）上完整管线与 dense 直连同为 52/54 基线。
   Weighted RRF 等调参若以 300 道 DuRetrieval 题为调优集，再拿同批题证明收益即构成任务明令禁止的
   过拟合自证；独立调优集/验证集的划分在当前免费配额与工期下无法可信完成。

## 2. 结论

**保持 ReciprocalRankFusion 原实现不动。** 若未来获得独立于 DuRetrieval 的第二语料评测集，
可按"冻结独立调优集 + 保留验证集"协议重启融合消融（Weighted RRF / Dense 主排名保护 /
精确术语 Lexical 补充），以本报告为基线对照。

## 3. 风险与观察点

- 生产 HYBRID 路径在阶段 4 后词法候选质量不变（diff=0）、速度 6 倍——RRF 输入分布未变。
- 若后续 Embedding A/B（配额恢复后）显示 Gemini 向量空间下词法贡献率变化，融合权重问题应
  在那时以新证据重启，而非在本轮预设。
