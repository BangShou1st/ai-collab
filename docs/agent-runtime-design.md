# Java Agent：工具调用与异常恢复设计

日期：2026-10-03。状态：设计，尚未实现。基于当前 Runtime、工具执行器、审批和仓储演进；与 [全局设计](backend-agent-redesign.md) 配套。

## 1. 目标与执行边界

Agent 负责连续任务中的信息收集、澄清、工具选择、提案组织和结果说明。Java Runtime 是唯一循环控制者；现有应用服务负责授权、业务规则、事务和审计。规划仍是独立分阶段流程，Agent 通过工具引用规划草稿和版本，不实现第二套批量确认。

原生工具模式和提示词结构化动作模式分开配置、测试并固定到 Run。原生能力不可用时，第一阶段允许显式选择受限只读模式；沿用已有只读范围。超时、限流或服务错误不能在运行中静默切到另一模式。提示词 JSON 解析与权限执行始终分离；仅能输出 JSON 不等于已验证多轮工具调用能力。

三种业务终点：给出有依据的回答；生成待确认提案/规划草稿；请求必要用户补充。用户等待时释放 Worker 和网络资源，补充信息后沿用目标及相关对象继续。提案生成与正式任务写入分别记录，审批不自动恢复旧 Run。

## 2. 职责分配

| 现有组件 | 目标职责 |
|---|---|
| AgentRuntimeCoordinator | 推进步骤、检查预算/取消、决定继续/等待/结束；不拼提供商报文 |
| AgentContextAssembler / AgentModelMessageComposer | 核验页面对象、组装工作状态与有界历史，保留工具调用/结果配对 |
| RoutingAgentModelExecutor / 模型网关 | 使用固定配置和模式执行单轮，保留结束原因、工具请求、usage 和类型化错误 |
| AgentToolRegistry / 工具策略 | 工具版本、Schema、风险类别、权限与本轮暴露集合的可信来源 |
| AgentToolCallExecutor | 校验、调度、记录单个调用状态、归一结果和取消；不吞掉错误分类 |
| AgentApprovalService / 规划确认服务 | 审批所见版本，事务执行业务变更，幂等返回资源身份 |
| Repository / EventService | 调用记录、租约与提交代次、事务事件、恢复和 SSE 补读 |

继续使用这些边界；只有职责拆分确有必要才新增组件，不为每条规则再包一层服务。

## 3. 工具契约

工具定义需表达名称和版本、用途与适用条件、输入 Schema、输出类型、READ_ONLY/PROPOSAL 类别、权限策略、超时、结果大小上限、幂等及重试条件。是否允许当前用户调用由服务端决定。MCP 的只读资格来自可信注册策略，不能只相信远端描述。

服务端把用户/项目/Run/取消信号注入执行上下文，模型参数不携带可改变执行身份的字段。即使模型返回一个已注册名称，若该工具不在本轮暴露集合，也必须拒绝；不能因没有找到对应 Schema 而跳过校验。

统一结果逻辑字段如下，实施时复用现有 DTO 和存储，按需要兼容扩展：

| 字段 | 语义 |
|---|---|
| invocationId / toolCallId | 服务端稳定调用身份 / 模型协议关联身份，两者不混用 |
| status | SUCCEEDED、FAILED、REJECTED、CANCELED、SKIPPED、UNKNOWN 等明确状态 |
| data | 成功数据；查询空结果也是成功，但不等于有证据 |
| error | 稳定 code、安全 message、retryable、可修正字段及错误路径；不泄露堆栈或凭据 |
| evidence | 来源 ID、项目范围、资源版本、读取时间、裁剪信息 |
| effect | NONE、PROPOSAL_PENDING、COMMITTED 等副作用事实；正式写入仅由审批结果提供 |

成功与失败的载荷应互斥；MCP isError 必须映射为失败，不能根据正文是否“像错误”猜测。处理超长结果时保留来源和错误元数据，明确 truncated；需要后续查询时返回受控资源引用，不让模型把被裁剪结果当完整数据。

## 4. 一轮模型与工具执行

1. 领取 Run，检查有效租约、取消、身份、模式和剩余预算。
2. 组装目标、约束、对象引用、成功观察、有界历史；生成并固定本轮工具目录。
3. 发起一次模型请求。空输出、截断、协议错误和无效动作分别归类；未完整接收的流式工具参数不能执行。
4. 持久化模型轮次及完整调用清单。检查工具数量、callId 唯一性、Schema 和允许范围，再开始任何工具执行。
5. 按依赖与风险调度，执行前再次检查权限、取消和预算。记录每个调用的最终处置与原始 callId 关联。
6. 把工具结果完整回传模型或进入提案/澄清终点。任何恢复都不能形成只有 tool result 却没有对应 assistant tool call 的历史。
7. 用实际结果核对完成状态，提交步骤、Run 状态与事件，事务提交后推送 SSE。

callId 缺失、重复等导致协议关联无法确定时，整轮调用清单不执行，允许一次协议修正。能够独立定位到单个调用的参数错误，可返回该调用的拒绝结果，其他互不依赖调用照常按策略处理。超出整轮调用数量预算时，在执行前拒绝该批并要求拆分，不能先执行一半再发现预算不足。

## 5. 批量工具调用与并发

- 无依赖的只读调用可以并发。默认以现有 RuntimeLimits 为基础，但真正落实全局、用户和 Run 的并发限制；使用生命周期受应用管理的执行器与有界调度，避免每个调用创建执行器。
- 依赖前一结果的调用放到下一轮；禁止模型在同一批内使用尚未产生的资源 ID。返回依赖未满足的观察，不能猜值执行。
- 提案创建/修订串行执行。第一阶段单批只允许一个提案操作，额外提案调用在执行前标记 REJECTED 并说明需要拆分；先完成允许的独立只读调用，再生成提案。所有调用都有结果，生成首个提案后不能静默丢弃剩余调用。
- 若一个提案成功、另一个查询失败，Run 的结果明确为“提案已生成，部分查询未完成”；不能声称全部需求已处理。UI 从结构化 outcome 呈现部分完成，不一定立即新增数据库状态枚举。
- 工具执行开始事件在实际调度执行时发出。校验拒绝是 REJECTED 事件，不能先显示已开始执行再拒绝。

本地幂等身份至少包含 Run、模型轮次和调用序号，并存工具版本及规范化参数摘要。模型 callId 用于协议配对，不能单独承担数据库幂等。相同调用身份、相同参数重放已知结果；同身份不同参数冲突。新一轮合法重查仍是新调用，不能仅以参数相同永久复用旧事实。

## 6. 超时、取消与结果未知

每个调用从实际发起时确定绝对截止时间；排队计入 Run 总时限，工具执行时限单独记录。内部和 MCP 工具使用各自配置的超时，不能统一硬编码为 10 秒，也不能从逐个 future.get 的时刻重新获得完整时限。

取消同时作用于未执行队列、模型请求和工具传输。Future 取消仅代表调度层发出取消，不保证底层网络已经停止；HTTP 调用须有超时或取消句柄。无句柄的遗留请求使用截止时间保护，并通过租约/代次拒绝迟到提交。

数据库提案或审批提交结果不确定时，先按稳定调用/幂等身份查询。确认未提交才重试；已提交则返回真实结果。无法判定时保留 UNKNOWN 并等待核对，不声称失败后直接重做。当前外部工具维持只读，未来外部写入需要独立设计幂等与补偿。

Run 取消停止后续执行，已经提交的正式任务不会自动撤销。已生成待确认提案允许按正式入口撤回/拒绝；取消发生在批次中间时，保存已完成结果，其他调用明确标记未执行或已取消。

## 7. 异常决策表

| 情况 | Runtime 处理 | 用户/模型获得的信息 |
|---|---|---|
| 模型 429 | 依据 Retry-After 与剩余时限有界退避；无预算则可恢复失败 | 服务限流，已完成步骤保留；不切换工具模式 |
| 模型 401/403 | 停止该模型调用，不自动换他人配置 | 当前配置认证失败或无访问权 |
| 模型超时/5xx | 重试由单一层控制并计入总预算，耗尽后结束 | 调用未完成；区分重试等待与最终失败 |
| 明确不支持某参数/能力 | 标记配置能力问题，要求显式调整模式 | 具体用途能力不满足；不解释为通用服务故障 |
| 模型空回复/格式错误 | 一次有界协议修正；仍失败则停止 | 输出无法解析，不生成虚假成功结果 |
| 输出截断 | 不执行不完整调用；保留之前已完成的步骤 | 输出预算不足/输出被截断 |
| 工具不存在或未暴露 | 无执行；返回允许范围内的纠正提示 | TOOL_NOT_FOUND / TOOL_NOT_ALLOWED |
| 参数错误 | 返回字段路径与约束，允许有限纠正 | TOOL_ARGUMENT_INVALID，不隐藏为通用异常 |
| 资源不存在、版本冲突 | 根据权限允许范围重新查询或请求用户澄清 | 对象已变化或无法定位；不自动覆盖 |
| 权限撤销 | 立即停止相关访问；过滤失去权限的旧观察 | 权限不足，不让模型重试绕过 |
| 只读工具超时/服务暂不可用 | 按工具策略有界重试；可选信息允许部分完成 | 标明缺失信息，不把失败归纳为事实 |
| MCP isError=true | 记录类型化失败观察 | 返回安全错误说明，可重试性由宿主策略决定 |
| 查询成功但无结果 | 成功空结果；必要时澄清或说明无证据 | 不能声称找到信息，也不作为系统异常重试 |
| 未预期代码异常 | 当前调用失败，安全错误 + traceId，保留堆栈在受控日志 | 不直接把异常内容发给模型或用户 |
| 重复调用且无进展 | 检查是否相同观察/相同失败；停止无效循环 | 已完成部分和未完成原因，必要时询问缺口 |
| 取消/预算耗尽 | 不再启动新动作，持久化准确状态 | 已执行、待确认、未执行分别展示 |

retryable 是“符合条件时允许重试”，不是“必然自动重试”。HTTP、适配器、工具与 Runtime 不能各自独立叠加重试。传输重试、参数纠正、模型格式修复分别计数并共用总时限；写入重试额外满足幂等与结果核对。

## 8. 澄清、上下文与结束条件

用类型化的用户输入动作表示澄清，携带问题、缺失项和目标引用；第一阶段可作为受控交互工具接入现有 WAITING_FOR_USER_INPUT。过渡期兼容旧 [QUESTIONS] 标记，但不再把它作为唯一入口。它是交互动作，不是审批，也不会授予额外权限。

用户补充“换负责人”“再加验收标准”更新当前工作状态和提案版本；用户明确取消、切换目标时记录变化。等待期间资源或权限可能变化，继续前重验。摘要只用于压缩，不能覆盖已核验身份或最新数据。

结束时依据可观察结果：回答有引用/来源范围；变更请求有提案或正式资源身份；澄清有具体缺口；部分失败有明确未完成项。缺少成功执行记录时，不允许展示“已创建/已修改”的操作成功卡片；生成式正文也应由结果约束并进行针对性评测。不能以模型仅输出了自然语言就认定用户操作目标完成。

## 9. 恢复、观测和前端

状态、工具结果与对应持久化事件在相应短事务中一致提交，SSE 提交后发布。事件使用游标去重补读；断线不等于取消，也不触发重新调用模型。租约接管后按已保存的轮次与调用清单恢复，已提交提案/写入先查结果，过期 Worker 不能覆盖新状态。

可观测字段：runId、turnId、invocationId、实际模型/模式、工具版本、尝试次数、排队与执行耗时、错误类别、结果大小、预算、提案修订、完成范围。日志不含凭据；调用结果和历史文本按权限、大小及保留期管理。

前端展示排队、调用模型、执行工具、等待输入、待确认提案、部分完成、失败和取消等用户可理解的状态。工具参数使用脱敏摘要，来源可定位。展示模型正文增量和真实工具事件，不包装为内部思考过程。

## 10. 实施包与验收

| 实施包 | 改动 | 必测行为 |
|---|---|---|
| A 结果与协议 | 类型化工具结果、MCP 错误传播、本轮目录校验、callId 完整性 | 未暴露工具拒绝；缺失/重复 callId 不执行；失败不记成事实 |
| B 调度与异常 | 托管执行器、绝对截止时间、批次处置、分类重试 | 慢工具并发、超时无累加放宽、部分失败、429/401/5xx、提案后续调用无丢失 |
| C 连续任务与澄清 | 工作状态、交互动作、观察失效、提案修订 | 补充不丢目标；多对象澄清；权限变化后历史不能泄露 |
| D 审批与恢复 | 审批绑定版本、调用幂等、租约隔离、取消与补读 | 重复提交、旧页面审批、提交后断线、Worker 接管、取消与提交竞争 |
| E 真实模型验收 | 代表性模型跑同一协作任务集 | 工具选择、参数正确性、澄清次数、完成率、无进展终止、耗时和失败可解释性 |

关键场景：查两份文档后生成一个提案；一个查询失败但其他有结果；提案前后用户修改负责人；模型请求不存在工具；MCP HTTP 成功但 isError=true；生成多个提案请求；取消后返回迟到结果；审批已提交但响应丢失；服务恢复后不会重复创建任务。

测试按行为补充到现有用例，不为每个内部方法编写镜像测试。外部模型与 MCP 互通需真实验证；模拟通过不声称提供商兼容已完成。
