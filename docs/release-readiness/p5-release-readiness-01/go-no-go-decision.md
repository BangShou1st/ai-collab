# go-no-go-decision.md — 最终发布裁决

**裁决：`RELEASE_CONDITIONAL_GO`** —— 允许以限定范围进入发布候选（RC）阶段；下列条件全部满足后转为 RELEASE_READY_GO，任一条件无法在计划窗口内完成或出现新 P0/P1 产品缺陷则自动转为 RELEASE_NOT_READY。

## 一、裁决依据

**支持 GO 的事实**：

1. **无 P0，无产品类 P1**。四项 P1 全部是部署/运维准备缺口（备份恢复、可观测性、发布流水线、TLS/Cookie 基线），无一是产品功能、安全机制或数据一致性缺陷。
2. **核心业务闭环 6.5/7 有真实端到端证据**（business-e2e-matrix.md）：项目管理、知识库、Agent 只读、Agent 受控写入、失败恢复、模型接入全部 REAL；AI 规划能力链路与落库 REAL（页面编辑链路 OFFLINE，已列 S2 补验）。
3. **安全门禁通过**：默认拒绝路由、全量 ProjectAccessGuard、审批三因子（nonce/revision/Idempotency-Key）、AES-256-GCM 密钥零回显、SSRF 全拒出站策略、Agent 永久禁止工具集与预算控制、跨用户 10/10 负面测试。
4. **数据库迁移纪律良好**：V1–V66 无跳号、约束设计成熟、本地 66/66 success、历史唯一违例（V5）已闭环。
5. **CI 达到质量门禁且覆盖目标提交**：run 40062189574 在当前 HEAD `15f4905` 上 success；近 8 次 dev run 全绿；CI 有防 Testcontainers 静默跳过断言。
6. **失败可区分、可恢复**：Agent 取消/暂停/恢复/重试均经真实浏览器验证且幂等；Provider 失败分类完整并前端可见。

**不支持 RELEASE_READY_GO 的事实**：

- 备份/恢复 DOCUMENTED_NOT_DRILLED——「数据升级与恢复具备必要证据」这一 RELEASE_READY_GO 硬条件不满足。
- 可观测性仅 local profile 存在、无发布流水线/runbook——「运维和回滚条件明确」不满足。
- compose 硬编码 REFRESH_COOKIE_SECURE=false——发布所需外部条件（TLS 基线）未确认。

**不是 NO-GO 的原因**：上述缺口均为有限工作量（S1 约 4 项、脚本+配置+文档为主）可补齐的外部条件，不影响目标版本核心用户流程；未发现核心用户流程无法完成、数据丢失/重复、权限缺失、无法启动等 RELEASE_NOT_READY 特征。

## 二、允许的发布范围（CONDITIONAL 边界）

- **包含**：用户与身份、项目协作核心（项目/成员/任务/里程碑/看板）、文档知识库、AI 模型接入（Gemini/Kilo/自定义）、AI 规划、Agent 全生命周期、操作日志/仪表盘。
- **标注实验特性**（须在发布说明声明）：MCP 集成（IMPLEMENTED_OFFLINE_ONLY，无真实连接验收）。
- **低置信度区域**（须在发布说明声明）：work 可视化域（甘特/依赖图/日历/负载/周报/风险/对比）与通知中心——有实现无验收证据（R-06），S2 冒烟后升级。
- **上游依赖声明**：Zen Free 可用性取决于上游限流；免费 Kilo 模型可能被上游下线（已有换模型处置流程）。

## 三、必须满足的条件（转 GO 的门槛，全部来自 risk-register P1）

| 条件 | 风险 | 验证 |
| --- | --- | --- |
| 备份脚本 + 隔离环境真实恢复演练 | R-01 | 演练报告（DB/MinIO/密钥三项核对） |
| 生产可观测性基线 | R-02 | 生产 profile 下 health/metrics 可达 + 日志滚动 |
| 发布 runbook + 可追溯镜像 | R-03 | digest 记录 + 步骤文档 |
| TLS/Cookie 安全基线 | R-04 | compose 变量化 + 生产 secure=true 验证 |

风险接受负责人：**须由人明确指定**（本任务不指定）。追加验证：S2 清单（MCP 决策、可视化冒烟、规划页面复核、Agent UX 两项、配置文档）。

## 四、自动转 NO-GO 条件

1. S1 任一条件无法在计划窗口内完成。
2. 出现新的 P0/P1 产品缺陷。
3. S2 中发现核心闭环（1/2/4/5）在真实环境回归失败。
4. 目标部署环境无法满足出网白名单要求且无替代方案。

## 五、任务书第二十节 20 问回答

1. **是否达到功能完成标准？** 是——核心四域全部实现且真实验收；可视化域/MCP 为验收缺口而非功能缺失。
2. **主要模块是否都有可靠验收证据？** 核心模块是（五份 2026-10-24 P4 + P2/P3 历史）；例外：可视化域、通知中心（无证据，R-06）、MCP（仅离线，R-05）。
3. **哪些跨模块闭环已真实通过？** 1 项目管理、2 知识库、4 Agent 只读、5 Agent 受控写入、6 失败恢复（主体）、7 模型接入。
4. **哪些闭环仍只有离线测试？** 闭环 3 的规划页面编辑/版本链路（能力与落库已 REAL）；闭环 6 的 QUEUED 暂停窗口（INCONCLUSIVE，离线补强）。
5. **是否存在 P0/P1？** P0 无；P1×4 全部为部署/运维面（R-01~R-04），无产品缺陷。
6. **是否有明显安全或权限问题？** 无 P0/P1；P3 三项（KDF/邀请邮箱/DNS TOCTOU）攻击前提苛刻，已记录。
7. **数据库迁移是否可靠？** 是——V1–V66 无跳号、约束成熟、本地全绿、唯一历史违例已闭环。
8. **备份恢复是否实测？** 否——DOCUMENTED_NOT_DRILLED，这是 RC 前必须补齐的第一优先项。
9. **关键环境依赖是否满足生产要求？** 本地开发环境满足；生产需补：出网白名单、TLS、可观测性目标、备份目标（均为文档/配置层面）。
10. **Agent 是否达到预期可靠性水平？** 是——主链路与生命周期全部真实验证，幂等与预算受控；剩余为 UI 体验项（R-07/R-08）与死列清理。
11. **模型接入是否存在发布阻断？** 否——Gemini/Kilo 真实通过；Zen 有清晰失败反馈，标注上游依赖即可。
12. **最严重的三个问题？** R-01 备份恢复未演练、R-03 无发布流水线/runbook、R-02 无生产可观测性（顺序即整改顺序；三者并列决定能否发布）。
13. **历史 Agent 重试 UI 是否需要发布前修复？** 不需要——有「重新发消息」兜底且后端 API 完备，列 RC 期间 UX 批次（R-07）。
14. **哪些代码质量问题值得近期修复？** 均不阻断；近期值得做的：AgentToolPolicy 加防误用注释、agentApi.resume 删除、cancelBusy 防连点（合计小时级）。
15. **当前 CI 是否覆盖目标提交？** 是——HEAD 15f4905 自身 run 40062189574 success。
16. **应先修复哪些、如何验证？** 按 remediation-plan S1 顺序：备份恢复（演练报告）、TLS/Cookie（compose+文档）、可观测性（本地生产 profile 冒烟）、发布流水线（镜像 digest 记录）。
17. **哪些允许延期？** risk-register 全部 P2/P3（有发布范围声明的除外：MCP/可视化域须标注或补验）。
18. **是否需要新一轮真实浏览器验收？** 发布决策不需要；RC 期间建议补两个低成本项（规划页面复核、可视化域冒烟）。
19. **本轮是否修改生产代码？** 否——仅 AGENTS.md 一处文档漂移修正（V65→V66，AGENTS.md 自身约定授权）+ 本报告集。
20. **最终裁决理由？** 见本文件第一节：核心达标 + 操作面缺口有限且明确 → CONDITIONAL GO。

## 六、边界声明

- 本轮验收环境为本地开发环境（local profile + Docker 基础设施），**不等同于生产环境**；所有「通过」结论限定于该口径。
- 本裁决不自动执行任何部署；合并 main 走 PR 且由人触发；发布动作由人执行 release-checklist.md。
- 本轮未发起任何付费模型生成；引用的全部真实模型调用均来自此前已授权轮次的既有证据。
