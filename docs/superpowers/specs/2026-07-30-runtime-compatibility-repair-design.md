# 知识问答、任务规划与项目文档运行时兼容修复设计

## 目标

恢复以下三条核心业务链路的真实可用性，而不仅是消除前端报错：

1. 知识问答能够基于项目文档完成向量检索，并由 AI 流式返回答案与引用。
2. AI 任务规划能够完成知识检索、规划骨架生成和后续细节生成。
3. 项目文档能够一次选择多个文件上传，并完成存储、解析和索引。

同时补齐令牌刷新、日期约束、表单校验和顶部错误提示，防止无效请求进入后端。

## 已确认根因

### 知识问答与规划骨架

Agent 功能为 `DocumentSearchHit` 增加了 `metadata` 字段，但
`DocumentMapper.search` 仍依赖 MyBatis 自动构造器映射。PostgreSQL `jsonb`
返回值无法匹配新的 `Map<String, Object>` 构造器参数，运行时抛出
`No constructor found in DocumentSearchHit`。

知识问答和任务规划共用 `DocumentSearchService`，所以两个功能同时失效。

### 文件存储

正在运行的 MinIO 容器凭据与当前 `.env` 中的后端凭据不一致。后端能够启动，
但 bucket 初始化和上传请求认证失败，最终映射为
`DOCUMENT_STORAGE_UNAVAILABLE`（HTTP 503）。

### 前端运行时

- 知识问答流式请求使用原生 `fetch`，没有复用 Axios 的令牌刷新机制。
- 知识问答和规划页面把文档列表作为硬启动依赖，文档接口失败会阻断整个页面。
- 规划表单允许空字段和非法日期直接提交。
- 规划轮询器会继续重试不可恢复的 HTTP 400。
- 通用错误映射用“请检查填写内容”等泛化文本覆盖了后端具体字段错误。

## 方案

### 1. 修复知识检索契约

为 PostgreSQL `jsonb` 元数据建立显式、安全的读取边界，不再依赖 record
自动构造器猜测。仓储层负责把数据库 JSON 转换为普通 Java
`Map<String, Object>`，领域与 Agent 引用逻辑继续使用稳定的
`DocumentSearchHit` 接口。

增加真实 PostgreSQL/pgvector 集成测试，插入带 metadata 的文档分块并执行
相似度检索，断言文件、内容、相似度和页码元数据都能正确读取。该测试必须能在
修复前复现构造器错误。

### 2. 恢复知识问答 AI

流式问答保留 SSE：

- 首次请求使用当前 Access Token。
- 返回 401 时通过现有刷新协调器静默刷新，并仅重试一次。
- 刷新失败时清理登录状态并跳转登录页，不形成循环。
- SSE 的 token、citations、done、error 均只触发一次终止语义。

端到端验收必须使用含 READY 文档和向量分块的真实项目，确认：

- 检索不再出现系统内部错误。
- 页面逐段显示 AI 答案。
- 回答完成后保存用户消息、AI 消息和引用。
- 模型或检索失败时显示具体中文错误。

### 3. 恢复 AI 任务规划

规划创建表单在请求前校验标题、目标、日期、最大任务数和文档状态。

最大任务数改为整数输入：

- 默认值：20。
- 允许范围：1–40。
- 前端输入控件限制范围，后端 DTO 与服务再次校验。

计划日期必须位于项目起止日期内，且计划结束日期不得早于开始日期。
规划轮询器只重试 429、502、503、504 等可恢复错误；其他 4xx 立即停止并显示
明确原因。

真实验收必须创建一条新规划并观察其至少完成骨架阶段，不能只验证列表接口。

### 4. 恢复存储并支持多文件上传

运行环境保留现有 MinIO 数据卷，使用当前 `.env` 重建 MinIO 容器，使容器与
后端凭据一致。重建后验证 bucket、上传、下载和旧对象可访问性。

前端文件选择器开启 `multiple`，建立上传队列：

- 一次选择多个文件。
- 每个文件单独显示等待、上传中、成功或失败。
- 限制并发，避免同时占满后端处理线程。
- 复用现有单文件上传 API，单个失败不影响其他文件。
- 全部结束后刷新文档列表。

### 5. 页面降级

知识问答与任务规划的核心数据和可选文档列表分别加载。

- 文档列表失败时，已有问答会话、问答历史和规划历史仍能打开。
- 需要选择文档的操作显示顶部提示，并提供重试。
- 页面初始化不因一个可选接口失败而整体中断。

### 6. 日期防线

建立共享日期规则，应用到项目、规划、里程碑和任务表单：

- 结束日期不得早于开始日期。
- 规划、里程碑和任务日期不得超出项目起止日期。
- 日期选择器直接禁用非法日期。
- 提交前再次校验，防止手工输入或状态变化绕过选择器。
- 后端保留最终业务校验。

### 7. 顶部具体错误提示

业务操作错误使用顶部消息提示，不再为了错误在页面内容中插入新的布局行。

错误提示由“操作上下文 + 安全具体原因”组成，例如：

- `上传“需求说明.pdf”失败：文件存储凭据无效，请联系管理员检查 MinIO 配置。`
- `创建规划失败：规划结束日期不能早于开始日期。`
- `提交问题失败：登录状态已过期，正在重新登录。`

前端优先采用后端返回的安全具体消息，`VALIDATION_ERROR` 不再覆盖字段原因。
未知异常仍隐藏堆栈和内部路径，并给出可执行的重试或联系管理员建议。

## 测试与验收

### 自动化

- 后端：DocumentSearch 映射集成测试、规划任务数与日期校验测试、现有全量测试。
- 前端：流式请求刷新测试、规划表单测试、轮询停止测试、批量上传队列测试、
  日期规则测试、错误呈现测试。
- OpenAPI：确认现有单文件上传契约不变；若未新增批量后端端点，则无需增加路径。

### 真实运行时

1. 重建 MinIO 后上传至少两个文件，确认逐文件结果及下载。
2. 等待文件进入 READY，提交一个知识问题，确认真实 AI 流式答案和引用。
3. 创建自定义最大任务数的规划，确认骨架生成不再失败。
4. 使用过期 Access Token 验证流式请求自动刷新。
5. 尝试所有非法日期组合，确认前端无法选择或提交。

## 非目标

- 不回滚已完成的 Agent 功能。
- 不新建重复的模型调用体系。
- 不通过吞掉异常或伪造成功结果掩盖 AI、检索或存储故障。
