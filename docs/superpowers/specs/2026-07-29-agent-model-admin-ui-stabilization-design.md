# Agent、多模型、管理员与前端稳定性设计

日期：2026-07-29

## 1. 目标

本轮修复以“浏览器中的核心协作流程可以被普通用户理解并稳定完成”为目标，覆盖以下结果：

- 用户向项目协作 Agent 发送“创建一个任务：完成 Agent 浏览器验收，优先级高，截止日期为 2026-08-05。”后，必须看到明确的运行状态和待审批任务卡片，不能静默失败。
- 普通知识问答、流式输出、取消和回答反馈恢复可用；有用/无用反馈只出现在助手回答下。
- 后端不再假设只有一种模型请求和响应格式，通过统一模型契约适配 OpenAI-compatible、Anthropic Claude 和 Google Gemini。
- DeepSeek、通义千问、智谱、Moonshot、MiMo 等提供 OpenAI-compatible 端点的中国模型通过同一适配器接入；厂商差异由能力声明和契约测试处理。
- 系统管理员可以通过前端管理本地用户和模型配置。
- 系统功能栏和项目功能栏固定，项目功能按用户任务合并，问答页面本身不出现整体滚动条。
- 甘特图、依赖图、日历、成员负载等视图使用清楚的图形、颜色、标记和图例表达项目事实。

本项目是本地应用。本轮不建设多租户、企业身份源、计费、模型市场、自动配额路由、复杂密钥轮换或跨节点配置分发。

## 2. 已确认的问题

浏览器中的目标 Agent 指令已经进入后端。对应运行在约两秒后以
`AGENT_TOOL_EXECUTION_FAILED` 结束，错误原因是“工具参数格式无效”。
当前 Agent Prompt 只向模型提供工具名称，没有提供
`create_task_after_approval` 的参数 Schema，因此模型可能选对工具但生成不符合
`CreateTaskRequest` 的参数。

前端轮询发现 `FAILED` 后只重新加载消息。失败运行不会生成助手消息，页面也不展示
运行错误，所以用户看到的是“没有返回”。同一项目中的历史运行还出现过结构化协议错误、
重复调用同一只读工具直到预算耗尽，说明模型适配和终止策略都需要统一治理。

现有后端已经具有 `system_admin`、创建测试账号、启用账号和停用账号能力，但缺少：

- 前端管理员入口与页面；
- 管理员用户列表接口；
- `/auth/me` 中可供前端使用的 `systemAdmin` 字段；
- 模型配置的持久化、鉴权和管理接口。

当前前端还存在导航项过多、项目功能栏不固定、会话条目高度不一致、问答页面整体滚动、
反馈按钮归属错误、可视化页面主要依赖文字且缺少清晰时间和关系表达等问题。

## 3. 范围分解与实施顺序

本设计分成三个可独立验收的阶段：

1. **P0：核心闭环恢复。** 修复认证视图、前后端契约、普通问答、反馈、Agent 工具协议、
   失败可见性、重试和审批式任务创建。
2. **P1：统一模型适配与管理员功能。** 建立模型能力契约、三类供应商适配器、模型配置
   管理、连接测试、用途分配和本地管理员。
3. **P2：前端信息架构与可视化。** 固定双导航、合并功能入口、约束问答布局和会话尺寸，
   重做日历、甘特图、依赖图和成员负载的表达。

只有 P0 验收通过后才进入 P1；只有模型管理闭环通过后才进入 P2。这样可以避免界面重构
掩盖后端故障。

## 4. 统一模型架构

### 4.1 上层契约

普通问答、Agent 和任务规划只依赖统一的模型服务，不直接依赖厂商 DTO。统一契约包含：

- 非流式文本生成；
- 流式增量事件；
- 结构化 JSON 或 JSON Schema 输出；
- 工具定义、工具调用和工具参数；
- 模型与供应商标识；
- 输入、输出 Token 和延迟；
- 可重试性、超时、额度、鉴权、协议和内容错误。

Embedding 作为独立能力接入同一配置目录，但不强迫不提供 Embedding 的供应商声明支持。

### 4.2 能力声明

每个已配置模型声明实际能力：

- `CHAT`
- `STREAMING`
- `STRUCTURED_OUTPUT`
- `NATIVE_TOOL_CALLING`
- `USAGE`
- `EMBEDDING`

模型用途为 `KNOWLEDGE_CHAT`、`AGENT`、`PLANNING` 和 `EMBEDDING`。管理员只能把满足
用途最低能力的已启用模型分配给该用途。能力不足时连接测试或保存操作直接拒绝，不能在
运行时假装支持。

结构化输出优先使用厂商原生 JSON Schema；厂商只支持普通文本时，允许使用严格 Prompt、
解析和一次纠正重试作为受控降级。工具调用优先使用原生工具协议；兼容端点不支持原生工具
时，使用相同 Schema 约束的 JSON 决策协议。

### 4.3 供应商适配器

- `OPENAI_COMPATIBLE`：OpenAI 及兼容 Chat Completions/Embeddings 端点，包括
  DeepSeek、通义千问、智谱、Moonshot、MiMo 等兼容服务。
- `ANTHROPIC`：Claude 原生 Messages API。
- `GEMINI`：Google Gemini 原生 generateContent/streamGenerateContent API。

适配器负责请求字段、鉴权、流式帧、工具调用、结束原因和用量的转换。上层不得读取厂商
专有字段。

### 4.4 配置与密钥

模型配置保存供应商类型、显示名称、基础地址、模型名称、能力、启用状态、用途和非敏感
参数。API Key 只允许设置或替换，查询接口只返回“已配置”状态，不返回原文。

这是本地应用，密钥使用本地配置的主密钥加密后持久化；主密钥来自未提交到 Git 的
环境配置。日志、审计和异常不得包含 API Key、Authorization Header 或完整模型响应。

连接测试使用最小请求并返回标准化结果：成功、鉴权失败、额度不足、超时、网络错误、
不兼容响应或能力不匹配。

## 5. Agent 数据流

1. 前端提交消息并立即显示用户消息与“正在处理”状态。
2. 后端创建持久化运行，Worker 按用途路由到当前 Agent 模型。
3. Prompt 或原生工具定义必须包含每个可用工具的名称、说明、严格参数 Schema 和审批属性。
4. 模型返回结果被归一化并在进入工具层前校验。
5. 只读工具执行后，工具结果进入后续模型上下文。相同工具和等价参数的无进展重复调用
   被终止，不能耗尽全部预算。
6. 写工具只生成待审批提案。`create_task_after_approval` 的规范参数包含标题、描述、
   里程碑、负责人、状态、优先级、工时、开始日期和截止日期；本验收用例必须归一化为
   标题“完成 Agent 浏览器验收”、高优先级和截止日期 `2026-08-05`。
7. 管理员批准后才调用现有 `TaskApplicationService`。审批继续使用 nonce、幂等键、
   项目权限和业务事务，重复批准不能重复创建任务。
8. 成功、待审批、失败、取消和预算终止都形成前端可见的稳定状态。

失败运行保留标准错误码和安全的用户提示。模型原始决策只允许以受限、脱敏的诊断记录
保存，不能泄露系统 Prompt、密钥或文档正文。

## 6. 普通知识问答与反馈

- 普通问答和 Agent 共享模型契约与错误映射，但保持各自的业务服务和权限边界。
- SSE 使用统一事件：开始、token、引用、完成、错误和取消。
- 流式处理的所有失败路径都必须发送终态或关闭连接，前端不能无限等待。
- 👍/👎 只属于已持久化的助手回答；用户问题、临时流式占位和错误消息都不显示反馈。
- 提交和撤销反馈使用同一消息 ID 契约。失败时恢复按钮状态并显示准确中文错误。
- 引用、反馈和会话查询都按项目和会话所有者限制，不能跨用户读取或写入。

## 7. 管理员能力

### 7.1 本地管理员

`local` Profile 幂等创建用户名和密码均为 `admin` 的系统管理员账号，仅用于本地开发和
浏览器验收。其他 Profile 不创建该账号。本轮不增加首次登录强制改密、企业级密码策略或
外部身份源。

### 7.2 管理员 API

`/auth/me` 返回 `systemAdmin`。所有 `/api/v1/admin/**` 接口由后端重新读取用户状态并
执行 `requireSystemAdmin`，前端入口控制不能替代授权。

管理员页面需要的最小 API：

- 分页或受限列表查询用户；
- 创建测试账号；
- 启用、停用普通账号；
- 查询模型配置；
- 新增、修改、启停模型配置；
- 替换 API Key；
- 测试连接；
- 为四类用途选择当前模型。

系统管理员不能停用自己或另一个系统管理员。管理操作写入不包含密钥的审计记录。

### 7.3 管理员界面

固定系统栏中的“系统管理”只对系统管理员显示，页面包含“用户管理”和“模型配置”
两个标签。用户管理呈现现有的创建测试账号、启用和停用功能；模型配置呈现供应商、模型、
能力、用途、启用状态、密钥是否配置、连接测试结果和编辑操作。

## 8. 前端信息架构

系统栏和项目栏都固定在视口顶部：

```text
系统栏：项目｜通知｜系统管理｜用户
项目栏：概览｜工作｜知识｜AI｜项目洞察｜设置
```

- “工作”：任务、里程碑。
- “知识”：文档、知识问答、知识评测。
- “AI”：AI 任务规划、项目协作 Agent。
- “项目洞察”：甘特图、依赖图、日历、成员负载、周报、风险分析、规划对比。
- “设置”：成员、操作日志和其他项目管理入口。

项目洞察使用单一入口和页内标签，不把每张图都放在顶层导航。窄屏时项目栏可横向滚动，
会话历史可以折叠，但不得遮挡主要内容。

页面文案只服务于用户完成操作。删除宣传式、技术式和重复说明，例如“带来源的项目问答、
进度检查、审批式写入与定时运行”。保留清楚的标题、按钮、状态、错误和必要的短引导。

## 9. 问答与 Agent 页面布局

应用外壳使用 `100dvh`。固定系统栏和项目栏占用高度后，问答页面通过 CSS Grid/Flex
填满剩余空间，并在所有伸缩容器上正确设置 `min-height: 0`。

页面根节点和浏览器 `body` 不出现纵向滚动条。只有消息列表内部滚动；输入框、发送按钮和
当前运行状态始终可见。不能只依赖易受内容影响的百分比高度。

左侧历史会话：

- 每项固定等高；
- 标题单行截断；
- 时间和状态对齐；
- 选中、悬停和键盘焦点清楚；
- 首项与后续项尺寸一致。

Agent 会话显示发送中、运行步骤、待审批、成功、失败、取消和预算终止。失败卡片提供明确
原因和可用时的重试操作，不能静默重新加载消息。

## 10. 可视化设计

### 10.1 日历

- 月视图直接显示每一天的全部任务，不使用“还有 N 项”隐藏内容。
- 日期格根据内容增长，项目洞察内容区滚动，而不是隐藏任务。
- 今日有清楚的背景和“今日”标记。
- 任务使用颜色、状态图形、优先级和逾期标记；悬停或点击显示完整信息。
- 上月和下月使用 `<`、`>` 图形按钮，并保留无障碍名称。

### 10.2 甘特图

- 统一时间刻度、周末区分、今日线和可见日期范围。
- 任务条表达状态、进度、起止日期和逾期。
- 依赖使用方向箭头；无日期任务单独列出并说明原因。
- 左侧任务名称区固定宽度，时间轴可横向滚动。

### 10.3 依赖图

- 节点使用状态颜色和简短标签。
- 箭头明确依赖方向，阻塞关系突出显示。
- 提供图例、空状态和重新布局操作。
- 不使用难以辨认的纯文本连接符代替图形关系。

### 10.4 成员负载

- 使用统一尺度的水平条形图比较成员工时和任务量。
- 用颜色区分正常、偏高和超载，并显示未分配任务。
- 数值标签作为图形的补充，不以大段文字替代图。

## 11. 接口一致性与错误处理

JSON API 继续使用 `code/message/data`；204、文件和 SSE 按 HTTP 语义处理。OpenAPI、
后端 DTO、前端 TypeScript 类型和实际 Controller 必须同步。

所有页面共享加载、空状态、错误、重试和中文枚举映射。错误处理区分：

- 用户可修正的输入错误；
- 登录或权限错误；
- 模型配置或能力错误；
- 模型暂时失败或超时；
- 额度不足；
- 协议或工具参数错误；
- 业务冲突和重复操作。

前端不显示 Java 异常、数据库细节、供应商原始响应或内部枚举。后端日志保留关联 ID 和
标准错误码，足以定位“前端提交、运行入队、模型调用、工具校验、审批、业务写入”中的
失败边界。

## 12. 测试与浏览器验收

### 12.1 后端

- 为统一模型契约和三类适配器建立官方格式的请求、响应、流式帧、工具调用、用量和错误
  Fixture 测试。
- 为能力分配、密钥不回显、管理员鉴权和连接测试建立服务与 Controller 测试。
- 为 Agent 工具 Schema、参数归一化、无进展循环终止、失败可见性和审批幂等建立回归测试。
- 为知识问答 SSE 终态、反馈所有权和撤销建立回归测试。

默认自动化测试不依赖真实外部模型网络。管理员连接测试和可选的本地真实模型验收使用当前
配置，不把密钥写入测试输出。

### 12.2 前端

- 测试系统管理员入口、用户管理和模型管理操作。
- 测试 Agent 的发送中、待审批、失败和重试状态。
- 测试反馈按钮只属于助手回答，并验证失败回滚。
- 测试功能分组、固定导航和会话条目等高。
- 测试日历今日标记、全部任务渲染和图形按钮。

### 12.3 真实浏览器验收

至少验证：

1. 使用本地 `admin/admin` 登录并打开管理员页面。
2. 新增或编辑三个协议族的配置，测试连接并分配模型用途。
3. 在项目协作 Agent 中发送固定任务创建指令。
4. 页面出现标题“完成 Agent 浏览器验收”、高优先级和截止日期 `2026-08-05` 的待审批卡片。
5. 批准一次后任务出现，重复操作不创建第二条任务。
6. 普通问答有返回，流式取消可结束，用户问题下无反馈按钮，助手回答反馈可提交和撤销。
7. 问答页面无整体纵向滚动条，消息列表可独立滚动，历史会话等高。
8. 双导航固定；项目洞察入口包含全部合并视图。
9. 日历展示全部任务并突出今日；甘特图、依赖图和负载图能由图形直接读出主要关系。

## 13. 完成标准

- 固定 Agent 创建任务用例完整通过，失败不再静默。
- OpenAI-compatible、Claude、Gemini 的自动化契约测试通过。
- 管理员可以完成用户与模型配置的本地闭环。
- 问答、反馈、Agent、审批和任务写入的前后端契约一致。
- 后端测试、前端测试、类型检查、构建、OpenAPI 校验和真实浏览器验收全部有实际结果。
- 文档只把经过验证的能力标记为完成。
- 修复过程中遇到的其他问题，只有在能够复现且属于当前页面、接口或核心闭环时才一并修复；
  不扩建与本设计无关的功能。
