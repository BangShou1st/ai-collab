# 现有实现闭环稳定化设计规格

> 日期：2026-07-29
>
> 状态：已批准，待实施
> 适用范围：AI Collab 当前仓库的现有功能、Phase 09 未提交实现及相关文档

## 1. 背景

AI Collab 已实现认证、项目与成员、任务与里程碑、评论、文档处理、项目知识问答、AI 任务规划等模块，并正在完成 Phase 09 的项目概览与操作日志。但是，当前“代码存在”“前端可操作”“前后端契约一致”“测试能够证明”和“文档宣称完成”之间并不完全一致。

本轮工作的目标不是继续扩展第一版产品范围，而是稳定已经开始开发的能力：修复真实缺陷，完成已有前后端能力的闭环，校正权限和中文显示，补充必要测试，并让文档准确反映代码事实。

## 2. 核心原则

### 2.1 范围判定

一个功能只有满足以下任一条件，才进入本轮：

1. 前后端已经存在，但联调失败或行为错误；
2. 后端业务接口已经实现，但对应前端入口缺失；
3. 前端入口已经存在，但调用的后端接口、权限或数据结构不完整；
4. Phase 09 已存在设计、代码或未提交文件，但尚未完成验证；
5. 文档对当前代码状态、接口、权限或数据结构的描述不准确；
6. 当前测试、构建或本地核心链路失败。

仅存在需求描述、没有可执行代码的功能不进入本轮。

### 2.2 实施约束

- 保留当前工作区已有修改，不回退、不覆盖用户成果。
- 继续在本地 `main` 分支工作，不创建功能分支。
- 所有生产行为修复必须先有能够失败的回归测试。
- 所有项目级查询和写入必须显式携带 `project_id`。
- 后端权限是可信边界，前端隐藏按钮只是交互优化。
- 不修改已经发布的 Flyway 迁移内容；新增数据库变更才创建新版本。
- 不把模型调用放入数据库事务。
- 不新增供应商专用业务依赖。
- 不把尚未实现的能力写成“已完成”。

## 3. 当前审计基线

### 3.1 已获得的运行证据

- 前端现有 6 个测试文件、39 个测试通过。
- 前端 TypeScript 类型检查通过。
- 前端生产构建通过，但存在较大的单入口产物警告。
- 后端测试能够完成，但 5 个断言失败：
  - 1 个 Spring Bean/PostgreSQL 集成测试仍断言最新 Flyway 版本为 V11；
  - 4 个迁移安全测试仍断言迁移历史仅到 V11；
  - 当前仓库已经存在 V12，因此失败属于迁移契约断言过期。
- 使用本地预置账号完成真实登录后，项目列表、Dashboard、Audit、任务、里程碑、文档、知识会话和 AI 规划列表接口能够返回统一成功响应。

### 3.2 已确认的实现缺口

- 项目更新和删除已有后端接口，但项目列表页没有操作入口。
- Phase 09 Dashboard 与 Audit 已有未提交的前后端代码，但缺少针对统计、权限、项目隔离和页面行为的测试。
- 前端自动化测试几乎全部集中在 AI 规划，其他现有模块缺少最低限度的契约与关键交互保护。
- 文档同时存在“Phase 09 已完成”“当前里程碑仍为 Phase 08”“第一版条目全部实现”等互相冲突的描述。
- 历史学习文档混合了阶段当时状态和当前状态，容易被后续开发模型误读。

## 4. 本轮功能范围

### 4.1 测试与构建修复

更新与 V12 迁移相关的测试断言，使测试检查实际需要的迁移历史和最新版本。不得通过删除 V12、跳过测试或弱化迁移校验来获得通过结果。

后端完整测试、前端测试、前端类型检查、前端生产构建和 `git diff --check` 必须作为最终验收命令。

### 4.2 Phase 09：项目概览

完成以下现有实现：

- 项目基本信息与当前用户角色；
- 成员数量；
- 任务总数、待处理、进行中、阻塞、完成、取消、逾期数量；
- 排除取消任务后的完成率；
- 里程碑任务进度和逾期状态；
- 最近更新任务；
- 最近上传文档；
- 最近项目活动；
- 项目根路由默认进入概览。

Dashboard 对所有项目成员开放。最近活动只返回展示所需的脱敏字段，不向普通成员暴露 `requestId` 和完整结构化 `detail`。

### 4.3 Phase 09：操作日志

完成以下现有实现：

- OWNER 和 ADMIN 可查看项目操作日志；
- MEMBER 访问后端接口得到稳定的 403 业务错误；
- 前端 MEMBER 不显示操作日志入口；
- 日志按 `created_at DESC, id DESC` 稳定分页；
- 分页从 1 开始，`size` 范围为 1–100；
- 日志展示操作人、操作类型、操作对象、摘要和时间；
- 历史空 `detail` 和非法 `detail` 使用安全中文回退；
- 高价值操作写入有限的结构化详情；
- 不记录描述全文、文档正文、模型 Prompt、Token、密码、Cookie、API Key 或其他密钥。

### 4.4 已有项目接口的前端闭环

项目列表页补齐后端已经实现的项目更新与删除：

- OWNER 可打开项目编辑界面；
- 编辑名称、描述、开始日期、截止日期和当前已支持的项目状态；
- 提交时携带后端已有的乐观锁 `version`；
- 版本冲突提示用户刷新后重试；
- OWNER 可发起项目删除；
- 删除前显示明确的二次确认；
- 项目仍有关联文档或已确认规划时，展示后端稳定业务错误；
- ADMIN 和 MEMBER 不显示所有者专属删除操作。

本轮不扩展项目数据模型，因此不新增项目类型，也不把现有 `ACTIVE | ARCHIVED` 改造成四状态模型。

### 4.5 现有页面联调审计

逐模块核对以下内容：

| 模块 | 本轮核对内容 |
|---|---|
| 认证 | 登录、会话恢复、当前用户、当前设备退出、全部设备退出、注册关闭提示 |
| 项目与成员 | 列表、详情、创建、更新、删除、邀请、角色修改、成员移除 |
| 任务与里程碑 | CRUD、负责人、状态、优先级、依赖、评论、权限 |
| 文档 | 上传、列表、详情、下载、重试、删除、处理状态 |
| 知识问答 | 会话、提问、引用、资料不足拒答、删除和错误显示 |
| AI 规划 | 创建、生成状态、编辑版本、恢复、局部修复、确认、删除 |
| Dashboard/Audit | 聚合统计、路由、权限、分页、中文摘要 |

审计发现的问题只有满足第 2.1 节的范围判定才修复。完全没有实现的功能只记录到功能矩阵。

## 5. 中文界面规则

所有面向普通用户的界面文案使用简体中文：

- 页面标题、导航、按钮、表单标签、空状态、确认框和错误提示使用中文；
- 后端枚举不得直接作为页面文案展示；
- 状态、角色、优先级、里程碑状态、文档状态、审计动作和对象类型必须经过集中映射；
- 日期使用中文年月日或统一的 `YYYY-MM-DD` 业务日期格式；
- `v1` 一类版本显示改为“版本 1”；
- `AI`、`API`、`PDF`、`DOCX`、`Markdown`、模型名称和 MIME 类型属于必要技术标识，可以保留；
- 产品品牌不再以单独的英文 `AI Collab` 作为主要用户界面名称，统一使用“高校竞赛 AI 项目协作平台”或经批准的中文简称；
- 未知后端错误码不能直接显示给用户，统一降级为安全中文提示。

代码变量、类型、接口路径、测试名称和开发注释不受“纯中文界面”约束。

## 6. 权限与数据隔离

### 6.1 权限基线

| 能力 | OWNER | ADMIN | MEMBER |
|---|---:|---:|---:|
| 查看项目与 Dashboard | 是 | 是 | 是 |
| 更新项目 | 是 | 否 | 否 |
| 删除项目 | 是 | 否 | 否 |
| 查看完整 Audit | 是 | 是 | 否 |
| 查看 Dashboard 脱敏动态 | 是 | 是 | 是 |
| 管理任务、里程碑、文档和规划 | 是 | 是 | 仅既有受限能力 |

### 6.2 验证要求

- 不能只测试前端按钮是否隐藏；
- Controller 或 Application Service 必须通过 `ProjectAccessGuard` 校验；
- 子资源查询采用 `(projectId, entityId)`；
- Dashboard 和 Audit Mapper 的每条项目级 SQL 都必须包含项目条件；
- 使用另一个项目的资源 ID 时不得返回或修改资源；
- MEMBER 对管理员接口得到 403，而不存在或不属于项目的资源按既有安全语义返回 404。

## 7. 错误处理与一致性

- 继续使用 `{code, message, data}` 统一响应格式；已有 204 删除响应保持现状，文档准确描述。
- 参数校验错误由全局异常处理器转换为稳定业务响应。
- 前端优先按业务错误码映射中文提示，不向用户展示 SQL、堆栈、内部类名或敏感字段。
- Dashboard 聚合中的可选列表为空时返回空数组，而不是 `null`。
- Audit 结构化详情序列化失败或超限时降级为空对象，不影响主业务事务。
- 项目更新使用乐观锁，受影响行数为 0 时返回 `VERSION_CONFLICT`。
- 项目删除继续遵守当前文档与已确认规划的保护规则，不在本轮改变删除语义。

## 8. 测试设计

### 8.1 后端

新增或补齐以下测试：

- V1–V12 迁移历史和最新版本测试；
- Dashboard 统计口径测试；
- Dashboard 项目成员访问和非成员拒绝测试；
- Dashboard 最近任务、文档和活动的项目隔离测试；
- Audit OWNER/ADMIN 成功、MEMBER 拒绝测试；
- Audit 分页边界、排序、历史空详情和非法详情回退测试；
- 结构化 Audit 详情敏感字段与长度限制测试；
- 项目更新乐观锁和 OWNER 权限测试；
- 项目删除保护规则测试。

优先复用 PostgreSQL Testcontainers 集成测试，不用 H2 模拟 PostgreSQL 特性。

### 8.2 前端

新增或补齐以下测试：

- Dashboard 加载、空数据、错误和中文状态映射；
- Audit 权限导航、分页和错误状态；
- 项目编辑表单、乐观锁请求、删除确认和权限按钮；
- 集中显示映射对所有已知枚举返回中文，对未知枚举返回安全中文回退；
- API 层请求方法、路径、查询参数和请求体契约。

前端测试不只断言组件内部变量，应断言用户可见行为和实际 API 调用参数。

### 8.3 联调冒烟

使用本地预置账号完成：

1. 登录并获取当前用户；
2. 加载项目列表和项目详情；
3. 打开 Dashboard；
4. 打开 Audit；
5. 加载任务、里程碑、文档、知识会话和规划列表；
6. 验证更新项目的版本字段；
7. 使用不同角色验证导航和后端权限；
8. 退出当前设备。

冒烟测试不得打印 Access Token、Refresh Token、密码或 API Key。

## 9. 功能矩阵

新增一份面向后续开发的权威功能矩阵。每个功能只能使用以下状态：

- `已完成`：前后端闭环、关键权限存在、具有验证证据；
- `部分完成`：至少一层已经实现，但缺少界面、接口、业务规则或验证；
- `未实现`：没有可执行实现；
- `不在第一版`：明确排除。

矩阵至少记录：

- 功能名称；
- 当前状态；
- 后端入口；
- 前端入口；
- 权限；
- 自动化测试证据；
- 手工验收方式；
- 已知限制；
- 推荐的后续开发文档。

文档不得仅依据类名或页面存在就标记“已完成”。

## 10. 文档重构

代码稳定并完成验证后，再按以下顺序调整文档：

1. 创建权威功能矩阵；
2. 更新 `CLAUDE.md` 为短小、准确、可直接供 Claude 启动读取的项目上下文；
3. 校正 `docs/architecture.md` 的当前能力、权限、状态模型和 Phase 09；
4. 校正 `docs/database.md` 的 V12、表和约束；
5. 校正 `docs/api/openapi.yaml` 与真实 Controller；
6. 重写 `docs/FUTURE_ROADMAP.md`，只保存未实现能力和明确优先级；
7. 为 Claude + MiMo V2.5 创建按模块拆分的开发入口、约束、验证与提示词文档；
8. 处理历史学习文档：保留有教学价值的内容，但在文首明确“阶段历史记录，不代表当前完成状态”；
9. 删除完全重复、已被权威文档替代且会误导后续模型的临时提示词或过时计划。

删除文档前必须确认其信息已经迁移到保留文档，并在最终交付中列出删除项。

## 11. Claude + MiMo V2.5 约束

后续开发文档必须把 MiMo 限制为执行者，而不是产品决策者：

- 每次只开发一个明确闭环；
- 必须列出允许修改的文件；
- 禁止修改范围外模块；
- 禁止自行新增表、枚举、状态、角色或 API；
- 禁止修改旧 Flyway 文件；
- 禁止删除失败测试或降低断言强度；
- 先读取对应功能矩阵、接口契约和模块开发文档；
- 先写失败测试，再写最小实现；
- 每个步骤提供确定的验证命令和期望结果；
- 发现歧义时停止实现并报告，不自行选择产品语义；
- 未获得完整验证证据时不得宣称完成；
- 输出必须列出修改文件、验证结果、剩余问题和未触碰范围。

Claude 负责上下文理解、方案审查、代码评审和跨模块一致性；MiMo 适合在严格文件边界和明确测试下完成小型实现任务。

## 12. Agent 定位

当前 AI 任务规划是“受控 AI 工作流”，不是完整通用 Agent：

- 已具备多阶段模型调用；
- 已具备结构化输出、业务校验、人工编辑和确认；
- 已具备幂等事务落地和操作审计；
- 模型不能直接操作业务表。

完整 Agent 框架还需要统一运行模型、状态机、工具注册、权限感知工具调用、短期状态、运行事件、预算和超时、暂停/恢复、人工审批以及可观测记录。本轮只在文档中定义该差距，不实现 Agent 框架。

后续 Agent 必须复用现有应用服务作为工具边界，不能让模型直接调用 Mapper、数据库、MinIO 或任意 URL。所有写工具都需要后端重新鉴权、参数校验、幂等控制、事务和审计；高影响写入继续要求人工确认。

## 13. 不在本轮实现

- 项目类型；
- 准备中、进行中、已完成、已归档四状态重构；
- 成员主动退出项目；
- 所有权转移；
- 管理员创建测试账号；
- 知识问答流式输出；
- 回答有用或无用反馈；
- 通用 Agent 框架；
- 通知、AI 周报、甘特图、日历、依赖图；
- 自动模型额度检测和自动供应商切换。

这些能力只能标记为“未实现”或“部分完成”，不得为了满足文档描述而混入本轮代码。

## 14. 交付与验收

本轮完成必须同时满足：

1. 后端完整测试通过；
2. 前端完整测试通过；
3. 前端类型检查和生产构建通过；
4. 本地核心接口冒烟通过；
5. Phase 09 权限、统计和项目隔离具有自动化证据；
6. 项目更新和删除可以通过中文前端完成；
7. 所有面向用户的已知枚举和错误具有中文映射；
8. 功能矩阵逐项对应代码和测试证据；
9. `CLAUDE.md`、架构、数据库、OpenAPI 和路线图相互一致；
10. 文档明确当前 AI 规划与完整 Agent 的边界；
11. `git diff --check` 无格式错误；
12. 最终报告区分已修复问题、未实现功能和已知限制。

## 15. 规格自检

- 无待定产品选项或占位符；
- 本轮范围与“不开发完全缺失功能”的决策一致；
- 已明确当前工作区修改的保护规则；
- 已覆盖架构、组件、权限、数据流、错误处理、测试、文档和 Agent 边界；
- 已明确完成状态必须由运行证据支持。
