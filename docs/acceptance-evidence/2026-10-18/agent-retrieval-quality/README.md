- 委派链路事实：子运行 `depth=1`、角色 `KNOWLEDGE_RESEARCHER`、受限只读白名单；父合成请求中**实际注入**子运行结论（`CHILD_RESEARCH` 数据块），父最终引用保留**子来源身份**（不是模型文本里的引用记号）。
- 本类脚本化模型轮次，度量的是**委派受理/回收/来源保真/失败如实降级**的机制正确性，**不是真实模型回答质量**。
- **不追求委派调用率越高越好**：简单单事实任务（如 #9 指定文档）直接研究（1 次工具、3 步）成本更低；委派用于需要多轮检索/正文对照的任务（本基线 B 场景）。

## 7. 质量指标与逐用例失败原因

- L1 硬性不变量（全部通过，逐用例断言）：来源 ID 不混淆（保留来源 documentId 与其 chunkId 归属一致）；丢弃归因互斥且合计恒等于 `droppedByContext`；上下文正文预算 ≤ 8000 code point；无期望证据时判为 `UNDEFINED_NO_EXPECTED_EVIDENCE`（不伪装成召回失败）；指定范围不越界；索引代际双向隔离；相同条款跨文档两身份并存。
- L2 真实 Embedding：见第 4 节。失败/偏低逐条归因：
  1. **#7 长分块尾部条件**：`DB_MISS` —— 期望证据在 Top20 内**未召回**（长分块被大量重复填充文本稀释，语义信号密度低）。非检索窗口问题（Top8 与 Top20 同为 0），也非上下文丢弃（`droppedByContext=0`）。
  2. **#2、#15 `SOURCE_CAP`**：证据已在候选（#2 容量规划 rank 8 相似度 0.4512；#15 上线门禁 rank 6），但最终 12 个来源名额被“每文档一个代表 + 全局补齐”占满。见下节成因分析。
  3. **#3、#13 旧入口保留率 0.5**：全局 `contentHash` 去重把两份文档的相同条款合并成一条；`buildDiverse` 保留两个独立来源，**真实 Embedding 下复现并确认修复有效**（0.5 → 1.0）。
  4. **#11 不存在的事实**：`UNDEFINED`，但检索仍返回 12 条高于 0.15 阈值的无关来源。阈值偏低属既有设计；真实模型在 L3 探针中正确拒答，未假阳性。
  5. **#5 深排位**：本语料的干扰分块不足以把正确证据挤出 Top8（`性能指标` 仍 rank 1，相似度 0.8843），故**未复现“Top8 之外”条件**；该窗口截断的机械行为由确定性合成用例覆盖，此处据实记录未复现。

**本轮未改动生产代码。** 依据任务原则“先用真实问题证明哪里质量不足，再做针对性改进”“只修实际触发的问题”，对第 7 节失败逐条判定：

| 现象 | 判定 | 依据 |
| --- | --- | --- |
| #3/#13 旧入口塌缩 | **非缺陷（已修复）** | `buildDiverse` 已消除跨文档全局去重；真实 Embedding 下确认 0.5→1.0 |

| #2/#15 `SOURCE_CAP` | **已文档化的设计取舍**，非缺陷 | D-RAG-01B R1 明确“优先保留文档覆盖，可能选择低于其他文档代表的分块”，并由 `CrossDocumentSourceSelectorTest#diversityMayKeepAWeakButEligibleDocumentRepresentative`（0.16 边界）钉住 |

成因分析（#2）：20 个候选、12 个来源名额。第一阶段给 9 个文档各 1 个代表名额（其中 `检索性能测试手册`/`安全与脱敏规范`/`需求变更单` 的代表仅 0.40–0.42），剩余 3 个名额按全局相似度补齐；期望证据 `容量规划`（0.4512）高于部分代表分块却因名额被代表占用而落选——这正是“跨文档覆盖优先”策略的**已知代价**。若把第一阶段代表名额限制为“代表相似度不低于全局第 N（N=名额数）高者”，可让弱文档参与全局竞争而不占用名额，从而保留 `容量规划`；但这会改变 D-RAG-01B 的既定语义与钉住该边界的单测。**本轮不实施**，作为下一轮的候选改进（见第 10 节），以免在无充分回归覆盖的情况下改动稳定的选择器。

结论：**无缺陷 → 只交付基线**，不创建 `fix(agent)` 提交。

- 清理 Docker 缓存（约 1.2 GB）后再次完整 `clean verify` **全绿**（见上）。
- 结论：**非代码缺陷、非本轮改动引入**；本次新增测试在两次运行中均通过。

## 10. 未验证部分与剩余风险

1. **L3 完整 Agent-loop 真实模型评测未做**：仅完成“真实模型 + 真实证据”的回答合成探针（L3-PARTIAL）。剩余风险：真实模型的多步工具调用、委派决策、预算收敛下的证据保留与最终综合质量，尚未在真实模型上逐用例判定。
2. **真实语料规模小且为手写**：15 个用例 / 13 份文档 / 38 分块，召回率不代表生产全量语义质量。建议下一轮引入更广的真实资料与标注查询集。
3. **跨文档覆盖优先的代价**（#2/#15）：名额被弱相关文档代表占用，可能挤掉更强证据。下一轮候选改进：为第一阶段代表名额引入“相对全局 N 名”下限，或对同文档多分块需求做互补保留；改动须同时更新 `CrossDocumentSourceSelectorTest` 并跑 P0 对照。
4. **长分块信息密度**：低密度长分块易被稀释而漏召。属分块/摘要侧问题，超出本轮范围。
5. **相似度阈值 0.15 偏低**：无答案问题仍会返回若干无关来源，依赖模型拒答；已在 L3 探针中确认真实模型能拒答，但阈值调优属另一轮。
6. **委派价值场景**：本轮仅验证机制正确性；真实模型下“直接研究 vs 委派”的性价比需在 L3 完整评测中继续观察（历史记录显示全库研究任务受子运行预算限制）。
