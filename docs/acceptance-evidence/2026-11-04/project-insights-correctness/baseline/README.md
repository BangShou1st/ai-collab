## 实际查看发现的问题（全部有截图证据）

### AI 周报（weekly-report-1440.png）
1. **统计口径失真**：页面显示"总任务 2"，但同一项目看板有 18 个待处理任务——统计集合与真实项目状态严重不符（周报 SQL 的 `OR status = DONE` 类条件导致只命中部分子集，却以"总任务"名义展示）。
2. 无报告起止日期，用户无法知道统计覆盖哪一周。
3. 无"本期新建 / 本期完成"区分，累计状态被当作周期变化展示。
4. 完成率 0.0% 无分母口径说明。
5. "亮点 / 风险"为固定规则文本，页面标题却是"AI 周报"——未调用模型却暗示 AI 生成。
6. 里程碑"即将到期 1"无时间窗口说明。

### 延期风险分析（risk-analysis-1440.png）
1. 高/中/低 15/2/2 **未说明是风险条目数还是涉及任务数**；同一任务"实现报名提交与数据存储接口"同时出现逾期与阻塞两行，无法判断是否重复计数。
2. 无任务跳转入口，风险不可操作。
3. 无数据来源与规则说明（用户无从知道这是规则检测）。
4. 顶部建议为固定文案，无行动指向。

### 成员负载（member-load-1440.png）
1. **项目有成员、有 18+ 任务，页面却显示"暂无成员数据"**——按 assignee 聚合且全员未分配时整页空，与项目真实状态矛盾，极具误导性。
2. 无口径说明（估算工时≠实际投入）。
3. 空态文案未区分"没有成员"与"成员无任务分配"。

### 规划对比（plan-comparison-1440.png）
1. 该项目为 AI 规划验收项目，规划下拉却为空——可对比规划的筛选条件存疑（交由 Agent A 审查后端）。
2. 无基准版本语义说明（最新版本 vs 实际应用版本）。

### 通用（四页共通）
1. `projectId` 在 setup 一次性捕获，切换项目（同组件实例复用）不重载——跨项目数据残留风险。
2. 无请求令牌，快速切换时旧响应可能覆盖新数据。
3. 失败态与空态不区分（请求失败展示为"暂无数据"）。
4. 无刷新入口。
