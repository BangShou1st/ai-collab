## C. 冻结方案与客观评价

- **A**：生产算法，过滤相似度/空正文、同文档 hash 去重后，先每文档最高分代表，再按全局分数补齐。
- **D**：保留 A 的文档竞争次序和名额，文档内部用 query 与 heading/body 的不同相邻字母数字二元组交集数选代表；平分时依 similarity 降序、UUID 升序。剩余位置仍按原全局分数补齐。重复背景不会因为重复次数得额外分，但更多字面匹配不代表语义正确。
- **E**：完整保护 A 的代表及顺序，仅在剩余名额按尚未被已选内容覆盖的 query 二元组数竞争；平分时依 similarity、UUID。覆盖保护的是来源文档身份，不是代表之外每一个互补事实。文档数达到或超过名额时没有可竞争空位，精确回退 A。

两种候选都只读取 query、候选 identity/heading/body/similarity 和 limit；不读 expected、答案、文件名例外或真实模型判定。字面规则没有可调权重/阈值，不进行参数搜索，也未设计第三候选。每步预处理与有界贪心扫描保持确定性；20 候选、最多 12 步，不存在扩大候选或无界循环。

13 文档竞争 12 位时，不可能额外保住主文档第二块并保证所有文档有代表。D 选择替换本文件代表，E 放弃该场景的新增收益，均不宣称无损解决所有冲突。

证据相关性按原始 marker 在**实际截断后的来源正文**中出现评价；多文档覆盖按含目标事实的期望文档计算，另记全部来源文档数；预算利用记录来源数、转义后上下文 code points 和未匹配标注的来源数。未匹配标注不等于已证明无关。标签仅在 select 返回后进入 evaluator；旧题和 E7/E11 原始期望均未改变。

装配器复制生产的转义、文件名/标题上限、每条公平分配、120 正文最小额度和 8000 总预算。每次 A 对照都与生产 KnowledgeContext 完整相等断言，D/E 不重新调用生产选择器改变所选次序。现有工具还有 600 字 quote 截断，本实验评价上下文装配层，不声称已验证完整 Agent 输出链或 Chat 回答。
