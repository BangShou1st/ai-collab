## 四、相邻上下文扩展安全性核验（阶段三）

针对上一轮提出的方案 C（分段检索定位后自动拼接前后相邻文本）：

### 1. 发现的重大安全与实现风险
- **Unicode Surrogate Pair（代理对）截断风险**：此前测试侧 `ContextExpander` 采用裸 `substring(text.length() - maxChars)` 方式获取前后文。在包含增补字符（如 Emoji `\uD83D\uDE80` 🚀 或特殊生僻字 `\uD842\uDFB7` 𠮷）时，若截断点恰好落在高位代理与低位代理之间，将直接产生**无效 Unicode 畸形字节或乱码（Malformed UTF-16）**。
- **跨边界串扰风险**：相邻扩展若缺少严格的文档边界、代际边界、章节标题边界过滤，极易将已废弃的旧版本内容、同项目其他文档的段落或不同一级标题下的内容误拼为一个来源。
- **真实 Offset 与引用失真**：追加了前后文的分块正文与数据库记录的 `charFrom`/`charThrough` 坐标不符，会导致前端划词高亮与引用校验逻辑失效。

### 2. 结论
**现阶段坚决不把相邻上下文扩展接入生产。** 这是一个尚未完全成熟的复杂机制，存在破坏文本编码与引用定位的确定性风险。
