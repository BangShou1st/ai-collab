# Work item record standard

Every managed work item must record its accountable assignee, current lifecycle status, due date, and last-modified time. These four fields are required so project reviewers can identify who owns the work, whether it is blocked or complete, when it is due, and when its record last changed. A task without any of these fields is incomplete for release review.

# Active release v2 acceptance

The release candidate acceptance review is scheduled for 2026-11-02. For the active v2 release, public API p95 response time must be strictly below 500 milliseconds, and the API error rate must stay below 0.5 percent. These v2 limits are the current release criteria and should be checked together before approval.

# Historical v1 limits (superseded)

The previous v1 release used a public API p95 limit of 800 milliseconds and an error-rate limit of 1.0 percent. Version 1 has been superseded. Its thresholds are retained only for historical comparison and must not be used to approve the active v2 release.

# Unrecorded budget

The project materials do not specify a project budget or an approved spending amount. Reviewers must not infer a budget from schedule, performance, staffing, or release requirements.
