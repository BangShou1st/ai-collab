# 团队协作平台运维手册

版本：v2026.05 ｜ 适用范围：生产环境运维团队 ｜ 密级：内部

## 第 1 页：API 使用限制

自 2026-06-01 起，Public API（含个人访问令牌）对每个用户实施默认限流 100 req/min。
限流按用户维度统计，不按 IP 维度统计；超出后返回 429 并附带 Retry-After 头。

团队管理员可以在管理后台为特定用户申请限流提额。提额审批通过后，该用户的限流上限
提升为 120 req/min。提额仅对申请时指定的用户生效，不能对整个团队批量生效；普通用户
无法自行发起提额申请。

### 数据导入

批量导入功能单次最多支持 5000 条记录。导入文件仅支持 CSV 格式，编码必须为 UTF-8
且不带 BOM；Excel 的 .xlsx 文件不被导入接口接受。超过 5000 条的批次必须拆分。

导入过程中系统逐行校验，失败行会在导入报告中逐条列出。当整批失败率超过 2% 时，
系统拒绝整批导入并要求修正后重试；失败率以单批 5000 条为分母计算。

## 第 2 页：密钥管理

生产环境的 API 密钥必须每 180 天轮换一次。轮换窗口为到期前 7 天，逾期未轮换的密钥
将被自动禁用。测试环境与开发环境的密钥不强制轮换，但建议至少每年更换一次。

### 部署纪律

同一 Helm chart 在同一集群内不得同时存在两个 release。历史事故表明，双 release 会
导致数据库迁移脚本双跑，产生不可逆的 schema 冲突。发布前必须确认旧 release 已完全
删除，包括级联的服务与 ingress 资源。

## 第 3 页：故障处置

数据库迁移失败时，必须先回滚当前 release，再修复迁移脚本。顺序不能颠倒：先修脚本
会导致部分节点已经应用了半成品迁移，产生 schema 漂移；回滚后再修复可以保证所有节点
从同一基线重放。

### 备份策略

全量备份每周日 02:00 执行一次，备份数据保留 90 天。手动触发的备份同样写入备份存储，
但不占用 90 天保留窗口的自动清理名额，需要运维手动管理。恢复演练每季度进行一次，
演练结果记入运维台账。
