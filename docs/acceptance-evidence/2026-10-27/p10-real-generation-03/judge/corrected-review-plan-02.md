# 裁判来源覆盖补充复核 02（冻结计划）

## 为什么新增第二版

补充复核 01 的来源数据已补齐，但把裁判规则和评测数据放在同一个 user 消息中，并把工具响应原文整体嵌入 JSON。前 12 次本地请求中仅 3 次返回符合结构的裁决，9 次复述了答案或输出其他 JSON；这些响应不进入本轮裁决。原始结果保存在 `corrected-review-results-prototype-01.json`。

本版继续保留相同的 22 条缺口样本，但把规则放在独立 `system` 消息中；user 消息只含问题、实际来源全文、实际入选 QA 片段/Agent 工具证据与候选回答。来源文本被明确标为评测数据，绝不作为裁判指令执行。精确输入与 SHA-256 在 `corrected-review-inputs-02.json` 中冻结。

## 冻结范围与预算

- QA：`Q10/Q11/Q12/Q13/R3`，来源使用真实 QA 请求选入 Prompt 的上下文来源与完整 fixture 文档。
- Agent：17 个有最终回答的场景，来源使用冻结场景文档、该场景真实工具调用的参数/结果摘要、来源引用片段及完整 fixture 文档。
- `AG06/AG15/AG19` 没有有效最终回答，仍为 `NOT_ASSESSABLE_NO_VALID_ANSWER`，不发送裁判请求。
- 模型：`qwen2.5:7b-instruct`、`qwen3.5:4b`。串行执行，每模型每输入一次，最多 44 次 loopback 请求；不重试。
- 仅使用本机 Ollama；不访问外部模型 API，不读取密钥，不改变生产路由。记录每次本地 HTTP 状态、延迟、Token（若服务返回）和解析结果。

## 裁决边界

本补充只修复来源覆盖不足的项目。两模型都来自同一 Ollama 运行时，视为不同权重的辅助意见，不宣称统计独立或独立人类验收。协议失败和无法解析的结果保留并排除出质量分母；不以运行成功替代裁决成功。
