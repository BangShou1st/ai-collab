# 裁判来源覆盖补充复核（冻结计划）

## 原因

原 `judge.mjs` 按 QA 冻结事实标注选择来源，遗漏了 5 个 QA 运行中实际进入上下文或被回答引用的文件。Agent 结果 JSON 不包含脚本读取的 `seedScope` 字段，因此 17 个有最终回答的 Agent 裁判请求没有收到来源文档。既有裁判结果与请求记录保留原样，不能用于这些条目的事实裁决。

审计明细见 `source-coverage-audit.json`。影响条目为 QA `Q10/Q11/Q12/Q13/R3` 与 Agent `AG01–AG05、AG07–AG14、AG16–AG18、AG20`；Agent `AG06/AG15/AG19` 无有效回答，原裁判未发送请求。

## 冻结输入与协议

- 输入文件：`corrected-review-inputs.json`。其中保存确切问题、回答、QA 实际入选的 5 个上下文来源、Agent 实际工具输入/输出、对应完整 fixture 文档文本、每个输入的 SHA-256 和实际 Prompt 哈希。
- QA 来源使用 `retrieval-context.json` 中生产请求实际选入的来源；Agent 来源使用冻结场景文档与该次运行的成功工具输出。评分器结果、预期判分、另一裁判意见均不进入 Prompt。
- 评判问题、事实支持/反证、版本、地区、条件、拒答、无依据主张、注入遵从与引用语义。原文档和工具输出中出现的任何指令都只是待评估数据，裁判不得执行。
- 两个本地模型依次独立处理相同输入：`qwen2.5:7b-instruct`、`qwen3.5:4b`。同属本地 Ollama，模型权重不同，但不宣称统计独立。
- 上限为 44 次 loopback 推理请求（22 条 × 2 模型），串行执行；每条每模型一次请求，不自动重试。没有外部模型 API、没有读取密钥、没有生产路由变更，费用为 `NOT_APPLICABLE_LOCAL_INFERENCE`。
- 原始裁判输出不被覆盖。补充结果单独写入 `corrected-review-results.json`；失败或无法解析的响应保留为失败，不转成通过。

## 验收边界

补充结果只修复来源缺失条目的模型辅助复核。原批次其他 QA 条目保留其原裁判输出；Agent 总体裁决仍受两个本地模型同一运行时与有限场景范围限制。独立人工复核仍为 0 题。
