## 二、十项核心问题逐一回答

### 1. 三个截断失败的真实原因分别是什么？
- **AG06（差旅加班住宿费）**：推理模型 `nvidia/nemotron-3.5-lightning:free` 的思维链（`reasoning_tokens`）占用了约 900~1400 tokens，叠加长检索上下文后，模型生成总 completion tokens 触碰了测试夹具设置的 2000 硬上限，触发 Provider 返回 `finish_reason: "length"`。适配器 `KiloGatewayModelExecution` 无条件抛出异常，应用层 `AgentRuntimeCoordinator` 将其判定为不可恢复错误导致失败。
- **AG15（电子发票规定拒答）**：多轮检索后上下文膨胀，模型在组织详尽拒答时思考链膨胀，触碰到 2000 token 输出配额边界，导致协议截断。
- **AG19（内部审计抽查数量拒答）**：经历了 4 轮连续工具检索，输入 context 膨胀至 2.4 万 tokens，模型在第 5 轮总结时思维链达到 1496 tokens，处于 2000 临界边界，在 P10-03 时偶发超限导致截断。

### 2. 哪些缺陷已经复现、修复和验证？
- **观测性缺口已修复**：为 `KiloGatewayTransport` 增加了深度请求与原始响应拦截，完整记录上游原始报文、`finish_reason` 与 `usage` 明细。
- **真实链路已复测验证**：在相同生产链路与模型下，AG01、AG06、AG15、AG19 全部实现 `SUCCEEDED` 闭环，生成了完整正确的业务答案与诚实拒答。
- **评分器数字误报机理已查明**：证实 17 项数字候选均为 Markdown 列表序号、UUID 片段或相似度小数，无业务数字幻觉。

### 3. 复测成功多少次，失败多少次，是否存在未解决情况？
- **复测场景**：4 个（AG01 对照组、AG06、AG15、AG19）。
- **外部模型调用**：11 次，**11 次全部成功（11/11 HTTP_RETURNED）**。
- **场景终态**：4 个全部为 `SUCCEEDED`，失败 0 次。
- **未解决情况**：免费推理模型的思考链占用补全配额属于模型架构特性，在单次输出预算极紧（如 ≤2000）时仍存在偶发截断风险，生产环境需确保 `max_output_tokens` 维持在 4000 以上。

### 4. 41 项待复核中，有多少得到确定性解决、多少仍需人工判断？
