# 剩余门禁与回滚

当前为 **PARTIAL_ACCEPTANCE / NO PRODUCTION GO**。目标生产环境至少需要：

1. 域名、可信 TLS 证书链、续签和外网 IPv4/IPv6 端口扫描；若使用 CDN/上游代理，重新设计并验证信任边界。
2. 服务器、私有网络、防火墙、容量、独立 MinIO 应用身份和私有桶；验证目标 Linux 主机 UID/GID 与备份目录权限。
3. 安全下发各独立生产密钥，离线加密备份原模型主密钥及恢复责任；不得直接替换存量主密钥。
   空库的首位系统管理员目前没有生产引导流程：需要安全迁入现有管理员或另行实现并验证受控引导，不能使用 local 演示账号充当生产管理员。
4. 安设备份计时器、独立故障域复制与真实接收人的告警通道；测量异机恢复、RPO、RTO 和有效保留期。
5. 在本次提交 SHA 上跑完整 CI（包括 Image build & container smoke），由 GitHub 管理员配置所需 required checks 并确认；不由 Agent 修改仓库保护。
6. 经明确额度授权后验证真实 Provider/Embedding、文档解析索引检索与引用、Agent 模型回合；验证生产拓扑的 SSE、容量与发布/回滚。
7. 由具备权限的负责人记录风险接受与最终发布批准；责任人、时间和环境当前均未指定。

回滚必须区分旧镜像回退和数据恢复：先保留脱敏证据及备份；仅在数据库迁移向后兼容时使用记录的旧 digest 回退并复测。数据不一致时先恢复到隔离实例，对账后由负责人决定前滚或授权切换。禁止覆盖源业务卷、修改历史 Flyway、手工改 checksum 或执行 `docker compose down -v`。操作流程详见 [生产部署手册](../../../deployment/production-foundation.md)。

本 P0 没有开发飞书 Connector 或更改文档 ACL；仅在 P0 门禁通过后另行设计授权范围和试点。
