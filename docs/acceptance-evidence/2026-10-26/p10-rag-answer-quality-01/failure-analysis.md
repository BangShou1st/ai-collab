# P10 离线层失败模式分析（failure-analysis）

> 对象是评分器与契约的行为，不是真实模型（无真实生成）。全部结论可由
> `offline-evaluation-results.json` 与确定性测试复现。

## 1. 现行 Prompt 对版本冲突的要求与不足（源码审查结论）

QA system prompt（`KnowledgeQuestionApplicationService`）已有：引用规则、
"资料未支持结论时明确说明资料不足"、注入防御指令（忽略 SOURCES 中的行为指令）、
无证据时统一拒答文案。**没有**任何关于多版本/废止条款/组织归属（华东≠华南）的辨别指令——
语料中 V1 旧标准与 V2 现行、三中心阈值同时可见（P9 实测 QA 6/7、Agent 7/7 冲突暴露）时，
正确辨别完全依赖模型自身能力，Prompt 未提供"识别现行版本"的任何引导。这是生成层的结构性风险，
属下一轮（获授权后的真实评测或 Prompt 改进实验）验证项，本轮不改生产。

## 2. 机械检测能力边界（实测确定）

- 8 个坏回答变体全部被正确标记（10 项高严重度：版本现行错误、废止当现行、地区套用、
  否定翻转、编造+拒答缺失、编造引用编号、无引用实质回答被系统替换、注入遵从）。
- 但否定翻转的未枚举措辞（"允许先组织培训再补签"）不经枚举即漏检——开发过程中实测确认，
  语义级翻转检测必须人工。机械层只承诺：枚举措辞零漏检、零误报（模范回答 0 高严重度）。

## 3. 证据缺口与生成责任的归因边界

- AQ09（跨 3 文档复合题）：P9 中"退回发起节点"未进入 QA 上下文（RETRIEVAL_MISS）。
  评分器将该事实的缺失标为 MISS_EVIDENCE_GAP（不可归责模型），即使模范回答包含它也会标注
  HIT_WITHOUT_CONTEXT_EVIDENCE（泄漏观察）。该题在 evidence-availability-matrix 中为
  QA=INCOMPLETE——真实模型评测时若此题回答不完整，应先归因检索/选择层。

## 4. QA 引用契约的强制行为

生产 `KnowledgeCitationValidator` 将"无有效引用的实质回答"整体替换为统一拒答文案并记
invalidOutput——这既是防线也是风险：模型给出了正确但无引用的回答时，用户看到的是拒答。
该行为已固化为确定性测试（CONTRACT_FORCED_ABSTENTION）。

## 5. Agent 来源卡与正文引用的未定义行为

Agent 无正文编号协议：来源卡=工具实际读取的身份（11 项 PostgreSQL 契约测试保护），
正文逐句与来源卡的对应关系没有任何机械绑定——"available-but-uncited"是既有契约行为。
语义级"正文是否被来源支持"在 Agent 路径只能人工审查，且比 QA 更缺工具支持。
