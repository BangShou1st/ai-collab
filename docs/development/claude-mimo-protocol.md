# Claude + MiMo V2.5 开发协议

## 核心原则

Claude 是主开发者和最终责任人；MiMo 是受限代码执行器。MiMo 不做产品、架构、数据、权限、事务或接口决策。

一个任务只有在 Claude 能明确回答以下问题后才能开始：

- 用户最终能完成什么操作？
- 哪些角色可以执行？
- 项目和子资源如何隔离？
- 哪些状态允许读或写？
- HTTP、Java、OpenAPI 和 TypeScript 契约是什么？
- 失败时返回什么稳定错误码？
- 哪个测试能证明旧行为错误、哪个验收能证明新行为可用？

## 职责矩阵

| 工作 | Claude | MiMo |
|---|---:|---:|
| 澄清需求和非目标 | 必须 | 禁止 |
| 设计数据库迁移和约束 | 必须 | 禁止 |
| 设计权限、状态机、事务、并发、幂等 | 必须 | 禁止 |
| 设计或修改 API 契约 | 必须 | 禁止 |
| 跨模块实现完整功能 | 可以 | 禁止 |
| 单个纯函数或 DTO/View/type | 可以 | 受限允许 |
| 沿用现有模式的单个 API 方法 | 可以 | 受限允许 |
| 已指定断言的局部测试 | 可以 | 受限允许 |
| 枚举中文映射和局部文案 | 可以 | 受限允许 |
| 删除文件、Git、提交、分支 | 可以按规则执行 | 禁止 |
| 最终审查和全量验证 | 必须 | 禁止 |

## MiMo 任务准入

同时满足以下条件才可委派：

1. 只改 1–2 个明确文件。
2. 不新增数据库表、字段、迁移或依赖。
3. 不改变权限、事务、状态转换或错误语义。
4. 不需要在两个模块之间选择架构方案。
5. 输入、输出、函数签名和验收命令已给出。
6. Claude 能在短时间内逐行审查全部输出。

任一条件不满足，由 Claude 实现。

## 发给 MiMo 的固定格式

```text
任务：<一个局部动作>

允许修改：
- <精确路径>

禁止修改：
- 除允许列表外的所有文件
- 数据库迁移、权限、事务、OpenAPI、Git

现有参考：
- <同仓库参考文件和函数>

必须保持的接口：
- <完整签名或 TypeScript 类型>

实现要求：
1. <可观察行为>
2. <边界条件>
3. 不使用 any、非空断言、空 catch、硬编码假数据。

验证：
- <精确命令>
- 期望：<具体结果>

输出：
- 仅给出修改说明和 diff。
- 如参考实现与任务冲突，停止并报告，不自行决定。
```

## MiMo 停止条件

MiMo 遇到以下情况必须停止：

- 需要修改允许列表以外的文件。
- 现有接口与任务描述不一致。
- 测试失败原因不属于本次局部改动。
- 需要选择新的错误码、状态、权限或事务方案。
- 需要删除、重命名或跨模块搬迁代码。
- 只能通过弱化断言、增加 `any`、吞异常或假数据才能通过。

## Claude 审查清单

收到 MiMo 输出后，Claude 必须：

1. 检查 `git diff -- <允许文件>`，确认没有越界。
2. 对照参考实现检查命名、返回类型、错误处理和中文文案。
3. 确认没有 `any`、空 catch、忽略错误、调试日志或敏感数据。
4. 运行局部测试并读取完整输出。
5. 运行类型检查或编译，捕获跨文件契约错误。
6. 必要时由 Claude 修正，不能把复杂返工继续交给 MiMo 猜测。
7. 完整功能闭环完成后执行全量验证。

## 推荐协作顺序

```text
用户需求
  → Claude 调查代码和事实
  → Claude 写规格与任务模板
  → Claude 实现架构、权限、事务和契约骨架
  → MiMo 仅补局部机械代码
  → Claude 逐行审查
  → Claude 集成、测试、构建、冒烟
  → Claude 更新权威文档并提交
```

## 失败示例

不要把“实现文档知识库”交给 MiMo。这包含存储、事务、异步处理、向量检索、权限和多个接口。

可以把以下任务交给 MiMo：

```text
在 ai-collab-frontend/src/shared/display-labels.ts 中，
按同文件已有映射模式增加 DOCUMENT_REINDEX_REQUESTED 的中文标签。
只改该文件；未知值回退规则保持不变；运行 pnpm test。
```
