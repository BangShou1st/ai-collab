# Claude 单功能任务模板

将下面整段复制给 Claude，先填写尖括号内容。一个模板只对应一个可独立验收的功能或缺陷。

```text
# 任务名称
<简短、可观察的结果>

## 用户问题
<当前错误、缺失能力或完整操作步骤>

## 目标
- <完成后用户可以做什么>

## 非目标
- <明确不做的相邻能力>
- 不进行无关重构。

## 事实依据
- 必读：AGENTS.md
- 当前能力：docs/feature-matrix.md
- 功能指南：<docs/development/guides/...>
- 接口：docs/api/openapi.yaml
- 相关源码：
  - <精确路径>

## 允许修改
- <精确文件或目录>

## 权限与隔离
- 允许角色：<OWNER/ADMIN/MEMBER/SYSTEM_ADMIN>
- 项目隔离：所有子资源使用 projectId + entityId。
- 非成员语义：PROJECT_NOT_FOUND。

## 状态规则
- <状态 A>：<允许行为>
- <状态 B>：<拒绝行为和错误码>

## 接口契约
- Method/Path：<例如 POST /api/v1/projects/{projectId}/...>
- Request：<字段、类型、必填、范围>
- Success：<HTTP 状态、View 字段>
- Errors：
  - <ERROR_CODE> → <HTTP 状态和中文消息>

## 数据与事务
- <表、约束、版本或幂等方式>
- 外部网络调用不得位于数据库长事务。
- 已提交迁移不修改；如需结构变化使用下一个版本。

## 实现步骤
1. 写失败测试并确认失败来自当前缺陷。
2. 实现后端领域规则和应用服务。
3. 同步 Controller/DTO/View、ErrorCode 和 OpenAPI。
4. 同步 TypeScript type、API、中文错误和页面。
5. 运行局部测试、全量测试、类型检查、构建和冒烟。
6. 更新 feature-matrix 和相关指南。

## 必写测试
- <测试名称>：<捕获的具体错误>
- <权限或跨项目测试>
- <状态或并发测试>
- <前端成功/错误/空状态测试>

## 验收
- <真实操作步骤和可观察结果>
- 不接受“代码已修改”作为验收。

## MiMo 使用
- 默认不使用。
- 如使用，只允许：
  - <1–2 个精确文件>
  - <完整函数签名和参考实现>
- 禁止迁移、权限、事务、OpenAPI、跨模块重构、删除文件和 Git。

## 停止条件
- 需要扩大允许文件或改变已确认契约时先报告。
- 同一根因连续三次修复失败时停止并重新审查架构。
```

## 使用要求

- Claude 必须先核对模板中的路径和当前代码；路径不存在时不能臆造替代实现。
- 任何接口改动都必须执行 `api-contract-checklist.md`。
- 缺陷的第一个有效验证必须是旧实现失败、新实现通过的同一个测试。
- 验收必须包含真实 HTTP 或用户操作，不能只依赖 mock。
