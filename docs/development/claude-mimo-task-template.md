## 严格执行顺序

1. 用不超过 15 行报告代码证据和差异，不等待再次确认。
2. 写一个能证明缺口的最小失败测试，运行并记录真实失败。
3. 只实现使该测试通过的最小改动。
4. 运行相关测试；失败时先定位根因，不绕过或删除测试。
5. 补前后端联调入口、中文显示、权限和错误处理。
6. 同步 OpenAPI、功能矩阵和直接相关文档。
7. 运行完整验证。
8. 检查 diff，只保留本任务改动。

## 禁止 MiMo 执行

- 禁止声称没有运行过的测试“已通过”。
- 禁止用 `any`、空 catch、硬编码成功数据、跳过权限或删除断言让测试变绿。
- 禁止先按全局子资源 ID 查询再补项目校验。
- 禁止把模型输出直接写入数据库。
- 禁止在事务中调用外部模型或对象存储。
- 禁止输出密码、Token、Cookie、API Key、邀请码或 `.env` 内容。
- 禁止把“建议”“占位 TODO”“只有后端”写成已完成。
- 禁止改动范围外文件；如确有阻塞，先报告具体文件和原因。
- 禁止自动安装大依赖或改变技术栈。

## 必须验证

```powershell
# 按本任务选择相关测试，最后必须运行全量
Set-Location ai-collab-backend
.\mvnw.cmd test
.\mvnw.cmd clean package -DskipTests

Set-Location ..\ai-collab-frontend
pnpm test
pnpm typecheck
pnpm build

Set-Location ..
.\scripts\smoke-existing.ps1
git diff --check
git status --short
```

如果某项与任务无关或环境阻塞，必须给出实际命令、退出码和具体原因，不得用“理论上通过”代替。

## 最终输出格式

只报告：

1. 已完成的用户闭环；
2. 权限、事务和并发决定；
3. 修改文件分类；
4. 实际验证命令与数字结果；
5. 仍未实现的相邻功能；
6. 当前 `git status --short` 中属于本任务和不属于本任务的内容。

---

对大型需求，先拆成多个模板任务。推荐每个任务控制在：一个迁移、一个后端用例、一组 API、一个前端入口和对应测试；不要把“完整 Agent”作为单次编码任务。
