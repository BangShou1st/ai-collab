# Agent 最终来源与引用契约

## 三个不同集合

| 集合 | 含义 | 可机械验证的范围 |
| --- | --- | --- |
| AVAILABLE_SOURCE | 本运行或子研究的成功工具读取后实际移交，且收口时身份仍合法的来源 | 持久化步骤、项目、文档/分块身份及状态；最多展示 50 项 |
| EXPLICITLY_CITED_SOURCE | 最终正文按明确契约指向的来源 | Agent 当前没有统一编号映射或强制的文本身份语法，不能从卡片顺序推导 `[S1]` |
| CLAIM_SUPPORTED_SOURCE | 某个结论得到原文支持 | 需要人工或独立语义审查；来源存在、编号合法和关键词命中均不能替代 |

QA 使用上下文 rank 与 `[S1]` / `[S1, S2]`，由 `KnowledgeCitationValidator` 校验并持久化实际引用来源。Agent 是独立契约：`AgentCitation` 的 documentId、chunkId、filename、heading、pageNumber、quote、similarity 来自工具，前端折叠区域展示“来源”，不是“语义已验证”。父子研究提示词要求给出 documentId/chunkId；通用助手提示词要求区分事实、推断、冲突和缺口，但没有全局稳定的 S 编号协议。

## 收口时的最小保证

`AgentRunEventRecorder.recordFinal()` 从本运行成功持久化工具结果取得来源。子来源还必须匹配本父运行 `DELEGATION_COMPLETED` 的持久化引用，并重新检查当前文档身份：向量分块所属文档必须 READY，正文分块所属文档不得 DELETING。采用持久化的原始摘录，拒绝移交参数中的替换文本。未知、删除、跨项目、身份不匹配的来源不能产生最终来源卡。

`resumeParent()` 只从子运行成功的工具读取中生成移交来源；子运行随后失败或取消，不应抹去这些已经取得的合法资料。保留其 AVAILABLE_SOURCE 身份，不等于把失败子运行的结论标记为已验证。失败工具本身不贡献来源。

子来源校验最多增加一条参数化 SQL，最多检查移交列表前 50 项，最多返回 50 个不同 chunkId；只在有移交引用时执行。查询通过 run_id 索引定位父运行步骤，源表用 UUID 主键 `ANY` 的最多50项过滤，再核对持久化 chunk/document 与项目身份，避免仅以 UUID 转文本比较扫描源表。已有直接来源优先，按 chunkId 去重，最终总上限仍为 50。后续不改写历史消息或模型正文，也不增加模型请求。

本保证沿用当前检索块/正文块的有效性规则，不能证明结论语义支持、版本业务有效性或并发删除之后的永久可用性。没有统一的 Agent 编号协议时，资料正文中的 `[S999]` 保持原文；不将其按 QA 规则静默删除，也不声称它已经通过引用校验。

## 后续产品设计

若需要正文与卡片一一对应，应先定义工具调用间、父子运行间、50 项截取后的稳定引用 ID，以及摘录/代码块中同形字面的转义规则，再增加显式引用集合。当前不新增响应字段，不改变前端展示，不把 AVAILABLE_SOURCE 重命名为语义支持。

实现与反例见 [P8 修复实验](../acceptance-evidence/2026-10-25/p8-rag-quality-fix-01/README.md)。
