# Agent 配置切换、过程说明与恢复设计

日期：2026-10-05。依据当前 d5f09ab 工作区代码及已完成的存量精简。本文件为方案，不代表下述能力已经实现。本轮仅调查和编辑设计文档，未修改业务代码。

## 1. 已确认需求与当前差距

- Agent 中途可以换模型，以用户当前 AGENT 用途配置为准。
- 执行过程中应有简短、自然的过渡说明，并显示真实工具活动与最终回答。
- 自动重试、崩溃恢复、暂停继续属于基础能力，简化不得删掉它们。
- 暂停 Agent 的后续动作；已经受理的后台规划继续完成，恢复时读取原结果。
- 保留现有 Java 应用、权限和业务操作身份；以必要改动满足需求。

当前 AgentModelConfigurationStore 固定首次模型配置 ID 和更新时间，配置编辑会让旧运行失败；这与本次需求冲突，应改为每轮读取当前配置。当前中途正文已存在 ModelTurnResult.content 和 agent_step.output_json 中，但 MODEL_COMPLETED 主要传递完成元数据，页面活动也隐藏这类正文。最终回答已有展示；按轮次的过渡说明与逐字流式展示是两个不同改动。

## 2. 模型切换：只在模型请求边界读取配置

1. 准备一轮新模型请求时，按 requesterId + AGENT 用途读取当前配置：用途指定优先，否则默认配置。
2. 该轮的模型能力、工具协议、输出参数、可选窗口限制和实际出站调用使用同一份配置，避免准备按 A、调用按 B。
3. 已发出的请求继续按原参数结束。配置编辑、默认配置或用途分配变化，在下一轮准备请求时生效。
4. 自动重试和暂停恢复后的下一轮，也重新读取当前配置。
5. 换模型不清空目标、有效约束、工具结果、审批、已用额度和重试次数，不创建新 run。
6. 已持久化的模型结果和待处理工具清单先按原调用身份恢复，不因为换模型重新请求或重做业务效果。
7. 每轮重新核对模型能力。CHAT-only 模型使用已有只读路径；需要原生工具能力而当前配置不具备时，给出明确能力限制。模型切换不授予项目权限，也不绕过审批。
8. 配置删除、禁用或无法连接，沿现有错误分类处理，不自动选择其他模型。用户改好配置后使用相应恢复或重试入口。

历史继续使用统一 ModelMessage 和已保存调用结果，由新适配器按其协议重新序列化，不直接发送旧提供商的请求 JSON。运行事件携带这一轮实际采用的模型与能力，前端由此更新当前模型提示；不新增全局配置广播或轮询服务。

实现方向：修改现有配置读取入口的语义；复用 AiConfigurationContext 保存该次准备与调用采用的配置，不新增模型路由引擎或型号策略库。若一次 advance 包含辅助摘要和主调用，两次出站各有清晰配置边界；主调用前重新确认配置，变化时重算能力和输入容量，采用有界准备，不在旧预算下直接换模型发送。

agent_run.model_configuration_* 可保留为最近使用配置的诊断信息，失去限制后续选择的作用。已有模型轮次继续记录实际 provider/model；历史结果不会因配置变化改写。本需求只改变 Agent 策略，独立后台规划继续按自己的 generation/attempt 身份推进，不因 Agent 换模型被取消。

## 3. 过程说明：复用已有模型正文与事件

用户看到的顺序应是：

> 你：检查这周任务是否影响交付。
>
> Agent：我先查看未完成任务，再核对里程碑。
>
> 工具活动：读取项目任务、检查里程碑。
>
> Agent：发现两项延期任务，接下来核对负责人和截止日期。
>
> 工具活动：读取任务详情。
>
> Agent：最终结论、依据和建议。

第一项交付采用轮次级说明：

- 模型一轮同时返回正文和工具调用时，将正文作为该轮说明展示；正文为空则只显示真实活动，不强制增加一句旁白。
- 提示只要求必要时简短说明当前动作或阶段发现；不要求每次调用写固定格式，也不另发模型请求生成旁白。
- 说明表示模型表达的意图或阶段判断，工具结果和已受理操作决定实际执行事实。说明本身不能改变运行状态或作为证据。
- 复用持久化 MODEL_COMPLETED 事件，增加面向用户的说明字段，以 stepSequence 对应原模型轮次。正文与模型轮次的落库采用同一事务，前端按事件序号重放。
- 收敛当前记录端和协调器重复发出的 MODEL_COMPLETED，保留一个持久事实来源。最终无工具回答继续使用已有 ASSISTANT 消息，避免重复展示。
- 前端按轮次说明和工具事件的顺序组织内容；普通说明复用文本展示，工具活动可展开。不把所有工具聚在一起、所有说明再放在最后。
- 不复制一套 agent_message/过程说明表。刷新从已有事件与模型记录恢复，遵守原项目、会话、运行作用域与去重规则。
- 展示普通 assistant 正文；不渲染 reasoning_content、协议 JSON 或原始工具参数。

逐字流式作为紧接其后的独立交互改动：在现有模型调用链增加正文片段回调，经现有 SSE 通道更新当前轮的临时文字；完整轮次落库后以持久结果替换。临时片段不逐 token 写数据库，断线重读已完成轮次；中断或失败时标明未完成，不把半截文字当最终结果。工具参数收齐并校验、完整模型轮次持久化后，才执行工具。每次模型调用用已有调用身份关联片段，避免失败重试时两份文字拼接。

首轮按轮次说明即可独立收尾；不把所有提供商逐字流式、恢复和暂停绑定成一个发布门槛。

## 4. 框架判断

现在继续现有 Java 链路，不在这轮引入整个 Agent 框架。

LangChain 的 Agent 模型循环、动态模型入口、进度更新与正文流是有价值的设计参照。LangChain4j 的 AI Services 可以减少模型、工具、记忆与 RAG 的编排代码，但本项目已经具有对应入口，权限、审批、业务版本及持久操作仍需要应用自己维护。当前引入会增加一轮状态和协议迁移；这是根据本项目代码作出的判断，不是框架能力不足的结论。

以后只有出现一个明确重复模块，并能实际替换它时，再评估局部采用库。例如替换一段模型适配而保持业务网关契约；不再同时保留两套常规 Agent 执行状态。此项不是当前交付前置条件。

## 5. 其余基础能力的最小设计

### 自动重试

沿用 Agent 已有最多两次、30 秒间隔的自动模型补救；补齐后台规划的临时网络/提供商失败补救。认证、缺少权限、额度耗尽、输入超限等需要外部修正的错误不盲目重试。格式修复保留自己的有限次数，因为需要携带不同反馈。

重试判定集中在现有应用层。已有数据库失败次数与已安排重试次数语义不同，先明确用途，不直接删掉其中之一。HTTP 默认单次调用保持明确，避免新增两层各自自动重试。重试沿用原业务操作、来源和 generation 身份；若需要新 attempt，原 operation 继续关联同一 generation 的该次尝试。被取消、被替代的尝试不能继续派发或借用新身份提交。

前端根据实际持久状态显示“将在稍后重试”或“已失败”；协调器不能在重试额度用尽后仍发 retryable=true 覆盖真实终态。Agent 换模型后重试使用当前配置；本轮不扩展独立规划生成中的模型切换规则。

### 崩溃恢复与计时

复用 agent_run、agent_step、agent_tool_invocation 和 agent_planning_operation。仅增加必要的持久存活时间，心跳按原 claim 身份续租，不增加业务 version。正常结束累计实际工作时间；崩溃接管只计到最后持久存活时间，停机等待不耗执行时间。

接管先读取已有模型轮次与调用结果，核对已经受理的业务操作；完整无工具回答也应完成原结果的收口，不能因此再请求一次模型。旧 worker 提交依旧由租约和 claim 身份拒绝。工具线程需要显式传递同一 claim 身份，不能依赖父线程的 ThreadLocal 自动传播。

### 暂停与继续

最小新增为 PAUSED 状态和暂停意图，复用现有租约与模型/调用记录。

- 排队运行可直接暂停；正在执行的运行记录暂停意图，当前调用结束并保存结果后暂停，不再启动新动作。
- 通过原运行锁确定暂停与新业务受理的先后，已受理动作完成原事务；暂停先到时不启动该动作。
- 释放运行租约，保留待处理调用，不把它们全部标为 SKIPPED。
- resume 将原 run 转回 QUEUED，不重置目标、额度或已完成记录；下一轮模型读取当前配置。
- 已受理后台规划继续完成，恢复核对原 operation 并读取结果。
- 普通“继续”在唯一对应当前目标的暂停运行时走同一 resume 命令；控制消息不覆盖 latestRequest。审批和等待用户回答继续走原入口。

第一版为调用边界暂停，页面说明“正在暂停，当前调用结束后保存进度”。立即中断、任意子运行全树暂停不列入这一项验收。

### 预算与到限处理

统一现有有效限额的计算来源和创建/重试的来源，明确运行记录与系统硬上限的关系，先保持实际限制不变。完整请求估算包含工具定义和额外指令；使用剩余空间装上下文，替代盲目的 0.6 比例重组。项目集合按范围和稳定顺序有界读取，并告知总量与未读范围；继续使用已有 RAG 和按需章节读取。

输入必需内容仍放不下时说明需要缩小范围；运行额度耗尽时展示已完成、未完成和原因。累计用量记录继续支持运行保护，精确费用边角继续为待办。

跨运行“继续剩余工作”单独设计交付：沿用旧业务操作和结果，给予明确的新运行额度，避免重复业务效果。当前派生重试创建新运行，不可在完成该能力前更名为断点续跑；本轮不新增通用 checkpoint 表或恢复阶段状态机。

## 6. 实施顺序与独立验收

| 顺序 | 改动 | 必须验证的用户结果 |
| --- | --- | --- |
| 1 | Agent 按当前配置切换；轮次级过程说明 | A 请求在途改成 B，A 结束后下一轮用 B；目的/结果/额度不丢；说明与工具按序出现、刷新不重复、最终回答只展示一次 |
| 2 | 自动重试与终态显示 | 临时故障后继续原操作；耗尽次数准确终止；取消/重新生成后旧结果不能落入新身份 |
| 3 | 崩溃恢复计时 | 隔离宿主真实中断后可以继续；停机不耗额度；已提交业务动作不重复；旧 worker 被隔离 |
| 4 | 动作边界暂停继续 | 模型/部分工具已落库后暂停恢复；重复命令幂等；暂停与完成竞争；后台规划完成后读取原结果；换模型后使用最新配置 |
| 5 | 请求体积与限额来源收敛 | 工具定义占主要输入和大项目集合；当前请求与有效约束完整；没有静默宣称审查全部资料 |
| 独立交互项 | 正文逐字流式 | 断线/重试/切换会话不拼错文字；已完成正文可重读；半截文字不当最终回答；未完成工具参数不执行 |
| 后续独立能力 | 到限后的剩余工作续接 | 已完成业务效果不重做；剩余范围和新额度明确；并发继续不会创建重复业务结果 |

相关改动分别收尾，不强制反复重跑完整 24 轮。数据库竞争用真实 PostgreSQL；页面验收统一走 browser-skill/bsk。没有新失败证据时不扩展精确计费、型号校准、自动换模型、通用工作流或通用中文语义识别。

与早先预算/恢复草案冲突时，本文件中的用户要求与实施顺序优先，尤其是 Agent 每轮使用当前配置和基础恢复优先。
