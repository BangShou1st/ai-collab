## 4. B：正文流式的最小设计

### 4.1 沿用完整模型轮次链路

目前 Agent 主调用链是：

`AgentRuntimeCoordinator → RoutingAgentModelExecutor → NativeToolCallingExecutor → ModelTurnGateway / RoutingModelTurnGateway → ModelTurnProviderAdapter / ZenModelExecution → provider adapter`。

OpenAI 兼容适配器已经有 SSE 聚合路径，Zen 的 `turnWithSession` 也在内部读流，但正文未逐步传到 Agent 页面。优先在现有完整轮次路径增加一个明确、轻量的正文观察接口/回调；仍聚合并返回原 `ModelTurnResult`，完整工具调用仍在流结束、解析及校验之后进入现有执行链。

**不能把 native tool turn 换成普通 `completeStream`**，否则会丢失工具协议。不要通过额外的模型请求生成旁白或重写回答，也不要让 UI 建立新的执行循环。

本轮至少打通现有实际使用的 OpenAI 兼容/Zen 原生路径。其他 adapter 或 Legacy 模式缺少可靠正文流协议时，保留一次性完成展示，并明确记录支持范围；不默默换模型，也不把完整响应拆成定时动画冒充实时生成。不要为全 provider 全协议适配扩展本轮。

### 4.2 展示片段与已提交事实分开

推荐复用现有、已经鉴权的 Agent SSE 连接增加**临时正文帧**，与持久 `AgentRunEvent` 明确区分；如代码核对后有更简单可靠的方案，可用等价实现并说明原因。

- 正文帧只用于当前请求的实时展示，不逐 token 写 `agent_event`、消息表或步骤表，不递增持久事件序号。
- 前后端解析要区分临时帧与持久事件；临时帧不能更新 `timeline.lastSequence`、`afterSequence` 或 `Last-Event-ID`，也不能改变权威运行状态。
- 复用 `beginModelCall` 创建的 **modelCallId** 绑定请求。必要时给现有 `MODEL_STARTED`/`MODEL_COMPLETED` 补兼容字段，把预览与完整结果关联；历史事件缺字段时仍按旧规则恢复。
- 临时内容按 `projectId + runId + modelCallId` 隔离，使用请求内顺序或等价方式防止重复/过期片段拼接。新请求不能追加到上一次失败的正文上。
- 正文观察与 SSE 写失败不能把模型调用误判为 provider 失败，不能触发额外模型重试；慢订阅者或关闭页面也不能拖死、取消持久 Agent 工作。
- 请求结束、失败、取消、暂停确认或被新 claim/新请求取代后关闭对应预览生命周期。旧 worker 迟到片段不能继续污染当前视图；沿用现有 lease/claim 语义设计最小的身份有效期检查，不为每个 token 加数据库事务。
- 不承诺断线恢复完整的未提交正文。刷新或重连恢复已提交消息/事件；同一在途请求可从后续片段继续预览，也可暂时回到分析提示。不能因浏览器重连而再发一次模型请求。

`AgentEventService.append` 是持久事件入口，不能用它存每个 token。`AgentEventStreamService` 可承担轻量临时帧发布；不要增加 Redis 消息总线或另一套调度平台。现有进程内 SSE fanout 的部署边界如实记录，不在本轮扩大成多实例改造。

### 4.3 完整响应仍走唯一收口入口

流结束后，完整 `ModelTurnResult` 继续走现有校验、`recordModelTurnWithSettlement`、`afterResponseSaved` 和文本/工具分派。SSE 传输结束本身不代表业务成功。

- 临时正文不进入下一轮上下文、摘要、工作状态或审批提案。
- 带工具调用的正文在提交后成为现有过渡说明；只有工具名和参数完成聚合并通过现有规则后才执行工具。
- 纯文本响应提交、消费并形成最终 ASSISTANT 消息后，替换或收敛同一预览位置，最终回答只出现一次；不要“流式气泡一份、最终卡片又一份”。
- 澄清、预算部分回答等按现有落库及分派规则呈现，不把 `MODEL_COMPLETED` 一概当最终成功。
- 截断、解析失败、提供商异常或落库失败时，预览不能变成成功答案；最简单可丢弃并显示现有失败/重试提示，若保留则必须明确是未完成内容，不纳入已完成回答。
- `UsageCarryingFailure` 的已收到用量透传、原错误码、格式修复、重试计数和一次性结算都要保留。本轮只防退化，不继续优化精确计费。

### 4.4 前端效果与内容边界

复用 `AgentView.vue`、`use-agent-workspace.ts`、`agent-event-stream.ts` 和现有活动/消息展示，不大改页面布局：

- 主对话内自然增长的正文，工具活动仍按真实事件穿插；无正文的工具轮不编造过渡文字。
- 仅展示普通 `content`；不泄漏 reasoning/thinking、工具参数 JSON、Legacy 决策 JSON、摘要正文或系统控制标记。`[QUESTIONS]` 等按既有语义处理，不能把协议原样流给用户。
- 未完成 Markdown 可先用安全文本或现有安全渲染方案；最终沿用 `marked + DOMPurify`。不引入第二套 Markdown 渲染器，不因分片插入产生脚本/外链图片执行。
- 项目/会话切换、A→B→A、切换运行、卸载与恢复代次变化都丢弃过期展示副作用；订阅换过去后旧片段不回来。
- 沿用同 run 稳定活动 key、展开和焦点保持；只有用户位于底部才自动跟随，向上阅读保留位置及“查看新内容”。
- 按需合并短片段降低重绘，有长度/内存上限并复用现有展示边界；预览到上限仅停止追加展示，不擅自中断模型或改运行预算。不新建复杂动画/缓冲框架。

## 5. 有限但完整的验证矩阵

先做受影响回归，最后做一次后端全量、前端全量及类型检查。出现新失败先定位根因，不靠宽泛放宽断言或删掉历史守卫。

| 边界 | 必须证明 |
| --- | --- |
| 真增量 | 一个模型请求至少两段普通正文在完整结果提交之前进入前端；完整结果仍只保存/消费一次 |
| 内容与工具混合 | 正文增量可见，工具参数分片及 reasoning 不可见；工具仅在完整校验后执行；纯工具轮仍正常 |
| 失败及自动重试 | 已有正文后截断/异常不落成成功答案；原错误及已收到用量保留；重试新 call 不混旧文本；等待重试时无旧“正在分析” |
| 暂停与配置切换 | 暂停意图不截断已准入展示；暂停确认后无新请求；续跑、下一请求按当前配置，已保存结果和调用不重做 |
| 恢复与去重 | 刷新/重连不新增模型请求；已保存响应的接管继续沿用既有恢复入口；最终答案、过渡说明和工具效果不重复 |
| 作用域、请求身份与游标 | 切会话/项目/运行及旧 claim 迟到不污染新视图；重复或过期片段不重复拼接；临时帧不跳过任何持久事件 |
| 阅读体验 | 已展开工具项不重挂载；上翻不被拉回；流结束后页面不遗留“正在输出” |

结合实际改动选择 adapter 协议测试、前端归约/组件及 SSE 解析测试、真实 PG 事务/身份回归。复用既有恢复、暂停、配置、结算回归，不为未修改的每个分支重复造同构测试；特别注意实际生产入口的覆盖，不能只测未被调用的 helper。

本轮流式涉及页面，做一次**有边界的 bsk 浏览器检查**：缓慢且真实分段的模型响应完成前，记录至少两个不同的正文状态；完成后回答一次；再核对刷新和切会话无串页。脚本化 SSE 可锁定时序与 UI 行为，但至少一次使用当前支持的真实模型检查正文实际增量。真实模型只在结束时吐一个大块时，不能据此声称真实增量已验收；记录 provider 行为，并区分实现回归与真实体验结论。无需重新扫全站、反复桌面/窄屏全景或跑长期多轮。

所有浏览器操作只用 `browser-skill` 的 `bsk`，按技能与全局规则开无焦点会话，验收结束再停止。阅读 `KnowledgeStreamQuestionService` 时，只借鉴文本流/安全展示；它的“读者断开取消 Future”生命周期不适用于后台 Agent。

## 6. 收口标准、报告与提交

建议在同一会话按这个顺序推进：核对基线与实际入口 → 恢复隔离检索环境并建立一条成功基准 → 实现正文增量 → 验证矩阵与有限真实使用 → 一次全量 → 报告和本地提交。

收口交付：

1. 文档检索完整成功链与正常问题质量证据；若存在直接缺陷，附根因、最小修复和正式回归。
2. 正文流式代码与前端体验；写清支持的 provider/模式及正常完成回退范围。
3. 正式测试、真实模型、脚本模型、浏览器和历史证据分开列明；任何没做的项目如实标未验收。
4. 新建 `docs/agent-real-use-and-streaming-report-20261006.md`，证据放本轮新目录；维护文档只增加唯一入口、临时帧/持久事件边界和支持范围，不堆第二份任务书。
5. 按可独立审查、可编译的改动组织本地提交；不强拆相互依赖链。核对工作区状态，未推送、未合并、未部署。

若缺失真实配置/embedding 必要资产，不用假模型替代 A 的成功证据，也不把二者都报完成；先完成不依赖该条件的实现与确定性回归，明确实际阻塞和待验证项，及时请求唯一必要信息。

环境清理只针对本轮创建的 host、dev server、bsk 会话和隔离容器；不停止用户已有服务、Docker 引擎，不删除业务数据或历史验收卷。需要启动 Docker 时用 Docker Desktop 主程序，禁止启动 Windows 辅助服务代替引擎。

本轮不做：框架迁移、全架构重构、混合检索/重排平台、自动择模、隐式后台追问、逐 token 持久化、未提交正文断点恢复平台、全 provider 一次性适配、到限后剩余工作续接、精确计费或重试策略改造。直接完成上述两项，确认范围内结果后收口。
