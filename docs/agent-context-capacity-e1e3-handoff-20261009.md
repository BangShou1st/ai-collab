## 交付 A：E1 目标修订发布串行化

现有 RUN_CONTEXT 发布事务只 `FOR UPDATE OF agent_run`，目标修订在 `agent_session`；UPDATE 的 JOIN 条件仍可能看到语句开始时旧快照。隔离 PostgreSQL 探针已复现：真实新目标写入先提交为 goalRevision=1，旧摘要随后仍 COMMITTED，summaryGoalRevision=0。

把真实会话目标行纳入短事务并发保护，在保护内读取并校验目标修订，再完成摘要终态转换；方案先核对现有写入锁序，防止死锁。不得跨模型 HTTP 持锁，不新增平台或表，不用 run.version 代替业务目标修订。

把探针转正式真实 PostgreSQL 回归，并保留两种合法交错：目标写入先提交则旧摘要不能生效但用量结算；发布先提交则目标写入随后生效。保留既有取消、过期租约、接管、幂等、暂停镜像。避免把只检查 WHERE 写成已经证明跨表串行化。

## 交付 B：E2 两个 scope 的实际辅助尝试事实

现有 `maybeSummarizeDetailed` 只有会话摘要失败能保留 auxiliaryAttempted；RUN_CONTEXT 失败/不合格返回 false 后，被无会话候选的 NOT_ATTEMPTED 覆盖，实际出站顺序仍可能为 B→A。

沿用 `SummaryOutcome`，让 RUN_CONTEXT 也返回可合并的提交/尝试事实，兼容既有 boolean 入口。尝试事实跨两个 scope 合并为 OR；实际失败、不合格不能被后续跳过覆盖；准入前拒绝/未出站则不要误报已尝试。提交事实应对应真实有效发布，不能只因调用了 complete 方法就声称成功。

新增真实生产组件行为回归：RUN_CONTEXT 实际失败、LENGTH 不合格、无会话候选、后续会话摘要跳过、准入前拒绝、完全不发生辅助请求的镜像。断言落在实际出站模型与组装结果，不只断言中间 flag。
